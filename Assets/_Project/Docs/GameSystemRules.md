## 유닛 이동 시스템

### 작업 배경

**초기 설계 (2026-04-29):**
기존 이동/전투 로직(Phase 0/1/2)을 반복 패치하는 과정에서 고칠수록 다른 부분이 망가지는 현상이 반복됐다.
이동 슬롯(삼각형 배치)과 공격 슬롯(동적 각도 기반)으로 유닛 겹침을 방지하는 방식으로 재설계했으나,
수십 개의 유닛이 동시에 동작하는 환경에서 슬롯 배정 로직이 지나치게 복잡해져 버그가 잦아지는 문제가 재발했다.

**재설계 (2026-05-11):**
슬롯 기반 분산 방식을 전면 폐기하고, 겹침을 허용하는 단순한 구조로 전환했다.
- 이동 슬롯, 공격 슬롯, 타일 점유 한도 제거
- 근접/원거리 구분 없이 모든 유닛이 동일한 상태 전환 로직을 공유
- 규칙의 수와 복잡도를 최소화하여 구현 안정성 확보

### 이동 규칙

**규칙 1. 기본 목표**
유닛은 스폰된 순간부터 상대방 성을 향해 이동한다.

**규칙 2. 이동 방식**
A*로 경로를 계산하고, 타일 중심에서 타일 중심으로 이동한다.
같은 타일에 여러 유닛이 위치할 수 있으며, 겹침은 허용한다.

**규칙 3. 공유 타일 상태 (Shared Tile State)**
모든 유닛이 접근할 수 있는 타일맵 상태를 서버에서 중앙 관리한다.
유닛이 이동하면 즉시 업데이트되며, 경로 탐색 시 이 정보를 기반으로 판단한다.

담고 있는 정보:
- 어떤 엔티티가 있는가 (건물 / 성)
- 어느 팀인가 (블루 / 레드)
- 점령 상태 (누구 영역인가)

유닛 점유 정보는 경로 탐색에 사용하지 않으므로 공유 타일 상태에 포함하지 않는다.

멀티플레이: 서버에만 존재. 유닛 이동 결정은 서버에서만 이루어지며 클라이언트는 NetworkTransform으로 결과를 받는다.
싱글플레이: 로컬에서 동일한 구조로 동작. 서버/클라이언트 구분 없이 단일 인스턴스로 실행된다.

**규칙 4. 경로 재계산 시점**
건물 건설 / 건물 파괴 시 해당 시점에 모든 유닛의 경로를 즉시 재계산한다.

**규칙 5. 이동 속도**
이동 속도는 유닛별 스탯으로 개별 관리한다.
A* 타일 이동과 전투 이동(월드 좌표 직선 이동) 모두 동일한 이동 속도 스탯을 사용한다.

**규칙 6. 전투 사거리 판정 기준**
전투 사거리 판정은 타일 기준이 아닌 월드 좌표 기준으로 처리한다.

**규칙 7. A* 이동 중 회전**
A* 이동 중 유닛은 항상 이동 방향(다음 타일 방향)을 정면으로 바라본다.
타일 전환 시 다음 타일 방향으로 서서히 회전한다.

**규칙 8. A* 재개 시 회전**
전투 종료 후 A* 이동을 재개할 때, 이동을 시작하기 전 첫 번째 이동 방향으로 서서히 회전한다.
뒤를 바라본 채로 이동하는 경우는 허용하지 않는다.

---

### 전투 진입 규칙

**규칙 9. 감지 사거리와 공격 사거리**
모든 유닛(근접/원거리 불문)은 감지 사거리와 공격 사거리를 별도로 가진다.
감지 사거리는 항상 공격 사거리보다 길다.
근접/원거리 유닛의 차이는 공격 사거리 수치와 공격 방식에만 있으며, 상태 전환 로직은 동일하다.

**규칙 10. 유닛 상태 머신**
유닛은 다음 세 가지 상태 중 하나에 있다:

1. **A* 이동**: 상대방 성을 향해 타일 중심으로 이동 중
2. **전투 이동**: 타겟을 향해 월드 좌표로 직선 이동 중
3. **공격**: 멈추고 타겟을 공격 중

상태 전환 조건:

| 현재 상태 | 전환 조건 | 다음 상태 |
|-----------|-----------|-----------|
| A* 이동 | 감지 사거리 내 적 진입 | 전투 이동 |
| 전투 이동 | 타겟이 공격 사거리 내 도달 | 공격 |
| 전투 이동 | 타겟이 감지 사거리 이탈 | A* 이동 재개 |
| 공격 | 타겟이 공격 사거리 이탈 + 감지 사거리 내 | 전투 이동 |
| 공격 | 타겟이 감지 사거리 이탈 | A* 이동 재개 |
| 공격 (타겟 처치 후) | 감지 사거리 내 다른 적 + 공격 사거리 내 | 공격 (새 타겟) |
| 공격 (타겟 처치 후) | 감지 사거리 내 다른 적 + 공격 사거리 밖 | 전투 이동 |
| 공격 (타겟 처치 후) | 감지 사거리 내 적 없음 | A* 이동 재개 |

**규칙 11. A* 이동 재개 방식**
전투 종료 또는 타겟 이탈로 A* 이동을 재개할 때:
현재 월드 위치 기준으로 성 방향 앞쪽에 있는 타일 중 가장 가까운 타일의 중심으로 이동한 뒤 A*를 재개한다.
뒤쪽 타일로 복귀하는 경우는 허용하지 않는다.

**규칙 12. 전투 이동 중 회전**
전투 이동(추격) 중 유닛은 항상 타겟 방향을 정면으로 바라본다.
타겟 방향으로 서서히 회전하며, 타겟이 이동해도 지속적으로 타겟 방향을 유지한다.

---

### 전투 연계 규칙

**규칙 13. 타겟 선택**
처음 감지된 적을 타겟으로 삼는다.
타겟을 처치한 후에는 감지 사거리 내에서 가장 가까운 적을 다음 타겟으로 선택한다.
감지 사거리 내에 적이 없으면 A* 이동을 재개한다.

**규칙 14. 공격 중 이동 금지**
모든 유닛은 공격 중 이동하지 않는다.

**규칙 15. 공격 중 회전**
공격 중 유닛은 항상 타겟 방향을 정면으로 바라본다.
타겟 방향으로 서서히 회전하며, 공격이 끝날 때까지 타겟 방향을 유지한다.

**규칙 16. 범위 공격 (AoE)**
범위 공격은 대미지 계산 방식의 차이이며, 이동 및 상태 전환 규칙은 동일하게 적용된다.
아군에게는 대미지를 주지 않는다.

## 랠리포인트 시스템

**규칙 1. 깃발 표시 범위**
각 플레이어는 자신이 설정한 랠리포인트 깃발만 화면에서 볼 수 있다.
상대 팀의 랠리포인트 깃발은 표시하지 않는다.

**규칙 2. 깃발 표시/숨김 규칙**

| 상황 | 동작 |
|------|------|
| 랠리포인트 설정 직후 | 3초간 표시 → 자동 숨김 |
| 배럭 팝업 열림 | 해당 배럭 마커 표시 (3초 타이머 중지) |
| 팝업 닫힘 | 모든 마커 숨김 |
| 배럭 파괴 | 랠리포인트 및 마커 제거 |
| 배럭 자신의 타일에 랠리포인트 설정 | 랠리포인트 해제 → 마커 제거 |

## 생산 패널 UI

---

### 팝업 열기/닫기

**규칙 1. 팝업 열기**
배럭을 클릭하면 팝업이 열린다.
팝업이 열리면 해당 배럭의 랠리마커가 표시되고, 배럭의 팀과 종족에 맞는 유닛 버튼이 바인딩된다.
배경을 클릭하면 팝업이 닫힌다.

**규칙 2. 팝업 닫기**
팝업이 닫히면 모든 랠리마커가 숨겨진다.
랠리마커 표시/숨김 세부 규칙은 랠리포인트 시스템 섹션 참조.

---

### 유닛 버튼 입력

**규칙 3. 탭**
유닛 버튼을 탭하면 수동 생산 등록을 시도한다.

**규칙 4. 롱프레스**
유닛 버튼을 0.5초 이상 누르면 해당 유닛의 자동 생산을 토글한다.

**규칙 5. 자동 생산 중인 유닛 탭**
이미 자동 생산 중인 유닛 타입을 탭하면 추가 등록 없이 자동 생산 토글(해제)로 처리한다.

---

### 큐 구조

**규칙 6. 슬롯 구성**
슬롯은 3개다. 슬롯0은 현재 생산 중, 슬롯1은 대기 1순위, 슬롯2는 대기 2순위다.
슬롯에 표시되지 않는 자동 순환 대기 항목이 그 뒤에 추가로 쌓일 수 있다.

**규칙 7. 큐 상한 계산**
큐 상한(3개)은 현재 생산 중 1개 + 골드가 이미 차감된 대기 항목 수의 합산으로 계산한다.
골드가 차감되지 않은 자동 대기 항목은 합산에서 제외한다.

**규칙 8. 슬롯 클릭 취소**
슬롯을 직접 클릭하면 해당 슬롯의 생산을 취소한다.

---

### 골드 차감 시점

**규칙 9. 수동 항목**
수동으로 등록한 항목은 등록 즉시 골드가 차감된다.

**규칙 10. 자동 항목**
자동으로 등록한 항목은 슬롯1 또는 슬롯2에 표시되는 시점에 골드가 차감된다.
슬롯 뒤에서 대기 중인 자동 항목은 골드가 차감되지 않은 상태다.

---

### 생산 등록 검증 순서

**규칙 11. 검증 우선순위**
수동 생산 등록 시 검증 순서는 큐 상한 초과 → 골드 부족 → 인구 초과다.
이 순서는 실제 등록 로직의 검증 순서와 반드시 일치해야 한다.

---

### 생산 실패 피드백

**규칙 12. 실패 피드백 방식**

| 실패 사유 | UI 반응 |
|-----------|---------|
| 큐 가득 (3개 초과) | 토스트만 표시 |
| 골드 부족 | 토스트만 표시 |
| 인구 가득 | 토스트만 표시 |

골드 부족 시 유닛 비용 텍스트 색상은 실패 시점이 아닌, 골드가 변경될 때마다 자동으로 재평가된다.
인구 가득 시 HUD 인구 텍스트 색상은 HUD가 자체적으로 처리한다. 생산 패널이 관여하지 않는다.

---

### 정보 바 (골드/인구/비용 텍스트)

**규칙 13. 골드 텍스트**
보유 골드가 변경될 때마다 자동 갱신된다.

**규칙 14. 유닛 비용 텍스트 색상**
보유 골드가 해당 유닛의 비용보다 적으면 빨간색, 충분하면 흰색으로 표시된다.
골드 변경 시마다 자동 재평가된다.

**규칙 15. 인구 텍스트**
"사용/최대" 형식으로 표시된다.

---

### HUD (골드/인구 상시 표시)

**규칙 16. 인구 가득 상태 표시**
인구가 가득 찬 상태(사용 >= 최대)이면 인구 텍스트를 빨간색으로 표시한다.
가득 차지 않으면 흰색으로 표시한다.

**규칙 17. 인구 텍스트 형식**
"사용 / 최대" 형식으로 표시된다.

---

### 자동 생산 규칙

**규칙 18. 수동 등록 시 자동 모드 해제**
수동 항목을 등록하면 자동 모드가 전체 해제된다.
단, 이미 골드가 차감된 자동 항목은 수동으로 이관되어 생산이 계속된다. 환불 없음.
아직 골드가 차감되지 않은 자동 항목은 제거된다. 환불 없음.

**규칙 19. 자동 생산 해제/취소 시**
자동 유닛 타입을 해제하거나 해당 슬롯을 취소했을 때:
- 이미 골드가 차감된 자동 항목 → 수동으로 이관. 환불 없음, 생산 계속.
- 아직 골드가 차감되지 않은 자동 항목 → 제거. 환불 없음.

**규칙 20. 자동 생산 중복 방지**
자동 타입을 새로 등록할 때, 대기 큐의 마지막 항목이 수동으로 등록된 같은 타입이면
중복 추가 없이 기존 항목을 자동으로 전환한다. 골드는 이미 차감된 상태를 유지한다.

**규칙 21. 자동 생산 중 자원 부족 시**
생산 시작 시점에 골드 또는 인구가 부족하면 자동 모드를 전체 즉시 취소한다.
남은 자동 항목들은 규칙 19에 따라 처리된다.

**규칙 22. 생산 완료 후 자동 순환**
자동 항목이 완료되면, 해당 타입이 자동 목록에 아직 있으면 대기 큐 끝에 재추가된다.
재추가 시 골드 미차감 상태이며, 슬롯1/2에 표시될 때 차감된다.

---

### 슬롯 직접 취소 규칙

**규칙 23. 취소 시 환불**
슬롯을 직접 클릭해 취소할 때 골드가 이미 차감된 항목은 전액 환불된다.
골드가 차감되지 않은 항목은 환불 없다.

---

### 스폰 대기

**규칙 24. 스폰 불가 시 대기**
생산이 완료됐으나 배럭 인접에 빈 타일이 없으면 진행률 100% 상태로 대기한다.
빈 타일이 생기면 다음 프레임에 즉시 스폰된다.

---

### 토스트 메시지

**규칙 25. 토스트 표시 방식**
동시에 여러 토스트가 요청되면 큐에 쌓아 순서대로 하나씩 표시한다.
진입 애니메이션 없이 즉시 표시되며, 설정된 시간이 지나면 페이드아웃으로 사라진다.

**규칙 26. 토스트 터치**
표시 중인 토스트를 터치하면 현재 메시지가 즉시 제거되고 다음 메시지가 표시된다.

**규칙 27. 토스트 자동 정리**
게임 시작 또는 종료 시 남아있는 토스트가 자동으로 초기화된다.

**규칙 28. 토스트 종류**

| 키 | 표시 상황 |
|----|-----------|
| GoldInsufficient | 골드가 부족해 수동 생산을 등록할 수 없을 때 |
| PopulationFull | 인구가 가득 차 수동 생산을 등록할 수 없을 때 |
| ProductionQueueFull | 큐가 이미 3개로 가득 차 추가 등록을 거부할 때 |

## 건물 배치 패널 UI

### 비용 텍스트

**규칙 1. 건물 비용 텍스트 표기 형식**
건물 비용은 숫자만 표시한다. 'G' 등 접미사를 붙이지 않는다.
(생산 패널 비용 텍스트와 동일한 표기 방식.)

---

### 건물 비용 텍스트 색상

**규칙 2. 색상 표시 기준**
팝업이 열린 동안 현재 보유 골드가 해당 건물의 건설 비용보다 적으면 빨간색으로 표시된다.
충분하면 흰색으로 표시된다.

**규칙 3. 색상 재평가 시점**
팝업이 열리는 순간과 골드가 변경될 때마다 자동으로 재평가된다.
팝업이 닫히면 흰색으로 초기화된다.

---

### 건물 배치 실패 피드백

**규칙 4. 골드 부족 시 피드백**
골드가 부족한 상태에서 건물 버튼을 탭하면 토스트 메시지를 표시하고 팝업을 유지한다.
팝업을 닫지 않는 이유: 사용자가 비용 텍스트 색상을 통해 어떤 건물이 불가능한지 직접 파악할 수 있도록 하기 위함이다.

> **멀티플레이 분기 제외**: 위 규칙은 싱글플레이 분기에만 적용된다. 멀티플레이 RPC 분기는 별도 작업 예정.
