# Game System Rules — 건물

- **목적·답하는 질문:** 건물의 랠리·철거·방어 공격·물안개 회복 동작을 판단한다.
- **포함:** 시스템별 현재 계약, 서버 권위, 대상 필터·예외, 미구현 추가 기획의 보류 경계
- **제외·담당 문서:** 패널 조작은 [BuildingPanelsUI](GameSystemRules_BuildingPanelsUI.md), 현재 수치는 [StatsReference](../StatsReference.md), 추가 작업 우선순위는 [ROADMAP](../ROADMAP.md)
- **권위원본·주요 참조:** 건물 동작 규칙 원본; 섹션마다 번호가 다시 시작하므로 섹션명과 ID를 함께 참조
- **갱신 조건·방법:** 승인 동작 변경 때 본문을 갱신한다. 낮은 우선의 미구현 추가 기획은 구현 사실과 분리하며 실행·실기 이력은 Task/History로 연결한다.

> ⚠️ 이 문서는 **각 섹션이 규칙 번호를 1부터 다시 시작**한다. 따라서 "규칙 9"라고만 적으면 어느 규칙인지 특정할 수 없다.
> 이 문서 안에서든 **다른 문서에서 참조할 때든** 반드시 아래 목차의 섹션 이름을 함께 적는다
> (예: "방어 타워 시스템 규칙 9", "MistShrine 물안개 힐 시스템 규칙 10").
> 규칙 번호는 코드 주석과 과거 작업 문서가 참조하고 있으므로 **번호 자체를 재배열하지 않는다** — 어긋난 것은 참조하는 쪽을 고친다.

## 랠리포인트 시스템

**규칙 1. 깃발 표시 범위**
각 플레이어는 자신이 설정한 랠리포인트 깃발만 화면에서 볼 수 있다.
상대 팀의 랠리포인트 깃발은 표시하지 않는다.

**규칙 2. 깃발 표시/숨김 규칙**

| 상황 | 동작 |
|------|------|
| 랠리포인트 설정 직후 | 3초간 표시 → 자동 숨김 |
| 배럭 팝업 열림 | 다른 배럭 마커를 숨기고 해당 배럭 마커만 표시 (자동 숨김 타이머 중지) |
| 팝업 닫힘 | 모든 마커 숨김 |
| 지정 후 맵의 다른 곳 탭 | 모든 마커 즉시 숨김. 생산 건물을 열면 그 건물 마커만 다시 표시 |
| 배럭 파괴 | 랠리포인트 및 마커 제거 |
| 배럭 자신의 타일에 랠리포인트 설정 | 랠리포인트 해제 → 마커 제거 |

자동 숨김 타이머는 배럭별로 관리한다. 싱글에서도 플레이어 팀의 랠리 이벤트만 마커에 반영하며 AI의 이벤트가 플레이어 마커나 타이머를 건드리지 않는다.

**규칙 3. 지정 가능한 위치와 입력 유지**
아군·적 건물과 금광 칸에도 랠리를 지정할 수 있다. 격자 밖 좌표와 막힌 타일(`TileKind.Blocked`, 화면에서 타일이 없는 빈 곳)은 지정할 수 없다.
지정 불가 위치를 탭하면 입력한 플레이어에게 「랠리포인트를 지정할 수 없는 위치입니다」 토스트를 표시하고 지정 모드를 유지한다. 이어서 정상 칸을 탭할 수 있으며 생산 창을 다시 열지 않는다. 멀티에서는 서버도 같은 좌표 판정을 수행해 지정 불가 요청을 거부한다.

**규칙 4. 랠리 목적지 선택과 적 성 진군**
유닛은 생산 후 랠리 칸을 경유한 뒤 적 성으로 진군한다. 실제 도착 칸은 이동 가능한 칸만 선택한다. 랠리 칸 자체로 갈 수 없으면 랠리 기준 헥스 거리 1→2→3의 고리를 순서대로 탐색한다. 첫 성공 고리 안에서 출발점 기준 경로가 가장 짧은 칸을 선택하고, 길이가 같으면 고정 방향 순서를 유지한다.
이미 선택된 칸에 도착했거나 3칸 범위에 도달 가능한 후보가 없으면 랠리를 끝내고 적 성으로 진군한다. 경로 공급 실패·권위 시작점 오류는 후보 없음이나 정상 도착으로 처리하지 않는다. 배럭 자신의 칸 지정에 의한 해제는 대체 목적지 선택보다 우선한다.

**규칙 5. 랠리 설정 후 건설과 이동 중 재선택**
랠리 칸에 건물이 지어져도 저장된 랠리는 유지한다. 건설 후 생산된 유닛은 규칙 4의 대체 목적지를 선택한다. 이미 랠리로 이동 중인 유닛도 경로 무효화·재경로 시 원래 랠리 칸을 기준으로 목적지를 다시 선택하고, 근처 칸 경유 또는 후보 없음에 따른 적 성 진군으로 이어진다. 이 계약은 유닛 이동 규칙의 전체 경로 차단 후속 범위를 모두 구현했다는 뜻이 아니다.

## 건물 철거 시스템

### 철거 대상

**규칙 1. 철거 가능 범위**
Castle(본기지)을 제외한 모든 건물은 철거할 수 있다.

---

### 철거 UI

**규칙 2. 철거 버튼**
건물 클릭 시 열리는 팝업(`BuildingActionPanelUI`)에 철거 버튼을 포함한다.
이 팝업은 3×3 그리드(9칸)를 가지며, 스킬 건물에서는 슬롯 1~5가 스킬, 슬롯 6이 철거(고정), 슬롯 7~9가 예약(빈 공간)으로 배치된다. 스킬 슬롯 배치 상세는 [GameSystemRules_Skills.md](GameSystemRules_Skills.md) 규칙 9 참조.

**규칙 3. 즉시 실행**
철거 버튼을 탭하면 확인 팝업 없이 즉시 철거가 실행된다.

---

### 철거 처리

**규칙 4. 골드 환불**
철거 시 해당 건물의 건설 비용 50%를 즉시 환불한다.

**규칙 5. 생산 큐 처리 (생산 건물 한정)**
생산 건물 철거 시, 큐에 있는 항목 중 골드가 이미 차감된 항목은 전액 환불하고 취소한다.
골드가 아직 차감되지 않은 항목은 환불 없이 제거된다.

**규칙 6. 연쇄 처리**
- 채굴소 철거 시 해당 채굴소의 골드 수입이 즉시 중단된다.
- 배럭 철거 시 랠리포인트 및 마커는 랠리포인트 시스템 규칙 2에 따라 처리된다.
- 철거로 인한 경로 재계산은 유닛 이동 규칙 4에 따라 처리된다.

## 방어 타워 시스템

타워는 이동하지 않는 방어 건물로, 사거리 안의 적 유닛을 자동으로 공격한다.
유닛의 3단계 상태 머신(A* 이동 → 전투 이동 → 공격)을 따르지 않으며, 타워 고유의 동작 규칙을 따른다.

> **⚠️ 종족별 방어 타워 = `BuildingType.AutoTower`(= 2) 하나다.**
> Human = **CannonTower**, Spirit = **RuneSpire**, Transcendence = **VineTower**.
> **MistShrine은 방어 타워가 아니다.** MistShrine은 공격하지 않는 별도 힐 건물이며 `BuildingType.HealShrine`(= 6)이라는
> 독립 enum 값을 쓴다 → [MistShrine 물안개 힐 시스템](#mistshrine-물안개-힐-시스템) 참조.
> (과거 GDD/TDD에 "Transcendence 방어 타워 = MistShrine"으로 적혀 있던 서술은 오류이며 2026-08-10 정정되었다.)

---

### 타겟 선택

**규칙 1. 타겟 대상**
타워는 적 유닛만을 타겟으로 삼는다.
적 건물, 아군 유닛은 타겟으로 삼지 않는다.

**규칙 2. 타겟 선택 기준**
사거리 내에 적 유닛이 여러 명이면 타워와 월드 좌표 기준 거리가 가장 가까운 유닛을 타겟으로 선택한다.

---

### 사거리 판정

**규칙 3. 사거리 판정 기준**
사거리 판정은 월드 좌표 기준 거리(Vector3.Distance)를 사용한다.
타일 좌표 기준이 아니다.
유닛 이동 시스템 규칙 6(전투 사거리 판정 기준)과 동일한 방식을 따른다.

---

### 쿨다운 동작

**규칙 4. 배치 직후 첫 공격**
타워가 배치되는 순간 쿨다운 타이머를 0으로 초기화한다.
배치 직후 사거리 안에 적 유닛이 있으면 딜레이 없이 즉시 첫 공격을 실행한다.

**규칙 5. 공격 후 쿨다운**
공격을 실행한 직후부터 해당 건물의 공격 쿨다운 시간(초) 동안 다시 공격할 수 없다.
쿨다운 중에도 타겟 탐색은 계속 수행한다.

---

### 타겟 사망 시 처리

**규칙 6. 타겟 사망 시 즉시 새 타겟 탐색**
공격 중 타겟이 사망하면 즉시 새 타겟을 탐색한다.
새 타겟을 찾더라도 기존 쿨다운 잔여 시간이 남아 있으면 대기한 뒤 공격한다.
쿨다운이 이미 0이면 즉시 공격한다.

---

### 타워 파괴 처리

**규칙 7. 파괴 시 공격 즉시 중단**
타워의 HP가 0 이하가 되면 타겟 탐색, 쿨다운 진행 등 모든 동작이 즉시 중단된다.
타워 오브젝트 파괴 처리는 건물 철거 시스템 규칙 6의 연쇄 처리를 따른다.

---

### 배치 제한

**규칙 8. 배치 개수 무제한**
타워 배치 개수 제한은 없다. 골드 보유량으로만 제한된다.

---

### 멀티플레이 처리

**규칙 9. 서버 권위 처리**
타겟 선택, 사거리 판정, 데미지 처리는 서버에서만 실행된다.
클라이언트는 서버로부터 결과를 받아 시각적 표현에만 사용한다.

---

### 타워 UI 패널

**규칙 10. 타워 클릭 시 팝업**
배치된 타워를 클릭하면 기존 건물 팝업 UI를 그대로 사용한다.
철거 버튼만 포함하며, 별도 타워 전용 UI를 제작하지 않는다.

---

### Human CannonTower 초기 방향

**규칙 11. Human CannonTower 배치 시 초기 회전**
Human 종족의 AutoTower(CannonTower)는 배치되는 순간 상대방 진영을 향하도록 초기 회전값을 고정한다.
배치 이후 실시간 회전은 없으며, 배치 시 한 번만 설정된다.

내 진영 포탑은 기본 방향(회전 없음)을 유지하고, 상대 진영 포탑은 Y축 180도 회전을 적용한다.
이는 ViewConverter의 팀별 좌표 반전과 무관하게, 내 화면에서 항상 상대방 포탑이 나를 향해 서도록 보장한다.

Spirit(RuneSpire), Transcendence(VineTower)는 이 규칙을 따르지 않는다.

---

### 타워 발사 연출

**규칙 12. 타워 발사 연출 (2026-07-12 신설)**

종족별 타워는 단일 `BuildingType.AutoTower`를 유지하고 발사 프리셋은 **BuildingType + Race**로 선택한다. Human CannonTower는 별도 tower preset에서 Assault(type1)의 실제 production VFX(`EffectPreset_Pistoleer_Attack` → `vfx_pistoleer_attack`)를 재사용한다. Tank/CannonCart의 actual Tank VFX·shared Cannon preset과 Human preset의 이름/SFX/offset/scale/나머지 값은 유지한다. Spirit RuneSpire는 RuneSpire attack VFX를 사용하고 Transcendence VineTower는 미지정 상태에서 다른 종족 preset으로 fallback하지 않는다. **Human CannonTower 외 타워(Spirit RuneSpire · Transcendence VineTower)는** 확정 공격 결과 identity·Impact 위치/시각·Race snapshot을 표현에 전달하고 현재 target 재조회·tracer 도착으로 피해를 재판정·지연하지 않는다. Human CannonTower는 아래 2026-10-20 개정 문단의 서버 권위 투사체 경로를 따른다. *(2026-10-27 적용 범위 문구 추가 — 사용자 승인(서버 권위 투사체 Plan 11-3 P5-J 「추천대로 진행해」). 규칙 내용은 바꾸지 않고 범위만 적었다 — 아래 개정 문단이 Human을 서버 투사체로 바꾼 뒤 이 문장은 RuneSpire · VineTower 경로의 설명이었다. 종전 문장: 「확정 공격 결과 identity·Impact 위치/시각·Race snapshot을 표현에 전달하고 현재 target 재조회·tracer 도착으로 피해를 재판정·지연하지 않는다.」 근거 [Research 20-7 D-6](../_Tasks/2026-10-19/13_30_server-authoritative-projectile/Research.md#20-7-docs))* *(2026-10-13: 「현재 target 재조회」와 원래 맞은 유닛의 화면 표현 추적의 관계는 이 규칙 끝의 2026-10-13 블록)* 피해/HP·주기·범위·Stats와 VFX 실물은 불변이다. 현재 연결·개별 검증/미확정은 [VFXSFXList](../Assets/VFXSFXList.md), 이전 Tank 재사용·Human 변경·정적/native·빌드 시도 인계는 [당시 원문·검증 근거](../History/ImplementationVerificationHistory.md#role-maintenance-20261016-rules-buildings-01)에서 구분한다. 이전 native PASS를 최종 Human 변경의 새 native·실기/pixel 수용으로 쓰지 않는다.

**[2026-10-20 개정 — 사용자 승인 · ✅ 구현됨 `b819dc51`(2026-10-21 갱신 — 종전 「목표 계약 · 🔴 코드 미반영(미구현)」)]** **Human CannonTower는 서버 권위 투사체로 피해를 준다** — 대포 입구에서 발사(발사 이펙트도 같은 위치), CannonCart의 투사체·착탄 이펙트, 착탄 때 피해, 비행 중 타워가 파괴돼도 피해. **Spirit RuneSpire와 Transcendence VineTower는 즉발 데미지를 유지한다**(히트 딜레이를 도입하지 않는다).

## MistShrine 물안개 힐 시스템

> **📌 이 섹션의 분기(분리) 시점 — 다음 특수 건물 작업 시 반드시 판단할 것**
> 특수 동작 건물이 **2종 이상**이 되면 이 섹션을 `GameSystemRules_SpecialBuildings.md`로 **분리한다**.
> 지금 이 파일에 두는 근거: 이 파일의 "방어 타워 시스템"이 이미 *비생산 단일 건물의 자동 동작 · 대상 선정 ·
> 쿨다운 · 서버 권위 · 파괴 시 중단 · 클릭 팝업* 규칙 세트를 담고 있어 MistShrine과 성격이 거의 같고,
> 독립 파일을 받은 `GameSystemRules_Skills.md`·`GameSystemRules_Upgrade.md`는 건물 하나가 아니라 프레임워크 규모였다.
> 특수 건물이 하나 더 생기는 순간 이 근거는 무효가 되므로 즉시 분리한다.

MistShrine 물안개 힐의 동작 계약은 아래 규칙1~27을 따른다. 현재 구현·실기 범위는 [PROJECT_STATUS](../PROJECT_STATUS.md), 멀티 미검증·물안개 VFX/아이콘 제작·밸런싱 확정 등 후속은 [ROADMAP](../ROADMAP.md)를 참조한다. 당시 코드/프리팹·싱글 실기 및 미완 범위 묶음은 [이전 원문](../History/ImplementationVerificationHistory.md#role-maintenance-20261016-round2-rules-buildings-01)이며 전체 완료로 확대하지 않는다.

---

### 이 건물이 무엇인가 (자연어 설명)

MistShrine은 **공격하지 않는 초월(Transcendence) 종족 전용 회복 건물**이다.
플레이어가 사용하면 건물 주변에 **물안개**가 깔리고, 물안개가 유지되는 동안 그 안에 있는
**아군 유닛과 아군 건물이 매초 체력을 회복**한다. 물안개가 걷히면 회복도 멈추고, 쿨다운이 끝나면 다시 쓸 수 있다.

---

### 분류와 정체성

**규칙 1. 방어 타워가 아니다 — 별도 건물 분류**
MistShrine은 **공격하지 않는다**. 방어 타워(`BuildingType.AutoTower`)가 아니라 **별도 분류 `BuildingType.HealShrine`(= 6)** 을 유지한다.
Transcendence의 방어 타워는 **VineTower**이며 이는 `AutoTower`(= 2)다 — 두 건물은 완전히 별개다(방어 타워 시스템 섹션 서두 참조).
따라서 방어 타워 시스템 규칙 1~12(타겟 선택·사거리·공격 쿨다운·발사 연출 등)는 MistShrine에 **적용되지 않는다**.

**규칙 2. 스킬 건물도 아니다**
MistShrine은 스킬 건물(`FlightFacility` / `MagicBuilding`)이 아니다.
종족 로드아웃 5슬롯·지점 조준을 전제로 하는 스킬 시스템(`GameSystemRules_Skills.md`)의 규칙을 따르지 않으며,
스킬 발동 경로(`SkillActivationUseCase`)도 **재사용하지 않는다**(규칙 12).

---

### 범위와 대상

**규칙 3. 범위 = 건물 중심 고정 원형 (조준 없음)**
회복 범위는 **MistShrine 건물 자신의 중심을 기준으로 한 고정 원형**이다.
스킬 건물과 달리 **지점 지정(조준)이 없다** — 플레이어가 범위 위치를 고를 수 없다.
반경 판정은 프로젝트 관례대로 **월드 좌표 거리** 기준이다(방어 타워 시스템 규칙 3, 유닛 규칙 6과 동일 방식).

**규칙 4. 힐 대상 = 아군 유닛 + 아군 건물**
범위 안의 **아군 유닛과 아군 건물 모두**를 회복시킨다.
**시전 건물 자기 자신과 본기지(Castle)도 대상에 포함**된다.
적 유닛·적 건물·중립 대상은 회복시키지 않는다.

**규칙 5. 최대 체력인 대상은 회복되지 않는다**
현재 체력이 최대 체력인 대상은 회복량이 적용되지 않으며, 회복 텍스트도 표시하지 않는다(규칙 15).

---

### 물안개 동작

**규칙 6. 물안개 생명주기**
`시전 → 물안개 생성 → 지속 시간 동안 매초 회복 → 물안개 소멸 → 쿨다운 잔여 시간 경과 → 재사용 가능`

**규칙 7. 물안개 지속시간 < 쿨다운 (다운타임 존재)**
물안개 지속시간은 반드시 쿨다운보다 짧다. 즉 **물안개가 걷힌 뒤 다시 쓸 수 있을 때까지 공백(다운타임)이 존재**한다.
지속시간 ≥ 쿨다운이 되어 물안개가 끊김 없이 상시 유지되는 설정은 금지한다.

**규칙 8. 1초 단위 틱 회복 — 물안개 전용 독립 누적기로 구현한다 (2026-08-10 정정)**

회복 주기는 **1초 간격**이다(이 부분은 변경 없음).
회복을 **어떤 구조로 돌리는가**는 아래와 같이 확정한다.

DoT의 discrete 피해 경로를 물안개 회복에 재사용하지 않는다. 1초 주기는 유지하되 물안개 전용 독립 누적기·대상 재수집을 사용한다. 피해 전용 경로를 Heal로 등록하면 회복 대신 피해가 될 수 있고, 유닛 전용 ID 조회는 건물 대상과 아우라 이탈을 표현하지 못한다. 상세 금지 조건은8-2, 폐기된 재사용 문구·정정 경위는 [이전 원문](../History/ImplementationVerificationHistory.md#role-maintenance-20261016-round2-rules-buildings-02)다.

**8-1. 채택 모델 — 물안개별 독립 누적기 + 매 틱 대상 재수집**
물안개 인스턴스마다 **자기 자신만의 시간 누적기**를 두고, 누적 시간이 1초를 넘길 때마다
**그 시점에 범위 안에 있는 아군 유닛·아군 건물을 매 틱 다시 수집해** 회복을 적용한다.
초월계 자연회복(`UnitCombatUseCase.TickNaturalRegen` — `GameSystemRules_Upgrade.md` 규칙 7)이 이미 쓰고 있는 구조와 같은 형태이며,
**이 방식이라야 규칙 9(아우라 — 범위 이탈 시 즉시 끊김)와 규칙 13(중첩 해소를 매 틱 재판정)이 성립한다.**

**8-1-a. 활성 물안개들은 서로 같은 위상(phase)으로 틱한다 (2026-08-12 보강)**
새로 생성되는 물안개의 누적기는 **0에서 시작하지 않고, 이미 깔려 있는 물안개의 누적기 값에서 출발**한다.
모든 물안개에 매 프레임 **같은 경과 시간**을 더하므로, 한 번 맞춘 위상은 물안개가 사라질 때까지 유지된다.

**이 조항이 8-1의 "물안개마다 독립 누적기"와 모순되지 않는 이유:**
누적기는 **여전히 물안개마다 하나씩** 존재하며(개수는 규칙 14 표 그대로 — 물안개 인스턴스 단위), 하나를 공유하지 않는다.
공유되는 것은 **누적기의 시작 값(위상)뿐**이다.

**이 조항이 왜 필요한가 — 규칙 13이 여기에 의존한다.**
위상이 제각각이면 각 물안개가 서로 다른 프레임에 회복을 발화하게 되고,
**"같은 틱에 발화한 물안개끼리" 중첩을 해소하는 구현에서는 비교 대상이 늘 하나뿐이 되어 규칙 13이 사실상 동작하지 않는다.**
실제로 이 문제가 발생해 **겹친 물안개 2개가 같은 대상을 각각 회복시켜 초당 회복량이 2배가 된 사례**가 확인되었다
(2026-08-12 실기·로그 검증 / `_Tasks/2026-08-10/14_12_mistshrine-heal-implementation/Plan.md` §9-4).

> ⚠️ **되돌림 금지.** 위상 정렬을 "불필요한 결합"으로 판단해 각 물안개를 0에서 시작하도록 되돌리면 **위 버그가 그대로 재발한다.**
> 구현은 여기에 더해, **중첩 해소의 소유권 판정을 "이번 틱 발화 여부"와 분리**해 두어야 한다
> (활성 물안개 전체에서 대상별 최근접 물안개를 정하고, 그 물안개가 발화한 틱에만 적용) — 그래야 타이밍이 어긋나도 규칙 13이 성립한다.

> **부수 효과(허용):** 이미 다른 물안개가 있는 상태에서 시전하면 그 물안개의 **첫 회복이 0~1초 사이**에 들어온다(공유 위상에 합류하기 때문).
> **대상 입장의 회복 간격은 1초로 유지**되며 이중 회복은 발생하지 않는다. 물안개가 하나뿐이면 종전과 동일하다.

**8-2. 금지 — HoT/DoT 시간 지속 효과 목록(`_activeTimedEffects`)에 물안개 회복을 넣지 않는다**
`Kind = Heal` + `TickInterval > 0` 레코드를 시간 지속 효과 목록에 등록하는 것을 **명시적으로 금지**한다.
되돌림(“DoT 틱을 재사용하면 되지 않나”)을 막기 위해 금지 사유를 코드 위치와 함께 남긴다.

| # | 금지 사유 | 지켜야 할 경계 |
|:-:|----------|----------------|
| ① | 피해 discrete 분기를 Heal 회복에 사용하면 매초 피해가 될 수 있다 | 물안개는 피해 틱 경로와 독립 |
| ② | 유닛 전용 조회/ID만으로 건물 대상을 구별할 수 없다 | 유닛·건물을 구분해 아군 재수집 |
| ③ | 미리 정한 총량 분할은 범위 이탈 즉시 중단 아우라와 다르다 | 매 틱 범위·유효성 재판정 |

도입 당시 코드 행번호·함수 실측은 [이전 원문](../History/ImplementationVerificationHistory.md#role-maintenance-20261016-round2-rules-buildings-03)이며 현재 행번호로 사용하지 않는다.

> ①~③ 때문에 규칙 40(DoT 초 단위 틱)은 **틱 주기의 참고 선례일 뿐이며, 코드 경로 재사용 대상이 아니다.**

**규칙 9. 아우라 방식 — 범위 이탈 시 즉시 끊김**
물안개는 **시전 시점 대상 스냅샷이 아니다.**
물안개가 유지되는 동안 **범위 안에 있는 대상이 그 틱의 회복을 받고**, **범위를 벗어나면 즉시 회복이 끊긴다.**
이후 다시 범위 안으로 들어오면 (물안개가 아직 유지 중이라면) 다시 회복을 받는다.

**규칙 10. 물안개는 고정 — 이동하지 않는다**
물안개는 생성된 위치(시전 건물 중심)에 고정된다. TorrentSpirit의 파도(유닛 규칙 28~31)처럼 전진하지 않는다.

**규칙 11. 시전 비용 없음**
시전에 골드 등 자원을 소모하지 않는다. **쿨다운으로만 사용 빈도를 제어**한다.
(자원 비용 도입은 향후 확장 여지로 남기되 현재 범위 밖이다.)

**규칙 12. 시전 건물 파괴 시 물안개 즉시 제거**
MistShrine이 파괴 또는 철거되면 그 건물이 만든 물안개는 **즉시 제거**되고 남은 지속시간과 무관하게 회복이 중단된다.
자동 모드 상태와 쿨다운 상태도 함께 정리한다(정리 경로는 규칙 25).
(방어 타워 시스템 규칙 7 "파괴 시 동작 즉시 중단"과 동일한 원리이며, 건물 제거 자체는 건물 철거 시스템 규칙 6의 연쇄 처리를 따른다.)

### 중첩 규칙

**규칙 13. 물안개끼리는 중첩되지 않는다 — 가장 가까운 건물 하나만 적용**
한 대상은 물안개 효과를 **하나만** 받는다. 여러 MistShrine의 물안개 범위에 동시에 들어가도 회복이 합산되지 않는다.
- 여러 물안개 범위에 동시에 들어간 경우 **더 가까운 MistShrine의 효과**를 받는다(월드 좌표 거리 기준).
- **거리가 완전히 동일하면 건물 `Id`가 작은 쪽을 적용한다.** 구현이 순회 순서에 따라 임의로 정하지 않도록 하기 위한 **결정적(deterministic) 규칙**이며, 서버·클라이언트 판정이 갈리지 않도록 반드시 이 순서를 지킨다.

> ⚠️ **이 규칙은 규칙 8-1-a(활성 물안개 위상 공유)에 의존한다.** 위상이 어긋나면 물안개들이 서로 다른 프레임에 발화해
> **중첩 해소가 실행될 기회 자체를 잃는다**(2026-08-12 실기에서 회복량 2배 사례 확인). 규칙 8-1-a를 함께 볼 것.

**규칙 14. 연구소 자연회복과는 별개 효과 — 중첩 적용된다**
초월계 자연회복(연구소 강화, `GameSystemRules_Upgrade.md` 규칙 7)과 MistShrine 물안개 힐은 **서로 다른 효과**이며 **동시에 함께 적용**된다.
규칙 13의 중첩 금지는 **물안개끼리**만 해당한다.
> ⚠️ 구현 주의: 자연회복은 BloomFairy 힐과 상호 간섭을 막기 위해 이미 `Heal` 버킷과 분리된 독립 채널로 구현되어 있다
> (`GameSystemRules_Upgrade.md` 규칙 7). 물안개 힐도 같은 이유로 **자연회복·BloomFairy 힐과 겹치지 않는 별도 채널**로 구현해야 한다.
>
> ⚠️ **모델이 닮았다는 것과 채널이 같다는 것은 다르다 (2026-08-10 규칙 8 정정에 따른 보강).**
> 규칙 8이 자연회복과 **같은 형태의 모델**(독립 누적기 + 매 틱 대상 재수집)을 채택했지만,
> **누적기와 채널은 완전히 독립**이다. 하나의 누적기를 공유하거나 한쪽 상태를 다른 쪽이 읽는 구현은 금지한다.
>
> | 효과 | 누적 단위 | 대상 |
> |------|----------|------|
> | 초월계 자연회복 | **팀 단위** 누적기 1개 | 해당 팀 유닛 전체(범위 없음) |
> | MistShrine 물안개 힐 | **물안개 인스턴스 단위** 누적기(물안개 개수만큼) | 그 물안개 범위 안의 아군 유닛 + 아군 건물 |
>
> 같은 대상이 두 효과의 조건을 동시에 만족하면 **양쪽 회복이 각각 적용**되며, 어느 쪽도 다른 쪽을 덮어쓰지 않는다.

### 회복 표현

**규칙 15. 실제로 회복된 대상만 회복 텍스트 표시 + 표시 주기 분리**
- 회복 텍스트는 **실제로 체력이 회복된 대상에게만** 표시한다(최대 체력이라 회복량 0인 대상에는 표시하지 않는다 — 규칙 5).
- **회복 틱 주기(1초)와 텍스트 표시 주기를 분리**한다. 매초 텍스트를 띄우면 범위 내 다수 대상에서 화면이 도배되기 때문이다(BloomFairy HoT가 "완료 시 1회 표시"로 억제한 선례 — 유닛 규칙37).
- **표시 주기는 임시로 "3초 누적 1회 표시"** 로 하고, 밸런싱 단계에서 확정한다(규칙 16 — 미확정).
- 건물 위 회복 텍스트는 기존 표시 경로로 커버된다(`FloatingHpTextSpawner`가 `IsUnit` 분기로 건물 월드 좌표를 이미 지원 — 신규 UI 불필요).

### UI

**규칙 17. UI 규칙의 단일 소스는 UI 문서다**
MistShrine 전용 패널(`BuildingPanelBase` 상속, 탭/롱프레스 조작, 자동 모드 기본 OFF, 쿨다운 오버레이, 범위 표시 UI, 회복 텍스트 표시 주기)의
규칙은 [GameSystemRules_BuildingPanelsUI.md](GameSystemRules_BuildingPanelsUI.md#mistshrine-패널-ui) **"MistShrine 패널 UI"** 섹션이 단일 소스다.
이 문서는 로직·네트워크 계약만 정의하며, UI 상세를 중복 기술하지 않는다.

**규칙 18. 자동 / 수동 모드 (조작은 생산 패널과 동일)**
- **짧은 탭 = 수동 시전 1회**
- **길게 누르기(0.5초) = 자동 모드 토글**
- **자동 모드 상태에서 짧은 탭 = 자동 모드 해제**
- **자동 모드 기본값 = OFF** (건설 직후 꺼진 상태). 수동 상태에서 사용자가 바로 사용하지 않을 수 있기 때문이다.
- 자동 모드가 켜져 있으면 쿨다운이 끝나는 즉시 서버가 자동으로 시전한다.

**규칙 19. 자동 모드 상태는 단순 bool 하나로 보관한다**
생산 시스템의 `AutoTypes` 리스트 파생 방식(`IsAutoMode => AutoTypes.Count > 0`)을 그대로 쓰지 않는다.
MistShrine은 기능이 하나뿐이라 순환할 목록이 없으므로 **건물당 bool 1개**가 적절하다.

### 로직 / 네트워크

**규칙 20. 전용 UseCase — `SkillActivationUseCase` 재사용 금지**
MistShrine은 전용 Application UseCase를 사용하며 Unity.Netcode를 참조하지 않는다. `SkillActivationUseCase`의 FlightFacility/MagicBuilding 게이트·슬롯·종족 loadout·실행기 레지스트리 전제는 MistShrine에 성립하지 않으므로 재사용하지 않는다. 도입 전 신설 지침은 [이전 원문](../History/ImplementationVerificationHistory.md#role-maintenance-20261016-round2-rules-buildings-05)다.

**규칙 21. 쿨다운 관리 패턴은 스킬 시스템과 동일하게 차용한다**
- `Dictionary<건물 Id, 남은 시간>` 으로 건물별 쿨다운 보관
- 발동 시점의 **총 쿨다운**도 함께 보관(쿨다운 오버레이 radial fill 비율 계산용)
- 서버 틱에서 감소(싱글 = `GameBootstrapper.Update` / 멀티 서버 = `NetworkCombatController` 틱, **이중 틱 금지**)
- **클라이언트 쿨다운 로컬 미러 필수** — 멀티에서 순수 클라이언트의 쿨다운 UI가 동작하려면 서버 브로드캐스트를 받아 로컬에서 감소시켜야 한다.

**규칙 22. 서버 권위 + 자동/수동 토글 네트워크 동기화**
시전 판정·대상 수집·회복 적용·쿨다운은 **서버에서만** 실행한다(방어 타워 시스템 규칙 9와 동일 원리).
자동/수동 토글 동기화는 생산 시스템 구조를 따른다:
`Request... → ServerRpc(팀 검증: senderClientId == 0 → Blue) → ClientRpc 브로드캐스트`.
NetworkBehaviour는 Infrastructure 레이어에만 두고, RPC 메서드명은 `ServerRpc` / `ClientRpc` 접미사를 지킨다.

**규칙 23. 아군 유닛 + 아군 건물 수집**
물안개는 적 전용 반경 수집을 그대로 사용하지 않는다. 아군 팀 필터를 적용하고 시전 건물 자신·본기지를 포함한다(규칙4).

**규칙 24. 건물 회복 경로**
건물도 도메인 회복·최대HP clamp와 멀티 HP 동기화를 적용한다. 유닛 전용 힐 경로에 건물을 억지로 넣지 않으며 회복 텍스트는 규칙15의 공통 표시 계약을 따른다. 도입 전 수집/건물 회복의 신규 작성 지침은 [이전 원문](../History/ImplementationVerificationHistory.md#role-maintenance-20261016-round2-rules-buildings-06)다.

**규칙 25. 파괴·철거 시 상태 정리 경로가 필요하다**
MistShrine이 파괴·철거될 때 ① 물안개 제거(규칙 12) ② 자동 모드 상태 제거 ③ 쿨다운 상태 제거를 수행하는 경로가 필요하다.
`GameEvents.OnBuildingDied` 구독으로 처리한다(연구소 파괴 시 진행 연구 취소가 동일 패턴 — `GameSystemRules_Upgrade.md` 규칙 8·9).
