# Game System Rules — 맵 공정성

대전 맵의 성, 골드광산, 지형, 건설 제한, 장식을 설계하거나 변경할 때 따라야 하는 보편 공정성 규칙이다. 구체적인 11×21 무작위 생성 사양은 `GameSystemRules_RandomMap.md`를 따른다.

---

## 적용 범위와 거리 기준

- 현재 및 향후 실제 도입하는 모든 대전 맵과 orientation에 적용한다.
- 미사용 맵/orientation은 도입 시 별도 설계하고 이 문서의 검증을 통과해야 한다. PointyTop은 현재 설계·구현 범위 밖이다.
- offset 행·열 차이나 월드 직선거리가 아니라, 해당 orientation으로 변환한 `HexCoord`와 `HexCoord.Distance`를 거리 기준으로 사용한다.

---

## 규칙 1. 맵을 구성하는 모든 요소는 정확히 180도 대칭이어야 한다

맵 중심을 기준으로 지형과 장식을 포함한 모든 맵 요소가 정확한 180도 대응쌍을 이뤄야 한다. 게임플레이에 영향을 주지 않는 장식도 예외가 아니다.

- 대상: 타일, 광산, 정적 지형, 건설 불가 구역, 장식 오브젝트
- 장식 대응 조건: 존재 여부, 종류, 스케일, 재질 변형, 회전 대응이 동일해야 한다.
- 중앙에 단독으로 놓이는 요소는 180도 회전 후 자기 자신과 일치해야 한다.
- 전역 조명과 UI처럼 맵 생성 요소가 아닌 것은 이 규칙의 범위 밖이다.
- 성, 채굴소, 경기 중 생성되는 건물과 유닛은 플레이어 소유 오브젝트이므로 맵 시각 대칭 대상이 아니다. 성과 시작 채굴소는 규칙 3에서 위치·점유 조건·초기 경제 효과의 팀별 공정성만 검증한다.
- 비대칭 예외는 두지 않는다.

---

## 규칙 2. 중립 광산은 중앙 단독 또는 180도 대응쌍으로 검증한다

중립 광산을 모두 개별적으로 양 성에서 같은 거리에 두어야 한다는 규칙은 사용하지 않는다. 배치 형태에 따라 다음 기준을 적용한다.

### 중앙 단독 광산

- 맵 회전 중심에 놓는다.
- Blue/Red 성 중심의 `HexCoord.Distance`가 동일해야 한다.
- 규칙 4의 정적 최단 접근거리도 양 팀이 동일하고 모두 도달 가능해야 한다.

### 대칭 광산 쌍

광산 A와 180도 대응 광산 B에 대해 다음 교차 조건을 모두 만족해야 한다.

- A→Blue 성 거리 = B→Red 성 거리
- A→Red 성 거리 = B→Blue 성 거리
- Blue 성 영역→A 접근거리 = Red 성 영역→B 접근거리
- Blue 성 영역→B 접근거리 = Red 성 영역→A 접근거리

평균이나 총합만 같은 배치는 허용하지 않는다.

---

## 규칙 3. 시작 광산과 초기 경제 조건은 팀별 대칭이어야 한다

양 팀의 시작 광산은 다음 조건이 모두 동일해야 한다.

1. 팀별 개수
2. 자기 성 중심에서의 `HexCoord.Distance`
3. 규칙 4의 정적 최단 접근거리
4. 초기 채굴소의 존재·소유·가동 상태
5. 초기 채굴소 수입을 포함한 경제 효과
6. 성과 시작 채굴소가 초기 소유권을 부여한 뒤 즉시 건설 가능한 고유 타일 수

초기 건설 공간은 광산, 지형, 건설 불가 구역으로 침범하지 않고 보호한다.

---

## 규칙 4. 정적 최단 접근거리는 대칭이고 도달 가능해야 한다

- 시작 집합: 해당 팀 성에 인접한 이동 가능한 타일 전체
- 도착 집합: 검사할 광산에 인접한 이동 가능한 타일 전체
- 접근거리: 시작 집합에서 도착 집합까지의 최소 스텝 수

중앙 단독 광산은 양 팀 접근거리를 직접 비교하고, 광산 쌍은 규칙 2의 교차 대응으로 비교한다. 비교 대상은 모두 도달 가능해야 한다.

포함 요소:

- 초기 고정 장애물과 이동 불가 타일
- 성과 초기 채굴소 등 초기 건물

제외 요소:

- 동적 유닛과 `ClaimedTile`
- 경기 중 건설된 건물
- 전투, 혼잡, 일시적 점유

광산과 성 자체는 이동 불가다. `HexPathfinder`에 이를 목표로 직접 넘기지 말고, 이동 가능한 인접 타일 집합끼리 최단거리를 계산한다.

---

## 규칙 5. 맵 변경 시 반드시 다시 검증한다

새 맵 추가, 크기/orientation 변경, 성·광산·정적 장애물·초기 건물·건설 불가 구역·장식 배치 변경, 초기 경제 변경 시 검증을 다시 수행한다.

다음 중 하나라도 실패하면 맵 작업은 완료가 아니다.

- 모든 맵 요소의 정확한 180도 대칭
- 중앙 광산 또는 대응 광산 쌍의 거리·접근성 대칭
- 성과 모든 광산의 도달 가능성
- 시작 광산·초기 채굴소·즉시 건설 공간·경제 효과 대칭
- 해당 맵 유형의 통로 폭과 건설 불가 구역 규칙

검증 기록에는 seed, 맵 유형, orientation/config, 성·광산 좌표와 `HexCoord`, 거리, 정적 접근거리, 도달 가능성, 시작 조건, 대칭 검사 결과를 남긴다.

모든 우회 경로를 개별적으로 열거하거나 경로 개수를 세지는 않는다. 회전 대응 타일의 이동·건설·점령·지형·광산 상태가 모두 같으면 양측 이동 그래프도 180도 회전으로 일대일 대응한다. 따라서 전체 타일 상태 대칭을 먼저 검증하고, 실제 경로 탐색은 성과 광산의 도달 가능성·대응 최단거리·맵 유형별 필수 통로 폭 확인에 사용한다.
