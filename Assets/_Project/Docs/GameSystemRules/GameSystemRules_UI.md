## 공통 UI 규칙

모든 UI 시스템에 예외 없이 적용되는 공통 규칙이다.
새로운 UI를 제작하거나 기존 UI를 수정할 때 이 섹션을 기준으로 삼는다.

---

### 반응형 UI

**규칙 1. Canvas Scaler 설정**
모든 씬의 Canvas는 아래 값으로 통일한다.

| 항목 | 값 |
|------|-----|
| Scale Mode | Scale With Screen Size |
| Reference Resolution | 1080 × 1920 |
| Match Width Or Height | 0 (가로 너비 기준) |

Match Width Or Height=0은 가로 너비를 기준으로 스케일링한다.
세로가 긴 기기(21:9 등)에서는 캔버스 논리 높이가 기준보다 자연스럽게 늘어나는 방식으로 대응한다.

**규칙 2. 앵커 기반 배치 원칙**
모든 UI 요소는 고정 픽셀 크기 대신 앵커 비율 기반으로 배치한다.
sizeDelta, offsetMin, offsetMax 등 고정 픽셀값 사용 금지.

앵커(Anchor)란 부모 오브젝트를 기준으로 자식 오브젝트의 위치와 크기를 비율로 지정하는 방식이다.
화면 크기가 달라져도 비율이 유지되므로 어떤 해상도에서도 레이아웃이 일관되게 표시된다.

Layout Group 내부 반응형 패턴:
GridLayoutGroup의 CellSize는 고정 픽셀값이므로 사용하지 않는다.
대신 VerticalLayoutGroup + HorizontalLayoutGroup 중첩 구조를 사용하고,
Control Child Size + Child Force Expand를 활성화하면 CellSize 없이
가용 공간을 자동으로 균등 분배한다.

**규칙 3. Filled/Simple 이미지 자식 앵커 규칙**
Image.Type.Filled 또는 Simple 타입 이미지 안에 자식 이미지가 있는 경우,
자식 이미지도 부모와 같은 비율로 앵커를 설정해야 한다.
고정 offsetMin/offsetMax를 사용하면 해상도마다 자식 이미지의 크기와 위치가 달라진다.

예: 게이지 바(부모, Filled) 안에 fill 이미지(자식)가 있을 때,
fill 이미지의 앵커를 0.14~0.86처럼 비율로 설정해야 모든 해상도에서 동일하게 표시된다.

### Safe Area

**규칙 4. SafeArea 컨테이너 구조**
노치, 펀치홀, 하단 홈바가 있는 기기에서 UI가 가려지지 않도록 모든 씬에 SafeAreaContainer를 배치한다.
SafeAreaContainer에는 SafeAreaFitter 컴포넌트를 부착하여 Safe Area 범위에 맞게 자동으로 조정한다.

```
[UI] Canvas
  ├─ Background               ← 전체화면 배경 등 Safe Area 적용이 불필요한 요소
  └─ SafeAreaContainer        ← SafeAreaFitter 컴포넌트 부착
       └─ (모든 실제 UI 요소)  ← 팝업, HUD, 버튼 등 전부 이 안에 배치
```

- 실제 UI 요소(팝업, HUD 등)는 전부 SafeAreaContainer 안에 배치한다.
- 전체화면을 채워야 하는 배경 요소는 SafeAreaContainer 밖(Canvas 직속)에 배치한다.
- 독립 Canvas를 가진 UI(ToastUI 등)는 해당 Canvas에도 SafeAreaFitter를 적용한다.
- **반투명 배경 오버레이(BlockingOverlay)도 전체화면 배경과 동일하게 SafeAreaContainer 밖(UIManager Canvas 직속)에 두어야 한다.**
  팝업 컴포넌트가 직접 소유하지 않고, `UIManager.ShowBlockingOverlay()` / `HideBlockingOverlay()`를 통해 제어한다.
  (각 팝업이 SafeAreaContainer 안에 개별 오버레이를 소유하면 노치/홈바 영역이 가려지지 않는 구조적 문제가 발생하므로, UIManager가 단일 소유한다.)

**전체화면 배경 오브젝트 구현 방법**

배경 오브젝트를 Canvas 직속에 올바르게 배치하기 위해 아래 4가지를 반드시 지킨다.

1. **RectTransform 설정**: anchorMin=(0,0), anchorMax=(1,1), offsetMin=offsetMax=(0,0) → Canvas 전체를 빈틈없이 채움
2. **raycastTarget=false**: Image 컴포넌트의 Raycast Target을 반드시 꺼야 한다. 켜두면 배경이 터치 이벤트를 모두 가로채 하위 UI 버튼이 눌리지 않는다.
3. **Hierarchy 순서**: 배경 오브젝트를 SafeAreaContainer보다 위(앞)에 배치한다. Unity UI는 Hierarchy 위쪽 오브젝트를 먼저(뒤에) 그리므로, 배경이 SafeAreaContainer 아래에 있으면 모든 UI를 가린다.
4. **기존 Image 처리**: SafeAreaContainer 안에 있던 오브젝트에 배경 역할의 Image가 붙어 있었다면, 별도 배경 오브젝트를 생성한 뒤 기존 Image는 삭제 대신 `enabled=false`로 비활성화한다. 실기 테스트 통과 후 최종 삭제한다.

### UI 숨김/표시

**규칙 5. CanvasGroup 숨김/표시 패턴**
UI 요소를 숨길 때 SetActive(false) 대신 CanvasGroup을 사용한다.

| 상태 | alpha | blocksRaycasts | interactable |
|------|-------|----------------|--------------|
| 숨김 | 0 | false | false |
| 표시 | 1 | true | true |

SetActive(false)를 사용하면 두 가지 문제가 발생한다.
- Layout Group(버튼들이 나란히 정렬되는 구조) 안에서 해당 요소가 차지하던 공간이 사라져 나머지 요소들이 이동한다.
- 오브젝트 내부 로직(Update 등)이 함께 멈춘다. DontDestroyOnLoad 오브젝트(ToastUI 등)에서 이 방식을 쓰면 이후 동작이 전혀 일어나지 않는다.

**DOTween / AnimatedPanel 사용 시 추가 주의사항**:
- DOTween 애니메이션이 진행 중인 오브젝트를 SetActive(false)로 비활성화하면 Tween 시퀀스가 강제 중단되고, 이후 Show() 호출 시 초기화 타이밍이 꼬일 수 있다.
- `AnimatedPanel` 컴포넌트가 붙은 오브젝트는 **항상 active 상태로 유지**한다. `EnsureInitialized()`에서 CanvasGroup을 `alpha=0 / blocksRaycasts=false / interactable=false`로 초기 설정하여 시각적으로 숨긴다.
- 배경 오버레이(`_backgroundOverlay`)도 GameObject는 항상 active 상태 유지. Show() 시 `alpha=1 / blocksRaycasts=true / interactable=true`, Hide() 시 `alpha=0 / false / false`로 즉시 전환한다.

**반투명 배경 오버레이(BlockingOverlay) 단일 소유 패턴**:
- 반투명 배경 오버레이는 **UIManager가 단일 소유**한다. 개별 팝업이 자체 오버레이를 들고 있지 않으며, `UIManager.ShowBlockingOverlay(onTap)` / `UIManager.HideBlockingOverlay()`로만 제어한다.
- 두 가지 모드로 구분한다.
  - **Modal 모드** — `ShowBlockingOverlay()` (콜백 없음): 뒤쪽 입력만 차단한다. 오버레이를 터치해도 닫히지 않는다. (ConfirmPopup, AnonymousWarningPopup, RematchRequestPopup)
  - **Popup 모드** — `ShowBlockingOverlay(() => Close())` (콜백 있음): 오버레이를 터치하면 등록된 콜백(팝업 닫기)이 실행된다. (InGameSettingsUI, BuildingPlacementUI, 생산/건물 패널)
- 팝업이 중첩될 수 있으므로 UIManager는 **참조 카운터**로 표시 횟수를 누적 관리한다. `HideBlockingOverlay()`가 호출되어 카운터가 0이 될 때에만 실제로 숨겨진다.
- 호출은 항상 null-safe 패턴 `UIManager.Instance?.ShowBlockingOverlay(...)`를 사용한다 (씬 직접 진입 시 Instance가 null일 수 있음).

### 폰트

**규칙 6. 기본 폰트**
TextMeshPro 텍스트 컴포넌트에 사용하는 폰트는 아래 두 가지다.

| 폰트 | 경로 | 용도 |
|------|------|------|
| Maplestory Light SDF | `Assets/_Project/Fonts/Maplestory Light SDF.asset` | 기본 폰트 (일반 본문, 라벨, 수치 등) |
| Maplestory Bold SDF | `Assets/_Project/Fonts/Maplestory Bold SDF.asset` | 강조 폰트 (헤더, 버튼 등 굵은 표현 필요 시) |

기본값은 Maplestory Light SDF이며, 강조가 필요한 경우 Bold SDF를 사용한다.
에디터 스크립트로 UI를 생성할 때도 폰트 에셋을 명시적으로 설정해야 한다.
이 두 폰트 외의 폰트는 사용하지 않는다.

### 골드 부족 UI

**규칙 7. 비용 텍스트 색상**
보유 골드가 해당 항목(유닛, 건물)의 비용보다 적으면 빨간색, 충분하면 흰색으로 표시한다.
골드가 변경될 때마다 자동으로 재평가한다.
팝업이 닫히면 흰색으로 초기화한다.

골드와 비용을 비교해서 색상을 결정하는 로직은 각 UI에서 동일하게 적용되어야 하며,
이 규칙을 따르는 개별 섹션에서는 해당 규칙을 별도로 기술하지 않고 이 규칙을 참조한다.

### 팝업

**규칙 8. 팝업 타입 구분**
모든 팝업은 아래 두 가지 타입 중 하나로 반드시 분류한다.
새로운 팝업을 제작할 때 어떤 타입인지 명확히 결정하고 구현해야 한다.

| 타입 | 설명 | 배경 탭 닫기 |
|------|------|-------------|
| 팝업 (Popup) | 정보 확인 또는 조작 패널 | 가능 |
| 모달 (Modal) | 사용자의 명시적 Y/N 선택이 필요한 팝업 | 불가 |

현재 예시:
- 팝업: 생산 패널, 건물 배치 패널, 인게임 설정 메뉴
- 모달: ConfirmPopup (포기 확인 등)

**규칙 9. 팝업 닫기 — 배경 탭**
팝업(Popup) 타입은 배경을 탭하면 닫힌다.
모달(Modal) 타입은 배경 탭이 비활성화되며, 반드시 확인/취소 버튼으로만 닫힌다.

**규칙 10. 팝업 중첩**
팝업이 중첩되어 열릴 수 있으며 다음 규칙을 따른다.
- 중첩 팝업이 열리면 하위 팝업은 즉시 입력이 차단된다.
- 닫기 순서는 LIFO (마지막에 열린 팝업부터 순서대로 닫힌다).
- 배경(Background)은 하나의 공유 배경을 사용한다.

### 로딩 인디케이터 (LoadingIndicator)

**규칙 L-1. LoadingIndicator는 UIManager.ShowLoading()으로만 제어**
- `UIManager.Instance?.ShowLoading(true, "메시지")` / `ShowLoading(false)`
- 직접 LoadingIndicator GameObject를 활성/비활성 금지.

**규칙 L-2. 씬 전환이나 비동기 작업 시작 시 반드시 ShowLoading(true) 호출**
- 해당하는 상황: 씬 전환(LoginScene/LobbyScene/GameScene), 로그아웃, 로비 복귀, 재경기.
- 게임 포기(싱글/멀티 모두)는 씬 전환 없이 같은 씬 안에서 GameEndUI만 표시하므로 해당 없음.

**규칙 L-3. ShowLoading(false) 책임은 목적지 씬 Bootstrapper**
- 씬을 시작하는 호출부는 ShowLoading(true)만 담당한다.
- ShowLoading(false)는 각 씬의 초기화 완료 시점에 호출한다.
  - Login 씬: LoginBootstrapper(ShowLoginSelect / 자동 로그인 분기).
  - Lobby 씬: LobbyRootView.Start() 완료 시점.
  - Game 씬: GameBootstrapper.LoadMap() 완료 시점.
- 어디서 켰든 목적지 씬이 준비되면 자동으로 꺼지므로 ShowLoading(false) 누락 버그를 방지한다.
- 예외 경로(비동기 작업 실패로 씬 전환이 무산된 경우)에서는 켠 호출부가 직접 ShowLoading(false)로 끈다.

**규칙 L-4. null-safe 패턴 필수**
- `UIManager.Instance?.ShowLoading(...)` — Lobby/Game 씬 단독 실행 시 Instance가 null일 수 있으므로 null-safe를 보장한다.

> Infrastructure(NetworkBehaviour)에서 발생하는 씬 전환(재경기 등)은 UIManager(Presentation)를 직접 참조하지 않고
> GameEvents(Application)를 경유해 Presentation(GameEndUI)이 ShowLoading을 호출하도록 한다(레이어 방향 보호).

## 생산 패널 UI

---

### 팝업 열기/닫기

**규칙 1. 팝업 열기**
배럭을 클릭하면 팝업이 열린다.
팝업이 열리면 해당 배럭의 랠리마커가 표시되고, 배럭의 팀과 종족에 맞는 유닛 버튼이 바인딩된다.
배경을 클릭하면 팝업이 닫힌다.

**규칙 2. 팝업 닫기**
팝업이 닫히면 모든 랠리마커가 숨겨진다.
랠리마커 표시/숨김 세부 규칙은 랠리포인트 시스템 섹션 참조.

---

### 유닛 버튼 입력

**규칙 3. 탭**
유닛 버튼을 탭하면 수동 생산 등록을 시도한다.

**규칙 4. 롱프레스**
유닛 버튼을 0.5초 이상 누르면 해당 유닛의 자동 생산을 토글한다.

**규칙 5. 자동 생산 중인 유닛 탭**
이미 자동 생산 중인 유닛 타입을 탭하면 추가 등록 없이 자동 생산 토글(해제)로 처리한다.

---

### 큐 구조

**규칙 6. 슬롯 구성**
슬롯은 3개다. 슬롯0은 현재 생산 중, 슬롯1은 대기 1순위, 슬롯2는 대기 2순위다.
슬롯에 표시되지 않는 자동 순환 대기 항목이 그 뒤에 추가로 쌓일 수 있다.

**규칙 7. 큐 상한 계산**
큐 상한(3개)은 현재 생산 중 1개 + 골드가 이미 차감된 대기 항목 수의 합산으로 계산한다.
골드가 차감되지 않은 자동 대기 항목은 합산에서 제외한다.

**규칙 8. 슬롯 클릭 취소**
슬롯을 직접 클릭하면 해당 슬롯의 생산을 취소한다.

---

### 골드 차감 시점

**규칙 9. 수동 항목**
수동으로 등록한 항목은 등록 즉시 골드가 차감된다.

**규칙 10. 자동 항목**
자동으로 등록한 항목은 슬롯1 또는 슬롯2에 표시되는 시점에 골드가 차감된다.
슬롯 뒤에서 대기 중인 자동 항목은 골드가 차감되지 않은 상태다.

---

### 생산 등록 검증 순서

**규칙 11. 검증 우선순위**
수동 생산 등록 시 검증 순서는 큐 상한 초과 → 골드 부족 → 인구 초과다.
이 순서는 실제 등록 로직의 검증 순서와 반드시 일치해야 한다.

---

### 생산 실패 피드백

**규칙 12. 실패 피드백 방식**

| 실패 사유 | UI 반응 |
|-----------|---------|
| 큐 가득 (3개 초과) | 토스트만 표시 |
| 골드 부족 | 토스트만 표시 |
| 인구 가득 | 토스트만 표시 |

골드 부족 시 유닛 비용 텍스트 색상은 실패 시점이 아닌, 골드가 변경될 때마다 자동으로 재평가된다.
인구 가득 시 HUD 인구 텍스트 색상은 HUD가 자체적으로 처리한다. 생산 패널이 관여하지 않는다.

---

### 정보 바 (골드/인구/비용 텍스트)

**규칙 13. 골드 텍스트**
보유 골드가 변경될 때마다 자동 갱신된다.

**규칙 14. 유닛 비용 텍스트 색상**
보유 골드가 해당 유닛의 비용보다 적으면 빨간색, 충분하면 흰색으로 표시된다.
골드 변경 시마다 자동 재평가된다.

**규칙 15. 인구 텍스트**
"사용/최대" 형식으로 표시된다.

---

### HUD (골드/인구 상시 표시)

**규칙 16. 인구 가득 상태 표시**
인구가 가득 찬 상태(사용 >= 최대)이면 인구 텍스트를 빨간색으로 표시한다.
가득 차지 않으면 흰색으로 표시한다.

**규칙 17. 인구 텍스트 형식**
"사용 / 최대" 형식으로 표시된다.

---

### 자동 생산 규칙

**규칙 18. 수동 등록 시 자동 모드 해제**
수동 항목을 등록하면 자동 모드가 전체 해제된다.
단, 이미 골드가 차감된 자동 항목은 수동으로 이관되어 생산이 계속된다. 환불 없음.
아직 골드가 차감되지 않은 자동 항목은 제거된다. 환불 없음.

**규칙 19. 자동 생산 해제/취소 시**
자동 유닛 타입을 해제하거나 해당 슬롯을 취소했을 때:
- 이미 골드가 차감된 자동 항목 → 수동으로 이관. 환불 없음, 생산 계속.
- 아직 골드가 차감되지 않은 자동 항목 → 제거. 환불 없음.

**규칙 20. 자동 생산 중복 방지**
자동 타입을 새로 등록할 때, 같은 타입이 이미 슬롯0에서 수동 생산 중이거나
대기 큐의 마지막 항목이 수동으로 등록된 같은 타입이면,
중복 추가 없이 기존 항목을 자동으로 전환한다. 골드는 이미 차감된 상태를 유지한다.

단, 대기 큐에 다른 항목이 있는 경우에는 슬롯0 전환 대신 대기 큐 끝에 새로 추가한다.
중간에 다른 유닛이 있으므로 이 경우는 중복이 아니다.
예: [Assault(슬롯0)] [Pistoleer(슬롯2)] 상태에서 Assault 자동 등록 →
    슬롯3에 Assault 추가 → [Assault(슬롯1)] [Pistoleer(슬롯2)] [Assault(슬롯3)]

**규칙 21. 자동 생산 중 자원 부족 시**
생산 시작 시점에 골드 또는 인구가 부족하면 자동 모드를 전체 즉시 취소한다.
남은 자동 항목들은 규칙 19에 따라 처리된다.

**규칙 22. 생산 완료 후 자동 순환**
자동 항목이 완료되면, 해당 타입이 자동 목록에 아직 있으면 대기 큐 끝에 재추가된다.
재추가 시 골드 미차감 상태이며, 슬롯1/2에 표시될 때 차감된다.

---

### 슬롯 직접 취소 규칙

**규칙 23. 취소 시 환불**
슬롯을 직접 클릭해 취소할 때 골드가 이미 차감된 항목은 전액 환불된다.
골드가 차감되지 않은 항목은 환불 없다.

---

### 스폰 대기

**규칙 24. 스폰 불가 시 대기**
생산이 완료됐으나 배럭 인접에 빈 타일이 없으면 진행률 100% 상태로 대기한다.
빈 타일이 생기면 다음 프레임에 즉시 스폰된다.

---

### 토스트 메시지

**규칙 25. 토스트 표시 방식**
동시에 여러 토스트가 요청되면 큐에 쌓아 순서대로 하나씩 표시한다.
진입 애니메이션 없이 즉시 표시되며, 설정된 시간이 지나면 페이드아웃으로 사라진다.

**규칙 26. 토스트 터치**
표시 중인 토스트를 터치하면 현재 메시지가 즉시 제거되고 다음 메시지가 표시된다.

**규칙 27. 토스트 자동 정리**
게임 시작 또는 종료 시 남아있는 토스트가 자동으로 초기화된다.

**규칙 28. 토스트 종류**

| 키 | 표시 상황 |
|----|-----------|
| GoldInsufficient | 골드가 부족해 수동 생산을 등록할 수 없을 때 |
| PopulationFull | 인구가 가득 차 수동 생산을 등록할 수 없을 때 |
| ProductionQueueFull | 큐가 이미 3개로 가득 차 추가 등록을 거부할 때 |

## 건물 배치 패널 UI

### 비용 텍스트

**규칙 1. 건물 비용 텍스트 표기 형식**
건물 비용은 숫자만 표시한다. 'G' 등 접미사를 붙이지 않는다.
(생산 패널 비용 텍스트와 동일한 표기 방식.)

---

### 건물 비용 텍스트 색상

**규칙 2. 색상 표시 기준**
팝업이 열린 동안 현재 보유 골드가 해당 건물의 건설 비용보다 적으면 빨간색으로 표시된다.
충분하면 흰색으로 표시된다.

**규칙 3. 색상 재평가 시점**
팝업이 열리는 순간과 골드가 변경될 때마다 자동으로 재평가된다.
팝업이 닫히면 흰색으로 초기화된다.

---

### 건물 배치 실패 피드백

**규칙 4. 골드 부족 시 피드백**
골드가 부족한 상태에서 건물 버튼을 탭하면 토스트 메시지를 표시하고 팝업을 유지한다.
팝업을 닫지 않는 이유: 사용자가 비용 텍스트 색상을 통해 어떤 건물이 불가능한지 직접 파악할 수 있도록 하기 위함이다.

> **멀티플레이 분기 제외**: 위 규칙은 싱글플레이 분기에만 적용된다. 멀티플레이 RPC 분기는 별도 작업 예정.

## 인게임 설정 메뉴

### 메뉴 열기/닫기

**규칙 1. 메뉴 열기**
HUD의 설정 버튼을 탭하면 인게임 설정 메뉴가 열린다.
설정 메뉴 외부 영역(공유 Background)을 탭하면 메뉴가 닫힌다.
닫기(X) 버튼을 탭해도 메뉴가 닫힌다.

**규칙 2. 싱글플레이 일시정지**
싱글플레이에서 설정 메뉴가 열리면 게임이 즉시 일시정지된다 (Time.timeScale=0).
메뉴가 닫히면 일시정지가 해제된다 (Time.timeScale=1).
멀티플레이에서는 일시정지 기능이 없다.

**규칙 3. 포기 확인 팝업**
설정 메뉴에서 포기 버튼을 탭하면 확인 팝업(ConfirmPopup)이 표시된다.
포기 확인 팝업이 열려 있는 동안 공유 Background 클릭은 차단된다 (설정 메뉴가 닫히지 않음).

---

### 게임 포기

**규칙 4. 포기 결과**
포기 플레이어는 패배 처리된다.
싱글플레이: 항상 Red 팀(로컬 플레이어)이 패배.
멀티플레이: 포기를 요청한 클라이언트의 팀이 패배.

**규칙 5. 재경기**
포기 후 재경기는 일반 게임 종료와 동일하게 처리된다.
커스텀게임에서는 재경기 요청이 가능하다.

## 닉네임 설정 화면

Login.unity 내 패널(NicknameSetupView)로 구현된다. 이메일 회원가입 완료 직후 또는 Google 최초 로그인 후 표시된다.

**규칙 1. 화면 구성**
- 닉네임 입력 필드 (TMP_InputField): 한글 2~12자 또는 영문/숫자 2~24자
- 확인 버튼: 입력 검증 후 닉네임 저장
- 스킵 버튼: 자동 생성 닉네임으로 진행

**규칙 2. 입력 검증**
- 빈 값이면 확인 버튼 클릭 불가 또는 안내 메시지 표시
- 최소 길이 미달 시 안내 메시지 표시
- 특수문자 포함 시 안내 메시지 표시
- 1차 검증은 클라이언트에서 즉시 수행, 최종 저장은 서버(Cloud Code)에서 처리

**규칙 3. 스킵 동작**
스킵 버튼을 누르면 자동 생성된 임의 닉네임으로 저장하고 다음 화면으로 진행한다.
자동 생성 형식: `구글_임의문자숫자` (Google), `사용자_임의문자숫자` (이메일)

**규칙 4. 완료 후 흐름**
- 이메일 회원가입 경로: 닉네임 설정/스킵 완료 → EmailVerifyView로 이동
- Google 로그인 경로: 닉네임 설정/스킵 완료 → Lobby 씬으로 이동

## Profile 탭 UI

Lobby.unity의 ProfilePanel(ProfileView)에 표시된다.

**규칙 1. 레이아웃 구성**
Profile 탭은 위에서 아래로 다음 섹션으로 구성된다.
1. 계정 정보 섹션: 닉네임#코드 표시, 닉네임 변경 버튼
2. 전적 섹션: 총게임수, 승, 패, 승률, 마지막 접속종료 날짜시각
3. 내 랭킹 섹션: 내 순위 표시 (20판 미만이면 "순위 없음")
4. 계정 연동 섹션 (익명 계정만): Google/이메일 연동 버튼
5. 로그아웃 버튼

**규칙 2. 닉네임 표시**
닉네임과 코드를 함께 표시한다. (예: 전사#4729)
닉네임이 없는 경우(익명 계정): 자동 생성된 `게스트_임의문자숫자` 표시

**규칙 3. 닉네임 변경 버튼**
닉네임 변경 버튼을 누르면 닉네임 변경 UI를 표시한다.
hasUsedFreeNicknameChange가 false이면 무료 변경 안내를 함께 표시한다.
true이면 유료 변경 안내를 표시한다.
익명 계정에는 닉네임 변경 버튼을 표시하지 않는다.

**규칙 4. 전적 표시**
아이템별 표시 내용:
- 총게임수: 멀티플레이 매치 총 횟수
- 승: 승리 횟수
- 패: 패배 횟수
- 승률: wins / totalGames × 100 (%), 총게임수 0이면 "-" 표시
- 마지막 접속종료: 날짜 + 시각 (예: 2026-06-29 15:30)

**규칙 5. 내 랭킹 표시**
총게임수가 20 미만이면 "랭킹: 순위 없음 (20판 이상 필요)" 표시
20 이상이면 "랭킹: N위" 형식으로 표시

**규칙 6. 데이터 갱신 시점**
Profile 탭이 활성화될 때마다 Cloud Save에서 최신 전적 데이터를 로드한다.

## Ranking 탭 UI

Lobby.unity의 RankingPanel(RankingView)에 표시된다. 현재 빈 placeholder 상태이며 구현 예정.

**규칙 1. 테이블 구성**
열 구성 (왼쪽→오른쪽):

| 열 | 내용 | 정렬 기준 |
|----|------|----------|
| 순위 | 1~100 | 고정 |
| 닉네임 | 닉네임#코드 | 텍스트 정렬 |
| 승률 | xx.x% | 기본 정렬 기준 |
| 게임수 | 총 게임수 | 숫자 정렬 |
| 승리 | 승리 횟수 | 숫자 정렬 |
| 패배 | 패배 횟수 | 숫자 정렬 |

**규칙 2. 페이지네이션**
10행씩 표시, 최대 10페이지 (상위 100명).
이전/다음 페이지 버튼으로 이동.

**규칙 3. 열 정렬**
각 열 헤더를 탭하면 해당 열 기준으로 오름차순/내림차순 정렬을 전환한다.
기본 정렬: 승률 내림차순.

**규칙 4. 구현 방식**
별도 라이브러리 없이 ScrollRect + VerticalLayoutGroup + 헤더 Button 조합으로 구현한다.
행 프리팹을 ScrollRect Content에 동적 생성하여 표시한다.

**규칙 5. 노출 조건**
총게임수 20 미만인 플레이어는 랭킹에 표시되지 않는다.

**규칙 6. 데이터 로드**
Ranking 탭이 활성화될 때 UGS Leaderboard에서 데이터를 로드한다.
로딩 중에는 로딩 인디케이터를 표시한다.
