# Game System Rules — 스킬 건물 (Skill Buildings)

> **이 문서는 스킬 건물 시스템의 단일 소스(SSoT)입니다.**
> 다른 문서(GameDesignDocument, ROADMAP 등)에서 스킬 건물을 다룰 때는 상세 내용을 이 문서로 연결하고, 개별 문서에는 요약과 참조만 둡니다.

---

## 이 문서가 무엇을 다루는가 (자연어 설명)

**스킬 건물**은 각 종족이 액티브 스킬(마법·특수 능력)을 사용하기 위한 특수 건물입니다. 유닛을 생산하거나 자원을 캐는 건물과 달리, 플레이어가 직접 버튼을 눌러 전장에 즉각적인 효과(피해·상태 변화 등)를 발생시키는 것이 목적입니다.

이 문서는 "스킬 건물이 어떻게 동작해야 하는가"에 대한 **프레임워크 레벨의 확정 설계**를 담습니다. 즉, 스킬을 어떤 자원으로 쓰는지(마나 없음, 쿨다운만), 몇 개까지 가질 수 있는지(최대 5개), 어떤 UI로 노출되는지(기존 범용 건물 패널의 3×3 그리드 재사용), 모바일 터치로 어떻게 조준하는지(스킬 버튼을 탭하면 조준 모드에 진입 → 화면을 드래그해 범위를 옮김 → 손을 떼면 발동, 하단 X로 취소), 그리고 멀티플레이에서 누가 판정하는지(서버 권위)에 대한 규칙을 정의합니다.

**아직 구체적인 스킬 목록과 수치(어떤 스킬이 몇 초 쿨다운에 얼마의 피해를 주는지)는 확정되지 않았습니다.** 이 문서는 그 값들을 나중에 데이터(ScriptableObject)로 채워 넣을 수 있도록, 코드가 따라야 할 "그릇(틀)"을 먼저 규정합니다.

**구현 상태: 기획 확정 / 미구현.**
현재 세 스킬 건물은 배치·피격만 되는 시각 오브젝트이며, 클릭 시 철거 버튼만 있는 범용 건물 패널을 공유합니다. 스킬 발동 로직·데이터·전용 UI는 전무하며, 이 문서의 규칙은 향후 구현의 기준이 됩니다.

## 스킬 건물 3종 정의

세 건물의 통칭은 **"스킬 건물"**이며, 종족별로 지칭할 때는 아래 프리팹/자산명을 사용한다.

| 종족 | 자산명(스킬 건물) | 프리팹 | BuildingType enum |
|------|------------------|--------|-------------------|
| Human | FlightFacility | `Building_FlightFacility_Blue` / `Building_FlightFacility_Red` | `FlightFacility` (= 3) |
| Spirit | MagicSpirit | `Building_MagicSpirit_Blue` / `Building_MagicSpirit_Red` | `MagicBuilding` (= 5) |
| Transcendence | WillowShrine | `Building_WillowShrine_Blue` / `Building_WillowShrine_Red` | `MagicBuilding` (= 5) |

**규칙 1. enum 공유 및 종족 키 분기 (직렬화·RPC 안정성)**
Spirit의 `MagicSpirit`와 Transcendence의 `WillowShrine`은 **동일한 enum 멤버 `MagicBuilding`(= 5)을 공유**한다. 스킬 로드아웃(어떤 스킬을 갖는지)은 enum이 아니라 **종족(건물)별 데이터로 각각 정의**하고, 실행 시 종족 키로 분기하여 올바른 스킬셋을 로드한다.

- enum 멤버를 종족별로 분리하거나 이름을 바꾸지 **않는다**. `BuildingType`은 `(int)` 캐스트로 RPC 직렬화되고 ScriptableObject/Scene에 직렬화되어 있어, 멤버 변경 시 기존 직렬화 데이터와 서버/클라 버전 정합성이 깨질 위험이 있기 때문이다. (근거: `Domain/Building/BuildingType.cs` 주석 — 멤버 순서·값 변경 금지)
- 필요 판단 시 향후 별도 enum 멤버로 분리 전환할 수 있으나, 그 결정은 이 문서 갱신과 함께 별도 작업으로 진행한다.

> **명칭 주의:** Spirit의 **스킬 건물**은 `MagicSpirit`이고, Spirit의 **방어 타워**는 `RuneSpire`(enum `AutoTower`)이다. 과거 문서에서 Spirit 방어 타워를 "MagicTower"로 표기한 사례가 있으나, 스킬 건물 `MagicSpirit`과의 혼동을 피하기 위해 방어 타워는 항상 `RuneSpire`로 표기한다. 방어 타워 규칙은 [GameSystemRules_Buildings.md](GameSystemRules_Buildings.md) 참조.

> **건설 비용:** 세 스킬 건물(FlightFacility / MagicSpirit / WillowShrine)의 건설 비용은 모두 **200 골드**로 동일하다. 권위 소스는 런타임 실제값인 `Resources/Config/BuildingStatsConfig.asset`(Inspector 값 우선)이며, `StatsReference.md`의 건설 비용 표기(200)와 일치한다.

## 공통 규칙

**규칙 2. 자원: 마나 없음, 쿨다운만**
스킬 사용에 소모되는 자원(마나·마력 등)은 도입하지 않는다. 스킬 사용을 제약하는 유일한 장치는 **쿨다운**이다.

**규칙 3. 건물별 글로벌 쿨다운**
쿨다운은 스킬 단위가 아니라 **건물 단위(글로벌)**로 적용한다. 한 스킬 건물에서 스킬 1개를 사용하면, 그 건물의 **모든 스킬 버튼이 쿨다운 동안 함께 잠긴다**(연속·동시 난사 방지).

- 개별 스킬별 쿨다운은 현재 도입하지 않는다. 향후 밸런싱 필요 시 재검토한다.
- 쿨다운 시간(초)은 스킬/건물 데이터로 정의한다(추후 확정).

**규칙 4. 건물당 스킬 수 최대 5개**
하나의 스킬 건물은 최대 **5개**의 스킬을 가질 수 있다. 실제 각 건물이 몇 개의 스킬을 갖는지와 그 목록은 데이터로 정의한다(추후 확정).

**규칙 5. 건물 업그레이드 없음 — 즉시 전부 사용 가능**
스킬 건물은 단계 업그레이드가 없다. 건물이 건설되는 즉시 그 건물의 스킬 전부(최대 5개)를 사용할 수 있다. 단계별 해금은 존재하지 않는다.

**규칙 6. 종족별 스킬셋 분리**
스킬 로드아웃은 종족(건물)별로 각각 정의한다. `MagicSpirit`(정령)과 `WillowShrine`(초월)이 enum을 공유하더라도 스킬셋은 서로 다르며, 종족 키로 분기하여 로드한다(규칙 1 참조).

**규칙 7. 데이터 주도 설계 (ScriptableObject)**
스킬은 데이터로 정의한다. 하나의 스킬 데이터는 다음 요소로 구성한다.

| 요소 | 설명 |
|------|------|
| 아이콘 | 스킬 버튼에 표시할 스프라이트 |
| 조준 방식 | 즉시 발동 / 지점 지정 (발동 경로 규칙 참조) |
| 쿨다운 | 발동 후 건물 글로벌 쿨다운 시간(초) |
| 타입 | 스킬 메커니즘 타입(3종 중 하나, 아래 참조) |
| 파라미터 | 반경·지속시간·피해량·상태 효과 등 타입별 수치 |

코드는 **타입별 실행기(executor)만** 구현하고, 구체 스킬과 수치는 ScriptableObject로 주입한다. 새 스킬을 추가할 때 원칙적으로 데이터만 추가하면 되도록 설계한다.

## 스킬 UI 패널

**규칙 8. 범용 건물 패널(`BuildingActionPanelUI`) 재사용**
스킬 건물 클릭 시 별도 전용 UI를 만들지 않고, 기존 범용 건물 행동 패널(`BuildingActionPanelUI`)을 재사용한다. 이 패널은 3×3 그리드(9칸)를 가진다.

**규칙 9. 3×3 그리드 슬롯 배치**

| 슬롯 | 용도 |
|------|------|
| 1 ~ 5 | 스킬 버튼 (건물이 보유한 스킬. 최대 5개) |
| 6 | 철거 버튼 (고정) |
| 7, 8, 9 | 예약(빈 공간) — 향후 여유분, 현재 미사용 |

- 스킬이 5개 미만인 건물은 슬롯 1부터 채우고 남는 스킬 슬롯은 비운다.
- 철거는 항상 슬롯 6에 고정한다. (철거 동작 자체는 [GameSystemRules_Buildings.md](GameSystemRules_Buildings.md) 건물 철거 시스템 규칙을 따른다.)
- 슬롯 7~9는 유틸리티 스킬 등 향후 확장을 위한 예약 공간으로 남긴다.

**규칙 10. 쿨다운 시각 표시**
쿨다운 중인 스킬 버튼 위에는 **버튼 전체를 덮는 어두운 반투명 오버레이**를 씌우고, 쿨다운이 진행될수록 이 어두운 부분이 **표준 쿨다운 스윕(clockwise sweep)** 방식으로 걷혀 사라지게 하여 남은 진행도를 나타낸다. 그 위에 **남은 시간(초) 숫자 텍스트**를 함께 표시한다. 이 표시는 **쿨다운(시전) 중일 때만 나타나며, 유휴 상태에서는 숨긴다**. 건물 글로벌 쿨다운이므로 쿨다운 중에는 슬롯 1~5의 스킬 버튼 전부에 이 표시가 적용된다(규칙 3).

- **오버레이 형태:** 버튼 전체를 덮는 **어두운 반투명 직사각형**으로 충분하다. 버튼의 실루엣(모양)을 정밀하게 추종할 필요는 없으며, 실루엣 추종은 후속 다듬음 항목으로 남긴다.
- **스윕 방향:** 어두운 부분은 **12시(위) 지점부터 시계방향으로 걷혀 사라진다**. 즉 쿨다운이 진행될수록 버튼이 12시 기점에서 시계방향으로 점차 드러난다(표준 쿨다운 스윕). 쿨다운이 끝나면 오버레이가 완전히 사라지고 버튼이 온전히 드러난다.
- **표시 조건:** 쿨다운이 걸려 있는 동안에만 오버레이와 남은 시간 숫자를 표시하고, 쿨다운이 없는(사용 가능한) 유휴 상태에서는 오버레이·숫자를 모두 숨긴다.

> 비용·색상 등 공통 텍스트 표기 규약은 [GameSystemRules_UI.md](GameSystemRules_UI.md)의 UI 규칙을 준용한다.

## 스킬 메커니즘 타입

스킬의 실행 방식은 아래 **3종 타입**으로 구분한다. 각 타입은 코드에 실행기 하나로 구현하고, 구체 스킬·수치는 데이터로 주입한다(규칙 7). 구체 스킬 목록과 수치는 **추후 데이터로 확정**한다.

**규칙 11. 타입 A — 즉발 범위 피해**
- 조준 방식: **지점 지정**
- 대상: 적
- 효과: 지정한 지점의 원형 범위에 **1회(즉발) 피해**를 준다.
- 구현 기반: 기존 원형 AoE 판정을 재사용한다. (유닛 특수 공격의 원형 반경 판정 참조 — [GameSystemRules_Units.md](GameSystemRules_Units.md))

**규칙 12. 타입 B — 범위 지속 피해(장판)**
- 조준 방식: **지점 지정**
- 대상: 적
- 효과: 지정한 지점의 원형 범위에 **지속시간 동안 도트(DoT) 피해**를 준다.
- 구현 기반: 기존 DoT 틱 시스템을 재사용한다. (초 단위 틱 모드 참조 — [GameSystemRules_Units.md](GameSystemRules_Units.md))

**규칙 13. 타입 C — 전역 상태변경**
- 조준 방식: **전역 즉시(조준 없음)** — 버튼 탭 즉시 발동
- 대상: **아군(긍정 효과)** 또는 **적(부정 효과)**
- 효과: 지속시간 동안 대상의 스탯·상태를 변경한다. **버프·디버프·제어(둔화, 빙결=이동속도 0·공격 불가)·회복**을 모두 이 하나의 상태변경 시스템으로 표현한다. 회복은 아군에게 거는 긍정 효과의 한 형태로 흡수한다.
- 구현 기반: 기존 HoT(지속 회복) 시스템을 일부 재사용하고, **신규 상태변경 시스템**을 추가한다. 이 신규 상태변경 시스템이 이번 설계에서 가장 큰 신규 구현 덩어리다.
- 회복(힐)은 **우선 전역 즉시 방식으로 구현**하되, 구현 후 지점 지정형으로 전환할지 여부를 재결정할 수 있다.

**규칙 14. 유틸리티 타입 제외**
이번 설계 범위에서 유틸리티 타입(위 3종에 속하지 않는 보조 스킬)은 **제외**한다. UI 슬롯 7~9(규칙 9)를 향후 유틸리티 확장 여유분으로 남긴다.

## 발동 경로

스킬은 조준 방식(규칙 7)에 따라 아래 두 경로 중 하나로 발동한다.

**규칙 15. 즉시 발동**
버튼을 탭하는 즉시 발동한다. **타입 C(전역 상태변경)**가 이 경로를 사용한다. 조준 단계가 없다.

**규칙 16. 지점 지정 발동**
버튼 입력으로 지도 조준 모드에 진입하고, 지도상의 한 지점을 지정하여 발동한다. **타입 A·B(범위 피해/장판)**가 이 경로를 사용한다. 조준 UX는 아래 "모바일 지점 조준 UX"를 따른다.

## 모바일 지점 조준 UX

게임은 모바일(터치) 기준이다. 조작 흐름은 **탭으로 조준 모드 진입 → 화면 터치·드래그로 범위 이동 → 손 떼면 발동 → 하단 X로 취소**다. 기존 "랠리포인트 설정 모드" 아키텍처(조준 모드 플래그 + 다음 탭 처리, `InputHandler.HandleClick` 최상단 분기)를 재사용·확장하여 스킬 조준을 구현한다.

> **구현 상태 주의(설계 정정):** 아래 규칙 17~20은 사용자 확정 설계이며 **현재 코드에는 아직 반영되지 않았다**. 기존 구현은 "스킬 버튼을 누른 채 드래그(연속 홀드)" 방식이며, 탭 기반 조작으로의 코드 반영은 **별도 후속 작업**으로 진행한다.

**규칙 17. 탭으로 조준 모드 진입**
스킬 버튼을 **탭(누름)**하면 **스킬 패널이 닫히고** 화면에 착탄 범위를 나타내는 **범위(조준 원)**가 표시되며 **조준 모드에 진입**한다. 조준 모드는 버튼에서 손을 떼도 **유지**된다(연속 홀드 방식이 아니다).

**규칙 18. 엣지 스크롤(카메라 자동 팬)**
조준 모드에서 **화면을 터치·드래그하는 중 조준점(범위 원)이 화면 가장자리에 오면**, 그 방향으로 카메라가 자동으로 부드럽게 팬(엣지 스크롤)된다(스마트폰 스크롤 감각). 이를 통해 화면 밖·맵 외곽·구석까지 조준점을 옮길 수 있다.

**규칙 19. 손 떼면 발동**
조준 모드에서 **화면을 터치하면 그 순간부터 범위(조준 원)가 손가락을 따라 이동**하고, 원하는 위치에서 **손가락을 떼는 순간** 그 위치에 스킬이 발동한다. (발동 트리거는 스킬 버튼에서 손을 떼는 것이 아니라, **화면 터치의 release**다.)

**규칙 20. 취소 (하단 중앙 X 버튼)**
화면을 드래그하다 손가락을 화면 **하단 중앙의 X 버튼(에셋)** 위로 가져간 뒤 그 위에서 손을 떼면 발동을 **취소**한다(스킬은 발동하지 않는다).

**규칙 20-1. 취소 버튼 확대 예고 피드백**
드래그 중 손가락(조준점)이 하단 X 버튼 위로 오면 **취소 버튼 UI가 확대**되어, "여기서 손을 떼면 취소된다"는 사실을 사용자에게 미리 알려주는 예고 피드백을 준다.

- **확대 방식:** 확대는 즉시(하드) 적용이 아니라 **부드러운 보간(Lerp)**으로 진행한다. 손가락이 X 버튼 위로 오면 부드럽게 커지고, 벗어나면 부드럽게 원래 크기로 복귀한다.

**규칙 21. X 버튼과 하단 엣지 스크롤 겹침 회피 규칙**
취소용 X 버튼과 하단 엣지 스크롤 영역이 겹치지 않도록 배치한다.
- X 버튼은 화면 맨 끝보다 **살짝 안쪽**에 둔다.
- 엣지 스크롤은 화면 **진짜 가장자리 여백**에서만 발동시킨다.
- 정확한 여백 폭은 구현·테스트 단계에서 조정한다.

**규칙 22. 조준점 맵 범위 clamp**
조준점(범위 원)의 중심은 **맵 타일 범위 안으로 clamp**한다. 최외곽 타일이 한계이며, 조준점은 맵 밖으로 나갈 수 없다.

**규칙 23. 엣지 스크롤 맵 경계 정지**
엣지 스크롤은 **맵 경계에서 정지**한다. 맵을 과도하게 벗어나 빈 공간이 크게 화면에 들어오지 않도록 제한한다.

**규칙 24. 지정 가능 영역**
지점 지정이 가능한 영역은 "맵 안 어디든"이다. 사거리·시야에 의한 지정 제한은 없다(규칙 22의 맵 경계 clamp만 적용).

## 멀티플레이 / 서버 권위

기존 전투·방어 타워와 동일하게 서버 권위 원칙을 따른다. (아키텍처 제약: NetworkBehaviour는 Infrastructure 레이어에만, RPC 메서드명은 `ServerRpc`/`ClientRpc`로 끝남.)

**규칙 25. 서버에서만 판정·실행**
스킬 **발동·판정·피해·상태변경**은 **서버에서만** 실행한다. 엣지 스크롤·조준점 이동·범위 미리보기는 각 클라이언트의 **로컬 표현**일 뿐 게임 상태를 바꾸지 않는다.

**규칙 26. 좌표만 전송 + 서버 재검증**
클라이언트는 **손을 뗀 순간의 조준 좌표(1개)만** 서버로 RPC 전송한다. 서버는 다음을 재검증한 뒤에만 스킬을 발동한다(클라이언트 입력을 신뢰하지 않는다).
- 건물 생존 여부
- 건물 글로벌 쿨다운 만료 여부(규칙 3)
- 전송된 좌표가 **유효한 맵 타일**인지(규칙 22의 clamp를 서버에서 재확인)

즉시 발동(타입 C)의 경우 좌표가 없으므로, 서버는 건물 생존·쿨다운만 재검증한다.

## 추후 데이터로 확정할 항목

아래 항목은 현재 **미확정**이며, 향후 데이터(ScriptableObject) 또는 별도 밸런싱 작업에서 확정한다. 확정 시 이 문서를 갱신한다.

- 각 스킬 건물(FlightFacility / MagicSpirit / WillowShrine)의 **구체 스킬 목록**(각 슬롯 1~5에 어떤 스킬이 들어가는지)
- 각 스킬의 **수치**: 쿨다운(초), 반경, 지속시간, 피해량, 상태 효과 강도·종류
- 개별 스킬 쿨다운 도입 여부(현재는 건물 글로벌 쿨다운만)
- 회복 스킬의 지점 지정형 전환 여부(현재는 전역 즉시)
- enum 멤버 분리 전환 여부(현재는 `MagicBuilding` 공유 + 종족 키 분기 유지)
