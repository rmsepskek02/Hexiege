# Game System Rules — 건물 패널 UI

기존 UI 문서에서 역할별로 분리한 규칙 원본이다. 제목·규칙 번호·날짜별 결정 및 검증 한계를 유지한다. 본문의 「이 문서」·「위/아래」는 종전 배치 문맥을 포함하므로 아래 공통 원본과 함께 읽는다.

> 공통 UI 규칙 1~11·L-1~L-4는 [GameSystemRules_UI.md](GameSystemRules_UI.md#공통-ui-규칙), 역할 독립성은 [GameSystemRules_Network.md](GameSystemRules_Network.md)가 원본이다. 이 문서의 섹션별 규칙 번호는 재번호하지 않는다.

> 스킬 패널·모바일 조준은 [GameSystemRules_Skills.md](GameSystemRules_Skills.md), 연구 패널은 [GameSystemRules_Upgrade.md](GameSystemRules_Upgrade.md)가 기능별 원본이다. 랠리포인트·물안개 작동은 [GameSystemRules_Buildings.md](GameSystemRules_Buildings.md)에서 정한다.

## 생산 패널 UI

---

### 팝업 열기/닫기

**규칙 1. 팝업 열기**
배럭을 클릭하면 팝업이 열린다.
팝업이 열리면 해당 배럭의 랠리마커가 표시되고, 배럭의 팀과 종족에 맞는 유닛 버튼이 바인딩된다.
배경을 클릭하면 팝업이 닫힌다.

**규칙 2. 팝업 닫기**
팝업이 닫히면 모든 랠리마커가 숨겨진다.
랠리마커 표시/숨김 세부 규칙은 랠리포인트 시스템 섹션 참조.

---

### 유닛 버튼 입력

**규칙 3. 탭**
유닛 버튼을 탭하면 수동 생산 등록을 시도한다.

**규칙 4. 롱프레스**
유닛 버튼을 0.5초 이상 누르면 해당 유닛의 자동 생산을 토글한다.

**규칙 5. 자동 생산 중인 유닛 탭**
이미 자동 생산 중인 유닛 타입을 탭하면 추가 등록 없이 자동 생산 토글(해제)로 처리한다.

---

### 큐 구조

**규칙 6. 슬롯 구성**
슬롯은 3개다. 슬롯0은 현재 생산 중, 슬롯1은 대기 1순위, 슬롯2는 대기 2순위다.
슬롯에 표시되지 않는 자동 순환 대기 항목이 그 뒤에 추가로 쌓일 수 있다.

**규칙 7. 큐 상한 계산**
큐 상한(3개)은 현재 생산 중 1개 + 골드가 이미 차감된 대기 항목 수의 합산으로 계산한다.
골드가 차감되지 않은 자동 대기 항목은 합산에서 제외한다.

**규칙 8. 슬롯 클릭 취소**
슬롯을 직접 클릭하면 해당 슬롯의 생산을 취소한다.

---

### 골드 차감 시점

**규칙 9. 수동 항목**
수동으로 등록한 항목은 등록 즉시 골드가 차감된다.

**규칙 10. 자동 항목**
자동으로 등록한 항목은 슬롯1 또는 슬롯2에 표시되는 시점에 골드가 차감된다.
슬롯 뒤에서 대기 중인 자동 항목은 골드가 차감되지 않은 상태다.

---

### 생산 등록 검증 순서

**규칙 11. 검증 우선순위**
수동 생산 등록 시 검증 순서는 큐 상한 초과 → 골드 부족 → 인구 초과다.
이 순서는 실제 등록 로직의 검증 순서와 반드시 일치해야 한다.

---

### 생산 실패 피드백

**규칙 12. 실패 피드백 방식**

| 실패 사유 | UI 반응 |
|-----------|---------|
| 큐 가득 (3개 초과) | 토스트만 표시 |
| 골드 부족 | 토스트만 표시 |
| 인구 가득 | 토스트만 표시 |

골드 부족 시 유닛 비용 텍스트 색상은 실패 시점이 아닌, 골드가 변경될 때마다 자동으로 재평가된다.
인구 가득 시 HUD 인구 텍스트 색상은 HUD가 자체적으로 처리한다. 생산 패널이 관여하지 않는다.

---

### 정보 바 (골드/인구/비용 텍스트)

**규칙 13. 골드 텍스트**
보유 골드가 변경될 때마다 자동 갱신된다.

**규칙 14. 유닛 비용 텍스트 색상**
보유 골드가 해당 유닛의 비용보다 적으면 빨간색, 충분하면 흰색으로 표시된다.
골드 변경 시마다 자동 재평가된다.

**규칙 15. 인구 텍스트**
"사용/최대" 형식으로 표시된다.

---

### HUD (골드/인구 상시 표시)

**규칙 16. 인구 가득 상태 표시**
인구가 가득 찬 상태(사용 >= 최대)이면 인구 텍스트를 빨간색으로 표시한다.
가득 차지 않으면 흰색으로 표시한다.

**규칙 17. 인구 텍스트 형식**
"사용 / 최대" 형식으로 표시된다.

---

### 자동 생산 규칙

**규칙 18. 수동 등록 시 자동 모드 해제**
수동 항목을 등록하면 자동 모드가 전체 해제된다.
단, 이미 골드가 차감된 자동 항목은 수동으로 이관되어 생산이 계속된다. 환불 없음.
아직 골드가 차감되지 않은 자동 항목은 제거된다. 환불 없음.

**규칙 19. 자동 생산 해제/취소 시**
자동 유닛 타입을 해제하거나 해당 슬롯을 취소했을 때:
- 이미 골드가 차감된 자동 항목 → 수동으로 이관. 환불 없음, 생산 계속.
- 아직 골드가 차감되지 않은 자동 항목 → 제거. 환불 없음.

**규칙 20. 자동 생산 중복 방지**
자동 타입을 새로 등록할 때, 같은 타입이 이미 슬롯0에서 수동 생산 중이거나
대기 큐의 마지막 항목이 수동으로 등록된 같은 타입이면,
중복 추가 없이 기존 항목을 자동으로 전환한다. 골드는 이미 차감된 상태를 유지한다.

단, 대기 큐에 다른 항목이 있는 경우에는 슬롯0 전환 대신 대기 큐 끝에 새로 추가한다.
중간에 다른 유닛이 있으므로 이 경우는 중복이 아니다.
예: [Assault(슬롯0)] [Pistoleer(슬롯2)] 상태에서 Assault 자동 등록 →
    슬롯3에 Assault 추가 → [Assault(슬롯1)] [Pistoleer(슬롯2)] [Assault(슬롯3)]

**규칙 21. 자동 생산 중 자원 부족 시**
생산 시작 시점에 골드 또는 인구가 부족하면 자동 모드를 전체 즉시 취소한다.
남은 자동 항목들은 규칙 19에 따라 처리된다.

**규칙 22. 생산 완료 후 자동 순환**
자동 항목이 완료되면, 해당 타입이 자동 목록에 아직 있으면 대기 큐 끝에 재추가된다.
재추가 시 골드 미차감 상태이며, 슬롯1/2에 표시될 때 차감된다.

---

### 슬롯 직접 취소 규칙

**규칙 23. 취소 시 환불**
슬롯을 직접 클릭해 취소할 때 골드가 이미 차감된 항목은 전액 환불된다.
골드가 차감되지 않은 항목은 환불 없다.

---

### 스폰 대기

**규칙 24. 스폰 불가 시 대기**
생산이 완료됐으나 배럭 인접에 빈 타일이 없으면 진행률 100% 상태로 대기한다.
빈 타일이 생기면 다음 프레임에 즉시 스폰된다.

---

### 토스트 메시지

**규칙 25. 토스트 표시 방식**
서로 다른 종류의 토스트가 동시에 요청되면 큐에 쌓아 순서대로 하나씩 표시한다.
같은 종류는 누적하지 않는다 — 이미 표시 중인 종류가 다시 요청되면 큐에 넣지 않고 표시 시간만 처음 값으로 되돌리고,
큐에서 대기 중인 종류가 다시 요청되면 무시한다.
근거: 같은 문구를 두 번 보여 줘도 새 정보가 없고, 버튼을 연타하면 같은 안내가 요청 횟수만큼 몇 초씩 이어져 오히려 방해가 된다.
진입 애니메이션 없이 즉시 표시되며, 설정된 시간이 지나면 페이드아웃으로 사라진다.

**규칙 26. 토스트 터치**
표시 중인 토스트를 터치하면 현재 메시지가 즉시 제거되고 다음 메시지가 표시된다.

**규칙 27. 토스트 자동 정리**
게임 시작 또는 종료 시 남아있는 토스트가 자동으로 초기화된다.

**규칙 28. 토스트 종류**

| 키 | 표시 상황 |
|----|-----------|
| GoldInsufficient | 골드가 부족해 수동 생산을 등록할 수 없을 때 |
| PopulationFull | 인구가 가득 차 수동 생산을 등록할 수 없을 때 |
| ProductionQueueFull | 큐가 이미 3개로 가득 차 추가 등록을 거부할 때 |
| UpgradeRequired | 건물 업그레이드가 필요해 현재 단계에서는 생산할 수 없는 유닛을 탭했을 때 |
| SkillOnCooldown | 스킬이 쿨다운 중이라 스킬 슬롯을 탭해도 발동할 수 없을 때 |
| BuildingNotAllowed | 이 타일에는 건설할 수 없어(자기 팀 소유 건설 불가 타일) 건물 배치 패널을 열지 않을 때 |

### 패널 구조

**규칙 1. `BuildingPanelBase`를 상속한 전용 패널을 신설한다**
MistShrine 패널은 `BuildingPanelBase`를 상속해 공통 프레임(헤더 제목 · 닫기[X] · 하단 철거 버튼+환불 표시 ·
대상 건물 파괴 시 자동 닫힘(공통 UI 규칙 11) · `IGameUI` 생명주기)을 그대로 물려받는다.
연구 패널(`ResearchPanelUI : BuildingPanelBase`)과 동일한 방식이다.

**규칙 2. `BuildingSkillPanelUI`는 재사용하지 않는다**
스킬 패널은 **종족 로드아웃 5슬롯 · 3×3 그리드 · 지점 조준**을 전제하는 UI다.
MistShrine은 슬롯도 조준도 없으므로 스킬 패널을 재사용하지 않고 전용 패널을 만든다.
여기서 "슬롯이 없다"는 것은 **종족 로드아웃 스킬 슬롯이 없다**는 뜻이며, 패널의 **3×3 그리드 9슬롯 규격 자체는 그대로 쓴다**(규칙 10).

**규칙 3. 패널 구성 요소**
- 사용(시전) 버튼 1개
- 쿨다운 표시 (규칙 7)
- 자동 모드 표시 (규칙 6)
- 철거 버튼 + 환불 금액 텍스트 (베이스가 제공 — 별도 구현 불필요)

> 이 요소들의 **배치**는 3×3 그리드 9슬롯을 따른다(규칙 10). 미사용 슬롯 숨김 방식은 규칙 11.

**규칙 4. 닫기 규칙은 공통 팝업 규칙을 따른다**
배경 탭 시 닫힘(공통 UI 규칙 8·9). 대상 건물 파괴 시 자동 닫힘(공통 UI 규칙 11).

### 조작 (생산 패널과 동일하게 통일)

**규칙 5. 탭 / 롱프레스 조작**
조작 방식은 **생산 패널 유닛 버튼과 동일하게 통일**한다(생산 패널 UI 규칙 3·4·5와 같은 UX).

| 입력 | 동작 |
|------|------|
| 짧은 탭 | 수동 시전 1회 |
| 길게 누르기(0.5초 이상) | 자동 모드 토글 |
| 자동 모드 상태에서 짧은 탭 | 자동 모드 **해제** (시전하지 않음) |

자동 모드 상태에서의 탭은 생산 패널의 `state.IsAutoMode && AutoTypes.Contains(type)` → `HandleToggleAuto` 분기와
동일한 분기 처리를 따른다.

**규칙 6. 자동 모드 기본값은 OFF**
건설 직후 MistShrine의 자동 모드는 **꺼진 상태**다.
근거: 수동 상태에서 사용자가 곧바로 사용하지 않기를 원할 수 있으므로, 켜진 상태를 기본으로 강제하지 않는다.
자동 모드 ON/OFF는 패널에서 즉시 구분되도록 시각 표시한다 — 생산 패널의 **자동 생산 테두리 회전 머티리얼 패턴**을 재사용한다.
표시 방식은 **테두리 회전 효과 하나로 확정**이며, 오버레이 배선 주의사항은 규칙 14를 따른다.

### 쿨다운 표시

**규칙 7. 쿨다운 오버레이는 `SkillCooldownOverlay`를 재사용한다**
사용 버튼 위 쿨다운 표시는 기존 `SkillCooldownOverlay`(시계방향 radial fill + 남은 초 텍스트, 남은 시간 0 이하면 자동 숨김)를 그대로 쓴다.
이 컴포넌트는 스킬 전용 로직 없이 `SetCooldown(remaining, total)`만 받는 **순수 표시 컴포넌트**이므로 재사용에 제약이 없다.
`total`(발동 시점 총 쿨다운)이 fill 비율에 필요하므로, 로직 측에서 남은 시간과 총 쿨다운을 함께 제공해야 한다
(`GameSystemRules_Buildings.md` MistShrine 물안개 힐 시스템 규칙 21).

### 범위 표시 UI

**규칙 8. 아군 MistShrine 패널이 열려 있는 동안에만 범위를 표시한다**
- 아군 MistShrine을 클릭해 **패널이 열려 있는 동안에만** 반투명 원형 UI로 회복 범위를 표시한다.
- **패널을 닫으면 즉시 사라진다.**
- **적 MistShrine은 클릭해도 범위를 표시하지 않는다** — 상대에게 정보 우위를 주지 않기 위함이다.
- 물안개가 지속되는 동안의 범위는 **물안개 VFX 자체로 확인**되므로, 물안개 지속 중이라는 이유로 범위 UI를 따로 켜지 않는다.
- 렌더링은 지면 데칼 셰이더 재사용을 우선 검토한다(`GameSystemRules_Buildings.md` MistShrine 물안개 힐 시스템 규칙 27 — **ZTest Always 금지**).
- 원의 **시각 사양(채움·외곽선)** 은 규칙 12를 따른다.

### 회복 텍스트

**규칙 9. 회복 텍스트는 회복이 실제로 발생한 대상만 · 표시 주기를 힐 틱과 분리한다**
- **실제로 체력이 회복된 대상에만** 표시한다(최대 체력이라 회복량 0인 대상은 표시하지 않는다).
- **회복 틱(1초)과 텍스트 표시 주기를 분리**한다. 범위 내 다수 대상에게 매초 텍스트가 뜨면 화면이 도배되기 때문이다
  (BloomFairy HoT가 "완료 시 1회 표시"로 억제한 선례 — `GameSystemRules_Units.md` 규칙 37 HoT 힐 텍스트 집계).
- **표시 주기는 임시로 3초 누적 1회 표시**로 하고, 밸런싱 단계에서 확정한다(**미확정**).
- 건물 위 회복 텍스트는 신규 UI 없이 기존 경로로 커버된다(`FloatingHpTextSpawner`가 `IsUnit` 분기로 건물 월드 좌표를 이미 지원).

### 패널 레이아웃 (2026-08-10 확정)

**규칙 10. 패널 레이아웃은 3×3 그리드 9슬롯을 유지한다 (A안 확정)**
MistShrine 패널은 비생산 건물 패널의 공통 규격인 **3×3 그리드 9슬롯**을 그대로 사용한다(전용 패널을 만들되 그리드 규격은 공통을 따른다).

| 슬롯 | 용도 |
|:-:|------|
| 1 | **사용(시전) 버튼** (규칙 3·5, 쿨다운 오버레이는 규칙 7) |
| 2~5 | 미사용(예약) |
| 6 | **철거 버튼** (`BuildingPanelBase`가 제공 — 규칙 1) |
| 7~9 | 미사용(예약) |

슬롯 6을 철거로 **고정**하는 이유: `BuildingSkillPanelUI`가 이미 "슬롯 1~5 = 스킬 / **슬롯 6 = 철거** / 7~9 예약"(스킬 규칙 9) 배치를 쓰고 있어,
**모든 건물 패널에서 철거 버튼 위치를 동일하게 유지**해야 오조작(잘못된 철거)을 줄일 수 있기 때문이다.

**규칙 11. 미사용 슬롯은 `CanvasGroup.alpha=0`으로 숨긴다 — `SetActive(false)` 금지**
`SetActive(false)`는 GridLayout의 셀 정렬을 무너뜨려 남은 버튼이 앞으로 당겨지므로 금지한다.
`BuildingActionPanelUI`·`BuildingSkillPanelUI`가 이미 쓰는 패턴(슬롯 버튼마다 `CanvasGroup` 캐시, 기본 `alpha=0`)과 동일하게 처리한다.
입력 차단이 필요하면 `blocksRaycasts`를 가시성과 함께 맞춘다.

### 범위 표시 원의 시각 사양 (2026-08-10 확정)

**규칙 12. 범위 표시 원은 반투명 채움 + 외곽선을 함께 사용한다**
- **반투명 채움만으로는 경계가 모호해** 회복 범위를 정확히 읽기 어렵다. 따라서 **채움 + 외곽선**을 함께 그린다.
- 렌더링은 기존 지면 데칼 셰이더(`Assets/_Project/Shaders/SkillAimOverlay.shader`) **재사용을 우선 검토**하며,
  **ZTest Always는 금지**한다(`GameSystemRules_Buildings.md` MistShrine 물안개 힐 시스템 규칙 27, `GameSystemRules_Skills.md` 규칙 22-1).
- 표시 조건(아군 · 패널이 열려 있는 동안만)은 규칙 8 그대로다.
- **색상 · 투명도 · 외곽선 두께 값은 미확정**이며, 아트/밸런싱 단계에서 확정한다.

### 물안개 지속 중 사용 버튼 상태 (2026-08-10 확정)

**규칙 13. 물안개 지속 중에도 사용 버튼에는 쿨다운 오버레이만 표시한다**
- 물안개가 지속되는 동안에도 사용 버튼 표시는 **쿨다운 오버레이(규칙 7)뿐**이다.
- **"물안개 지속 중"임을 나타내는 별도 UI 표시는 두지 않는다.**
- 근거: 물안개 VFX가 맵에 떠 있어 플레이어가 지속 상태를 시각적으로 인지할 수 있으므로, UI를 중복으로 늘리지 않는다.
- 물안개 지속시간과 쿨다운이 다르다는 점(지속 < 쿨다운, `GameSystemRules_Buildings.md` MistShrine 물안개 힐 시스템 규칙 7)은 UI에서 구분하지 않는다.

### 자동 모드 시각 표시 (2026-08-10 확정)

**규칙 14. 자동 모드 표시는 테두리 회전 효과만 사용하고, 오버레이 오브젝트는 하나만 둔다**
- MistShrine 패널의 자동 모드 ON/OFF 표시는 **테두리 회전 효과 하나로 확정**한다(별도 도트 인디케이터를 두지 않는다).
- 근거: 프로젝트에 **도트 인디케이터 UI가 실재하지 않는다.** 씬(`Assets/_Project/Scenes/Game.unity`) 확인 결과
  `ProductionPanelUI`의 `_unitAutoIndicators`(List\<GameObject\>)와 `_unitBorderOverlays`(List\<Image\>)는
  **같은 `BorderOverlay` 오브젝트**를 각각 GameObject/Image로 가리키는 **중복 배선**이다.
  코드 주석의 "기존 도트 인디케이터"는 과거 설계의 흔적이다.
- 그 결과 생산 패널에서는 같은 오브젝트에 `SetActive`와 `CanvasGroup.alpha`가 이중으로 걸린다(두 제어 방향이 같아 시각 버그는 없다).
- **MistShrine 패널은 이 중복 구조를 복제하지 않는다** — 자동 상태 표시용 오버레이 오브젝트를 **하나만** 두고 **단일 경로로만 on/off** 한다.

> `ProductionPanelUI`의 중복 배선 자체를 정리할지는 이 문서의 범위가 아니다(별도 판단 필요).

## 건물 배치 패널 UI

### 비용 텍스트

**규칙 1. 건물 비용 텍스트 표기 형식**
건물 비용은 숫자만 표시한다. 'G' 등 접미사를 붙이지 않는다.
(생산 패널 비용 텍스트와 동일한 표기 방식.)

---

### 건물 비용 텍스트 색상

**규칙 2. 색상 표시 기준**
팝업이 열린 동안 현재 보유 골드가 해당 건물의 건설 비용보다 적으면 빨간색으로 표시된다.
충분하면 흰색으로 표시된다.

**규칙 3. 색상 재평가 시점**
팝업이 열리는 순간과 골드가 변경될 때마다 자동으로 재평가된다.
팝업이 닫히면 흰색으로 초기화된다.

---

### 건물 배치 실패 피드백

**규칙 4. 골드 부족 시 피드백**
골드가 부족한 상태에서 건물 버튼을 탭하면 토스트 메시지를 표시하고 팝업을 유지한다.
팝업을 닫지 않는 이유: 사용자가 비용 텍스트 색상을 통해 어떤 건물이 불가능한지 직접 파악할 수 있도록 하기 위함이다.

> **멀티플레이 분기 제외**: 위 규칙은 싱글플레이 분기에만 적용된다. 멀티플레이 RPC 분기는 별도 작업 예정.

### 무작위 맵 타일 선택과 건설 패널

> **타일 상태 표기**: 타일의 상태는 `TileKind` 한 가지 값(`Normal` 일반 타일 / `NoBuild` 건설 불가 타일 / `Blocked` 막힌 타일)으로 표현한다. 세 값의 성질과 이 표기를 쓰는 이유의 단일 소스는 `GameSystemRules_RandomMap.md` 5장(규칙 9·10)이다.

**규칙 5. 판정 우선순위**

`InputHandler`(Presentation)와 `GridInteractionUseCase`(Application)가 함께 다음 순서로 클릭을 처리한다. 패널을 여는 1·2번은 `InputHandler`가 맡고, 타일 상태를 판정하는 3~5번은 `GridInteractionUseCase`가 맡는다. 건물 액션 패널과 채굴소 배치 팝업을 여는 일은 Presentation의 몫이라 Application에 둘 수 없기 때문이며(레이어 규칙), 이 분담을 하나로 합치면 Application → Presentation 역참조가 된다.

1. 기존 building action 분기
2. `MineKind`와 MiningPost 건설 자격 분기
3. `TileKind.Blocked`(막힌 타일) 차단
4. `TileKind.NoBuild`(건설 불가 타일) 처리
5. 일반 타일(`TileKind.Normal`) 처리

광산 분기가 건설 불가 처리보다 먼저이므로 광산 타일의 MiningPost 예외는 유지한다.

**규칙 6. 막힌 타일 또는 빈 공간 클릭**

- 논리 `HexGrid`에 좌표가 있어도 `TileKind.Blocked`는 선택할 수 없다.
- 기존 타일 선택을 해제하고 열린 건물 배치 패널을 닫는다.
- 토스트를 표시하지 않는다.
- 새 타일 선택 이벤트를 발행하지 않는다.

**규칙 7. 자기 팀 소유 건설 불가 타일 클릭**

- 타일을 정상 선택하고 highlight를 표시한다.
- 건물 배치 패널을 열지 않으며, 이전 타일에서 열린 패널이 남아 있으면 닫는다.
- `ToastKey.BuildingNotAllowed`로 `이 타일에는 건설할 수 없습니다`를 표시한다.

**규칙 8. 중립·적 소유 건설 불가 타일 클릭**

- 타일 선택과 highlight만 수행한다.
- 건물 배치 패널을 열지 않고 stale 패널을 닫는다.
- 건설 의도가 성립하지 않으므로 토스트를 표시하지 않는다.
