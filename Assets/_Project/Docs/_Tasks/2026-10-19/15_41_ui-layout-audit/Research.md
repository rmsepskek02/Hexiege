## 3. 모든 화면에서 함께 볼 항목

- 기본 세로 비율과 다른 화면 비율에서 Safe Area・앵커・겹침・잘림・여백・스크롤 끝 접근을 확인한다. 가능한 비율과 실제 관측 범위를 기록한다.
- 긴 한글/영문/숫자・특수문자, 빈 값/빈 목록, 로딩・실패・활성/비활성 상태를 조건이 허용하는 범위에서 본다. 한글 깨짐과 glyph 누락을 구분한다.
- 버튼의 보이는 영역과 실제 터치 영역, 스프라이트 찌그러짐, 배경/오버레이/팝업 정렬 및 닫은 뒤 복원을 본다.
- 승인된 Light/Bold 역할 기준과 실제 에셋・효과를 대조한다. 기준 승인과 전체 UI 적용 완료는 별개다. 글자가 안 들어간다고 임의 축소하지 않고 공간・배치・줄바꿈을 먼저 검토한다.
- Yes=초록・No=빨강 합의는 유지한다. 단독 액션 색상은 별도 논의이며 이번 문서 작성만으로 일반화하지 않는다.

## 4. 구조 조사에서 구분할 대상

메인 구조 조사 인계에 따르면 계정 연동 입력과 인게임 프로필 뒤로가기에는 미배선/null 경계가 있다. `NetworkStatusUI`/`LoadingScreen`의 호출 미확인 경로, 구형 `LobbyUI` 및 로비 구형 프로필은 현재 화면과 분리한다. 미배선・호출 미발견・레거시를 실제 표시된 신규 결함으로 곧바로 취급하지 않고 관측 가능 여부와 참조 근거를 기록한다. 새 기능 구현・배선 복구・레거시 삭제는 이번 점검 범위가 아니다.

화면은 CanvasGroup이나 런타임 조건으로 나타날 수 있다. Hierarchy의 active 표시만으로 표시/숨김・미사용을 판정하지 않는다. 결과 화면의 보호된 Modal lease와 UIManager 오버레이 소유권은 보존한다.

## 6. 실행・관측 기록의 경계

사용자는 Unity 직접 조작을 승인했다. 메인은 computer-use 스킬과 `@oai/sky`로 연결했고 실제 기준 상태는 7절에 기록했다. 에디터 전용 MCP가 현재 노출되지 않았다는 사실만으로 Windows 컴퓨터 조작 가능성까지 불가라고 단정하지 않는다. 연결 성공과 Play・제품 UI 점검 성공은 구분한다.

자격증명 입력・로그인・결제・유료 닉네임 변경・서버 데이터 쓰기를 유발하는 조작은 자동 실행하지 않는다. UI 진입/Play/비율 변경은 관측 목적이며 native 인터페이스 제한이 확인되면 시도를 중단하고 제한・영향 범위를 기록한다. 수정 가능한 제품 구현 계획은 관측 결과와 별도로 사용자 합의를 거친다.

관측 인계는 화면 경로・상태・비율・실제 증상・근거・영향・미확인 사유로 남긴다. 문서 작성 담당자가 화면을 직접 관측한 것처럼 기록하지 않는다. 누적 관측은 7절 이후, 논의 후보는 11절과 최신 합의 13절을 따른다. 공통 구조와 미관측 경계는 15절, 최신 환경 동기화/재시험 전 상태는 서두와 16절을 기준으로 읽는다.

## 7. 에디터 연결 기준 상태 관측

이 절은 연결부터 Play 진입까지 각 당시 상태의 누적 기록이다. 이후 실제 화면 관측은 8~10절을 따르며 아래 대기/미실행 문장을 현재 상태로 재사용하지 않는다.

메인 실제 computer-use 관측 인계다. `@oai/sky`에서 중복 앱 항목을 같은 창 기준으로 구분하여 Unity 창에 연결했다. 최초 창 활성화 timeout 뒤 스킬 절차의 창 목록 재확인・상태 읽기로 복구했고 스크린샷을 얻었다. 도구 사용 불가가 아니다.

- 창 제목: `Hexiege - Login - Android`, Unity 6.3 `6000.3.5f2`
- 현재 씬: Login
- Game 프리셋: Mobile 1080×1920, 표시 배율 0.17x
- 에디터 상태: Compiling Scripts 진행 중. busy 표시가 24초에서 40초로 변해 진행을 관측했다.
- 아직 Play를 클릭하지 않았고 현재 Game 화면이 실행 중이라고 판정하지 않았다. 제품 UI 배치/가독성 판정도 아직 없다.

컴파일 완료를 잠시 기다린 뒤 원래 순서의 화면 점검을 이어간다. 이를 장기 blocked로 분류하지 않는다. 떠 있는 Android Logcat 창의 원시 로그・기기 식별자・사용자 계정은 문서에 옮기지 않았으며, 도구가 대화에 표시한 스크린샷의 base64나 새 이미지 파일도 문서에 저장하지 않았다. 새 문서 meta 자동 가져오기는 후속 관측 대상이지 완료 확정이 아니다.

후속 메인 관측에서 Compiling 뒤 Importing iteration 3으로 진행했고 busy 표시 01:17을 확인했다. 에디터 가져오기 진행을 기다리는 상태이며 도구 불가나 제품 Game 화면 정상 판정이 아니다.

그 뒤 컴파일/가져오기가 끝나고 `The open scene(s) have been modified externally` 대화상자가 나타났다. `Assets/_Project/Scenes/Login.unity`가 디스크에서 변경되어 다시 불러올지 묻는 Reload/Ignore 선택이다. 창 제목의 Login에는 별표가 보이지 않았으나 이것만으로 미저장 정보 손실 위험이 없다고 단정하지 않는다.

메인은 computer-use 확인 정책 [5.1]의 외부 앱 확인 경고에 대한 실행 시점 승인 경계에 따라 어느 버튼도 누르지 않았다. 사용자에게 Reload 후 점검 계속/직접 처리 선택을 물었으며 현재 응답 대기다. 승인 전에 이 대화상자를 처리하거나 제품 UI 조작을 이어가지 않는다. 에디터 연결은 유지되며 도구 실패・장기 blocked가 아니다. 사용자 회신 후 이어갈 수 있고 아직 Play・제품 UI 판정은 없다.

환경 변경 관측: 시작 때의 폰트 문서 2개 수정 외에 기존 로그 meta 2개(`_Logs/2026-10-16/11_31_logcat/RuntimeLog_device.txt.meta`, `_Logs/_editor/2026-10-16/RuntimeLog.txt.meta`)의 삭제 표시를 메인이 발견했다. 원인은 미확정이며 메인/담당자는 해당 로그 조작 명령을 실행하지 않았다. Unity 자동 삭제로 단정하거나 복원/정리하지 않고 외부 변경을 보존한다. 새 문서 meta의 자동 생성 여부도 아직 미확인이다.

사용자는 확인창을 직접 처리하겠다고 선택했다. 메인은 Reload/Ignore를 누르지 않았다. 이후 상태 읽기에서는 Unity 창이 다른 창에 가려 확인창 종료나 제품 화면을 판정할 수 없었다. 다른 앱의 구체 내용・계정은 기록하지 않는다. 현재는 사용자 처리 완료와 조작 가능한 상태 확인을 기다리며 제품 UI 조작・Play는 아직 수행하지 않았다.

사용자가 확인창 처리 완료와 이어 진행을 명시했다. 메인은 Unity 창 선택/활성화에 성공했고 확인창・컴파일 창이 사라진 것을 확인했다. Game 탭을 선택한 뒤 Shift+Space로 Game 뷰를 확대했다. 프리셋은 Mobile 1080×1920, 표시 배율은 0.4x이며 제품 파일 변경이 아닌 에디터 보기 조작이다.

## 8. Login 기본 화면의 실제 런타임 관측

2026-10-19 재개 뒤 메인이 에디터에서 직접 본 결과다. Domain Reload 종료 후 Splash가 실행됐고 Edit 모드에서 보였던 알림 겹침은 사라졌다. 관측은 아래 **6개 기본 범주・두 화면 비율의 일부 조합**이며 전체 UI나 모든 비율/조건을 확인한 것이 아니다. 모두 기본 빈 입력 상태로, 자격증명 입력・로그인 제출・회원가입・재설정 메일 발송・익명 로그인・계정 생성은 하지 않았다.

### 확인 후보와 아직 판정하지 않은 내용

- 익명 안내 본문은 버튼 문구보다 작고 본문 영역에는 여유가 보인다. 가독성 개선 후보지만 0.33x 축소 Game 뷰이므로 실기 읽기 실패나 최소 터치 영역 실패로 판정하지 않는다.
- 화면별 placeholder 굵기 차이는 이후 메인 정적 대조에서 설정 불일치가 확인됐다. `Login.unity`의 로그인 이메일 placeholder는 `Maplestory Light SDF.asset`, 재설정 이메일 placeholder는 `Maplestory Bold SDF.asset`이며 둘 다 fontStyle=0이다. 승인된 공통 UI 규칙 6의 입력 placeholder=Light에 맞춰 재설정 placeholder는 후속 수정 후보로 기록한다. ResetView/InputForm의 font override 문자열 검색에서는 교정 경로를 찾지 못했으나 모든 런타임 교정의 부재를 증명하지 않는다. 실제 렌더 전체의 폰트 보장으로 확대하거나 기존 입력 기능 수용을 취소하지 않는다. 폰트・씬은 수정하지 않았다.
- 인증 대기・최초 닉네임・네트워크 실패・입력값별 오류/활성 상태・긴 문구/키보드・로비・게임・공통/월드 UI는 이번 관측으로 확인되지 않았다. 상태를 만들기 위한 서버 요청은 수행하지 않았다.

이 묶음 관측 직후 원래 Mobile 1080×1920・0.4x로 복귀해 로그인 선택 화면에서 Play를 유지했다. 에디터 제품 파일을 저장하지 않았다. 당시 로비 접근에는 사용자 직접 로그인이 필요했다. 메인은 computer-use의 사용자 인증 자동화 금지 지침에 따라 로그인하지 않았고, 계정/비밀번호를 대화로 요청하지도 않았다. 사용자 직접 로그인과 완료 응답을 기다린 뒤 9절에서 실제 Lobby 관측을 재개했다. 사용자 로그인과 동시에 조작하지 않았다.

## 13. 레이아웃 방향 합의와 남은 점검 재개

사용자가 남은 화면 확인을 이어가도록 승인했다. 메인이 9:16・Play 유지・Lobby・인간 상태를 실제 재확인했다. 싱글 범위 점검은 계속하고 멀티 두 번째 실행을 준비할 수 있는지는 사용자에게 질문한 상태다. 멀티 화면을 이미 확인했다고 기록하지 않는다. UI 조작은 메인만 수행하고 문서 담당자는 후속 실제 관측 인계를 받아 기록한다.

이 단계에서 합의한 방향은 **기획/기능 추가・구현 없이 기존 UI의 레이아웃을 정리하는 것**이다. 전투 패널의 동일 크기와 공통 기능 고정 슬롯이라는 의도를 존중하고 충분한 여백을 유지한다. 빈 공간 자체를 결함으로 취급하지 않는다. 점검/교정 대상은 정렬・간격・프레임 침범이며, 닉네임 특수 팝업은 별도로 다룬다.

따라서 앞선 관측에서 큰 여백을 후보로 적은 사실은 보존하되, 그것만으로 패널을 축소하거나 설명 정보를 추가하자는 제안은 철회한다. 11절의 고정/내용 맞춤・정보 밀도 등은 당시 논의 초안이며 현재 합의보다 우선하지 않는다. 이 방향 합의가 지금 코드/씬/규칙을 바꿨다는 뜻은 아니다.

후속 관측은 정적 설정・실제 화면・기존 수용을 분리하고 실제 본 범위만 확정한다. 기존 인풋필드 수용과 원시 로그 private custody/무삭제/무업로드를 유지한다. 변경은 기존 두 Task 문서뿐이며 새 Task・Testcase・QA・상시 규칙・메모리・제품 파일・Git 변경은 하지 않았다. 전체 점검 완료는 아니며 후속 관측을 기다린다.
