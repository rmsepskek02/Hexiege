## 3. 조작・실행 경계

메인은 승인된 에디터 UI 조작・Play・화면 비율 변경으로 관측한다. 문서 담당자는 메인의 실제 관측 인계를 증거 범위대로 기록한다. 초기 연결과 기준 상태는 확인했으며 제품 UI 점검 성공까지 확장하지 않는다.

자격증명 로그인・결제・유료 변경・서버 데이터를 쓰는 동작은 자동 수행하지 않는다. 테스트용 조건을 만들기 위해 코드/씬을 변경하거나 새 개발 도구를 생성하지 않는다. Shop placeholder・미배선 입력/뒤로가기・호출 미확인/구형 UI는 신설・배선 복구・삭제로 확대하지 않는다. 기술적 접근 제한은 가능한 관측과 불가능한 상태를 구분해 보고한다.

새 폴더/Markdown meta는 수동 작성하지 않는다. Unity 자동 생성 가능성과 제품 수정은 구분한다. 원시 로그의 private custody와 보호 Modal/오버레이 계약을 유지한다.

## 4. 관측 기록과 인계 형식

관측 후 Research에 화면・진입 경로・비율・상태・직접 보인 문제・근거 위치・영향・미재현 사유를 추가한다. 정적 배선/동적 생성/첨부 이미지/과거 수용/이번 Editor 관측을 구분한다. 이미지 네 장의 원본 위치가 제공되면 참조만 연결하고 새 복사본을 만들지 않는다.

사용자 인계는 실제 문제 목록과 수정 우선순위, 합의해야 할 규칙 초안으로 정리한다. 새 구현・전체 UI 폰트 적용・상시 규칙 변경은 이 점검 계획의 자동 후속이 아니다. 실제 관측이 끝나기 전 “전체 점검 완료”로 보고하지 않는다. Testcase/QA는 별도 요청 없이 생성・실행하지 않는다.

## 5. 문서 확인 상태

아래 실행 기록의 현재/대기 표현은 각 관측 당시 상태다. 최신 상태는 서두와 이 절 마지막 인계 상태를 따른다.

문서 작성자는 새 두 파일의 자연어 목적・근거 링크・미관측 경계・승인 범위를 저장본으로 확인했다. `python3 Tools/check_docs.py`를 이번 작성 뒤 한 번 실행했으나 WindowsApps의 python3.exe 프로세스 시작이 ResourceUnavailable로 실패했다. 검사기 본문은 실행되지 않았으며 진단 0건/PASS를 확인하지 못했다. 다른 runtime 탐색은 하지 않았다. `_Tasks/`는 기계 검사 제외이므로 이 결과와 별도로 링크・의미・사실 대조가 필요하다.

제품 코드・씬・에셋 수정, 구현 검사・기기/멀티 검증은 수행하지 않았다. 구체적 화면의 제한 관측 완료와 전체 UI 범위의 점검 미완을 구분하며 이 두 문서 작성과 실행 근거를 별도로 기록한다.

메인 초기 연결 관측은 Research 7절에 기록했다. Login 씬・Mobile 1080×1920 프리셋에서 Unity 스크립트 컴파일 진행을 확인했으며 Play 클릭・제품 UI 판정은 아직 없다. 연결 timeout은 복구됐으므로 도구 불가나 장기 blocked로 처리하지 않고 컴파일 종료 뒤 원래 점검 순서를 이어간다.

후속 관측은 Importing iteration 3・busy 01:17로 진행 중이다. 가져오기 완료 뒤 점검을 이어가며 현재 기준 화면 표시만으로 제품 UI 정상 판정을 하지 않는다.

이후 컴파일/가져오기는 끝났으나 외부 변경 Login 씬의 Reload/Ignore 확인 대화상자가 나타났다. 메인은 computer-use 확인 정책에 따라 아무 버튼도 누르지 않고 사용자 선택을 기다린다. 제목에 별표가 없다는 관측을 미저장 정보 손실 안전 보장으로 확대하지 않는다. 승인 전 조작은 하지 않으며 에디터 연결 불가・장기 blocked로 분류하지 않는다. 실제 제품 점검은 응답 후 이어가고 Play・UI 판정은 아직 없다. 상세 누적 관측은 Research 7절을 따른다.

이후 사용자는 확인창 직접 처리를 선택했다. 메인은 Reload/Ignore를 클릭하지 않았고 처리 완료・조작 가능한 상태 확인을 기다린다. Unity 창이 가려진 후속 상태만으로 확인창 종료나 제품 화면 정상을 판정하지 않는다. 다른 앱의 내용은 기록하지 않으며 제품 UI 조작・Play는 아직 없다.

사용자의 처리 완료・이어 진행 승인 뒤 Unity 활성화와 확인창/컴파일 창 종료를 확인했다. Game 뷰 확대 후 Mobile 1080×1920・0.4x에서 첫 Play 클릭을 수행했고 파란 Play・Reloading Domain을 관측했다. 제품 파일은 바꾸지 않았으며 Edit 모드의 Splash/알림 겹침을 런타임 결함으로 판정하지 않는다. 현재는 Play 진입 중으로 실제 제품 UI 관측 뒤 원래 화면별 점검을 이어간다. 이전 입력 수용을 유지한다.

이후 Domain Reload가 끝나 Login 기본 6개 범주를 관측했다. Splash는 1080×1920, 로그인 선택/이메일/가입은 1080×1920과 1080×2340, 재설정/익명 안내는 1080×2340만 확인했다. 빈 입력 상태의 화면 배치와 이동만 관측했으며 자격증명 입력・인증 요청・메일 발송・계정 생성은 하지 않았다. 익명 본문 크기/placeholder 굵기는 근거 추가가 필요한 후보이며 전체 가독성 PASS나 폰트 위반으로 확정하지 않는다. 상세는 Research 8절을 따른다.

당시 원래 Mobile 1080×1920・0.4x의 로그인 선택 화면으로 돌아와 Play를 유지하며 사용자 직접 로그인/로비 도착 알림을 기다렸다. 인증 자동화・계정정보 요청・사용자와 동시 조작은 하지 않았고 완료 응답 뒤 로비 관측을 재개했다. 제품 파일 저장・새 검사・자동 문서 검사 반복은 하지 않았고 기존 입력 수용을 유지한다.

사용자 직접 로그인 완료와 실제 Lobby 창을 확인한 뒤 전투 기본・싱글 난이도 선택 화면・커스텀 선택/빈 코드 참가・상점 placeholder・프로필・닉네임 변경 팝업을 Mobile 1080×1920・0.4x Play에서 관측했다. 이 묶음 당시 난이도 선택/게임 시작・랜덤 매칭・방 생성/참가・닉네임 저장/구매는 실행하지 않았고 팝업이 열린 상태였다. 이후 설정/랭킹과 싱글 진입은 다음 기록을 따른다. 계정 값・스크린샷 복사 없이 Research 9절에 해당 시점의 상태와 후보를 기록한다.

그 뒤 사운드 하위 화면과 음소거 1회/해제 1회로 원래 100% 복원을 확인했다. 슬라이더/초기화는 조작하지 않았다. 빈 랭킹은 두 비율에서 관측했으나 실제 행/페이지는 미재현이다. Tall에서는 사운드・프로필・두 번째 닉네임 팝업도 확인했고, 입력/제출 없이 첫 열기와 달리 오류 안내가 사라진 상태를 원인 미확정으로 기록한다.

Tall에서 팝업 취소 후 CustomJoin/Custom/기본 전투 화면을 뒤로 순차 복귀하고 인간→정령→초월→인간을 관측해 원래 선택으로 복원했다. 이후 로컬 싱글 쉬움 선택으로 dim/spinner/로딩 문구를 확인했다. 당시에는 Game 준비 대기・인게임 관측 전・비율 복원 전이었으며 다음 기록에서 진입/관측을 이어갔다. 네트워크 방 생성/매칭은 하지 않았다. 상세는 Research 9절이며 로비 전체 조건 완료로 확대하지 않는다.

이후 쉬움/인간 싱글 진입과 로딩 종료를 확인했다. Tall HUD에서 개발 FPS/hover와 제품 HUD 겹침을 관측했으나 출시 빌드 결함으로 확정하지 않는다. 설정 메인/사운드, 빈 인게임 프로필을 관측했고 프로필과 설정 메인은 1080×1920에서도 확인했다. 값 변경 없이 이 묶음 직후 설정 메인에서 싱글 일시정지 상태였다. 당시 본진 클릭 1회 패널 미표시와 카메라 경계 상황은 원인 미확정으로 남겼고 이후 Castle 분기 대조는 다음 기록에 보정했다. Research 10절에 실제 범위를 남기며 기존 입력 수용・원시 로그 보존・제품 무수정 경계를 유지한다.

### 인게임 후속 관측과 현재 인계 상태

그 뒤 포기 확인창을 열고 취소로 복귀했다. 제목 없는 질문과 동일 크기의 초록 포기/빨간 취소, dim 뒤 설정을 관측했으며 포기 확정은 하지 않았다. 자연 패배 결과에서 다시하기를 한 번 눌러 새 싱글을 시작했다. 1080×1920에서 인간 건설 패널・훈련소 생산/큐 진행・연구소 강화 표를 관측했다. 연구소는 위쪽 밀집/아래 여백・내부 경계를 넘는 버튼 스킨・하단 철거 외형이 후보이며 최소 실기 글자 크기 실패로 판정하지 않는다. 연구/강화/철거 구매는 하지 않았다.

전체 UI 점검 완료가 아니다. 정령/초월 건물・Mist/스킬/조준/HP 세부, 멀티 대기/준비 실패/재경기/승리, 랭킹 데이터 행/페이지・긴 Toast・실기 Safe Area/최소 글자/터치는 미관측으로 남긴다. 다음 단계는 버튼 크기/색/위험 확인, 패널 크기/여백/표, 텍스트 크기/행간/대비/긴 문구, 개발 표시 분리를 묶어 논의할 초안이다. Research 11절의 분류를 규칙 확정으로 취급하지 않고 기존 폰트 기준・입력 수용을 유지한다. 코드・상시 규칙・다른 문서를 수정하지 않으며 문서 검사기의 기존 실행 불가 한계를 유지한다.

이후 정령 싱글 쉬움에 진입해 건설 7종・MagicBuilding 공통 패널을 확인했다. 폭우 선택으로 빨간 범위 원/취소 X를 관측하고 X로 취소했으며 발사하지 않았다. 기존 MiningPost 패널의 제목・철거 아이콘/비용・큰 여백도 관측했고 철거는 하지 않았다. 이 묶음 직후 정령 Game에서 해당 패널을 열어둔 상태이며 초월 추가 점검을 예정한다. 최종 종료 상태와 미관측 정리는 후속 인계 뒤 확정하고 상세는 Research 12절에 누적한다. 기존 제품/규칙/로그 무수정・입력 수용을 유지한다.

## 6. 남은 점검 재개와 현재 레이아웃 방향

사용자 승인으로 남은 실제 점검을 재개한다. 메인이 9:16・Play・Lobby 인간을 재확인했고 싱글 점검을 계속한다. 멀티 두 번째 실행 준비 가능 여부는 사용자 응답 대기다. 상세 최신 합의는 Research 13절을 따르며 UI 조작은 메인만 수행한다.

추가 기획/기능/구현 없이 기존 화면의 레이아웃을 정리하는 방향이다. 전투 패널 동일 크기・공통 기능 고정 슬롯 의도를 존중하고 충분한 여백은 유지한다. 빈 공간 자체를 결함으로 보거나 설명 추가・패널 축소로 해결하자는 이전 제안은 철회한다. 정렬・간격・프레임 침범을 중심으로 검토하며 닉네임 특수 팝업은 별도다. 앞선 후보/관측은 당시 기록으로 보존하고 이 합의를 현재 기준으로 적용한다.

아직 제품 수정이나 새 규칙 반영을 실행하지 않았다. 후속 관측이 오면 실제 범위・근거・미관측을 구분해 기존 두 문서만 갱신한다. 새 Task/TC/QA・규칙・메모리・코드/씬・원시 로그・Git 변경 없이 기존 입력 수용과 private custody를 유지한다. 현재 전체 UI 점검 완료가 아니다.

### 재개 후 추가 확보 범위

인간 FlightFacility 기본 패널, 정령 Research의 9:16/Tall, 초월 Research의 Tall을 실제 확보했다. 정령 연구 Tall은 Pause 후 비율 변경→1프레임 Step으로 정상 갱신된 화면을 관측한 것으로 미갱신 프레임과 구분한다. 인간 다른 생산 건물 선택 뒤 로비 전환 경로는 미확정이고 정령 FireSpire는 클릭 전 파괴돼 패널이 미확보다. 상세 관측은 Research 14절을 따른다.

### 재개 후 관측 마감과 공통 분기 정리

초월 연구를 9:16으로 바꾸고 1프레임 갱신해 기본 표를 확보했다. 이후 자연 패배/다시하기가 이어져 SporePatch 패널은 확보하지 못했고 반복 실행을 멈췄다. 결과에서 로비로 돌아와 인간 선택을 복원했다. 최종 상태는 Play 유지・Pause 해제・Lobby 인간 전투 기본 화면・Mobile 1080×1920・0.4x이며 제품 씬은 저장하지 않았다. 멀티 준비 응답이 없어 네트워크 조작은 하지 않았으며 응답 대기는 검사 실행이 아니다.

공통 생산 popup/단계, 2유닛과 최고 단계 숨김, Magic 로드아웃, 초월 연구 자연회복 별도 행, 공통 결과 상태 줄/별도 재경기 패널, Toast/랭킹/월드 숫자 구조를 읽기 전용 대조로 묶었다. 실제 배치 분기와 단순 데이터 변형을 구분하고 종족/단계를 모두 별도 화면인 것처럼 목록을 늘리지 않는다. 정확한 경로와 직접 관측 여부는 Research 15절 표를 따른다.

최종 반영 뒤 자동 문서 검사를 한 번 시도했으나 기존 ResourceUnavailable로 본문 실행은 불가했다. 진단 0건/PASS를 주장하지 않고 다른 runtime 탐색도 하지 않았다. `_Tasks/` 제외와 별도로 로컬 링크・시점・의미를 직접 확인한다.

## 7. main 동기화 뒤 점검 재시도 준비

현재 환경의 랜덤 매칭 1회 오류와 00:01 잔류 뒤 사용자가 Esc로 중단했다. 취소 복귀 관측은 없고 다른 환경 빌드의 정상 보고와 원인을 섞지 않는다. 사용자 main 동기화 승인으로 메인이 `codex/ui-improvements`를 origin/main의 `ec0002178230493dcb8490a541fa7c41bcee11b4`까지 fast-forward했다. 최초 meta 8개 충돌은 그 파일만 외부 보관 후 main meta를 적용했으며 원시 로그 본문・기존 작업을 보존했다. 정확한 수행/보관 이력은 Research 16절을 따른다.

4개 커밋・31개 파일 동기화는 메인 인계값이며 매칭 런타임 코드는 바뀌지 않았다. 새 커밋/push・충돌 해결용 코드 교정 없이 기존 문서/폰트 수정과 로그 meta 삭제 표시・Task를 유지했다. 권한 거절 뒤 승인 범위의 권한 상승 재시도는 성공했고 자동 승인 검토 거절로 설명하지 않는다.

동기화 직후에는 Play 해제・Login・1080×1920・0.4x에서 컴파일 후처리 진행을 확인했고 재시험 전이었다. 이후 재시험은 다음 기록을 따른다. main 동기화 성공을 매칭 해결이나 전체 점검 PASS로 대체하지 않는다. 문서 담당자의 수정은 기존 두 파일뿐이고 원시 로그 보호・기존 입력 수용을 유지한다.

### 2026-10-20 재시험 진행 상태

메인은 동일 HEAD/origin/main과 브랜치를 확인했다. 첫 Play/Tap 뒤 편집 화면 전환은 원인 미확정이며, Play를 한 번 재진입해 기존 세션의 Tap→Lobby를 관측했다. 로그인 자격증명은 조작하지 않았다. 로비에서 AccountInfoText/LiberationSans의 한글 glyph 미지원 경고를 관측했으나 광범위 폰트 교정은 하지 않았다.

랜덤 1회 재시도에서 00:01과 매칭 티켓 생성 정보, 이후 04:22로 증가한 대기를 관측했다. 식별자는 기록하지 않고 새 즉시 오류가 안 보였다는 범위와 상대 연결/멀티 Game 미확보를 구분한다. 당시 Play 유지・Pause 해제・Lobby 인간・9:16/0.4x 매칭 대기 중이었으며 다른 기기의 접속 결과를 기다렸다. 최신 멀티 UI 관측은 8절을 따른다. 과거 준비 가능 응답을 현재 접속으로 간주하지 않는다.

추가 로그 meta 삭제 표시/AndroidResolverDependencies 설정 변경은 메인 관측으로 Research 16절에 기록하고 원인 확정・임의 복구는 하지 않는다. 추가 pull・새 commit/push・코드 교정・원시 로그 조작 없이 기존 입력 수용/패널 여백 합의를 유지한다. 검사기는 기존 실행 불가 상태이며 성공/PASS로 보고하지 않는다. 전체 실제 UI 점검 완료가 아니다.

## 8. 멀티 UI 점검 재개 — 2026-10-21

사용자 승인으로 메인이 9:16/0.4x에서 자동 로그인→로비 인간→랜덤 대기→멀티 Game을 확인했다. 대기 화면의 제목/긴 취소 버튼과 남은 캐릭터/탭, Game HUD와 개발 IMGUI의 밀집, 설정의 동일 크기 3버튼과 작은 모서리 X, 빈 프로필 프레임과 X 뒤 Game 복귀를 관측했다. 정확한 상태와 한계는 [Research 17절](Research.md#17-매칭-교정-뒤-멀티-ui-점검-재개--2026-10-21)을 따른다.

첫 인계 당시 Play・Game・인간・Mobile 1080×1920・0.4x를 유지하며 기기에서 경기 종료 뒤 결과 화면을 남겨달라는 사용자 협조 요청 중이다. 당시 결과/재경기 UI는 확인 전이었고, 이후 아래 마감 기록에서 승리 결과만 확보했다. 관측된 빈 프로필을 기능 복구 계획으로 바꾸거나 Editor 축소 화면을 기기 최소 글자/터치 실패로 단정하지 않는다.

## 11. 최신 진행 방식 — Login 묶음 교정 후 사용자 확인

10절의 7파일 일괄 계획에 따른 1차 적용은 이미 인계됐지만 수정 후 화면 검수는 아직이다. 사용자 최신 요청에 따라 추가 편집을 Login 묶음으로 좁힌다. 10절 Login 행의 placeholder Light 방향은 현재 [공통 UI 폰트 규칙 6](../../../GameSystemRules/GameSystemRules_UI.md#폰트)의 **placeholder Bold / 실제 입력값 Light**로 대체한다. 안내/오류 본문 Light와 제목/버튼 Bold는 유지한다.

1. 구현 담당자가 Login placeholder 교정 결과를 인계한다. 아래 후속 인계로 소스 교정을 확인했으며 화면 검수와 구분한다.
2. Login 묶음의 수정 후 화면을 보고하고 사용자 확인을 받는다. 소스 적용/정적 검사/실제 화면 관측을 각각 구분한다.
