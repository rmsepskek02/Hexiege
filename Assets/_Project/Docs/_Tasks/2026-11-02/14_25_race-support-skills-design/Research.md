# Research — 종족별 지원 스킬 기획 확정

## 이 문서는 무엇인가

각 종족에는 버튼을 눌러 전장에 직접 효과를 내는 **스킬 건물**이 하나씩 있다(인간 FlightFacility · 정령 MagicSpirit · 초월 WillowShrine). 지금 이 세 건물에는 세 종족 모두 똑같은 **임시 스킬 5개**(폭탄 · 빙결 · 공격 버프 · 둔화 · 회복)가 들어 있다. 이것은 스킬 시스템이 제대로 돌아가는지 시험하려고 넣어 둔 자리채움일 뿐, 실제 게임의 스킬이 아니다.

2026-11-02 대화에서 사용자가 **종족마다 어떤 스킬을 넣을지**를 정했다. 인간은 "화력 지원"(포격·공습·연막·EMP·전술 지령), 정령은 "원소 마법"(메테오·서리 감옥·화염과 대지의 축복), 초월은 "강한 유닛을 더 강하게 만드는 숲의 마법"(늪·포효·순풍·쉴드·재생)이다. 초월은 일부러 직접 공격 스킬을 두지 않기로 했다.

문제는 이 스킬들 중 상당수가 **지금 스킬 시스템에 없는 기능**을 필요로 한다는 점이다. 예를 들어 지금 시스템은 "한 지점에 한 번 터지는 폭발", "한 지점의 지속 피해 장판", "맵 전체 아군/적에게 거는 상태" 세 가지만 할 수 있다. 그런데 서리 감옥은 "한 지점 안의 적만 얼리기", EMP는 "적 방어탑을 잠시 멈추기", 공습은 "직선으로 길게 폭격하기"가 필요하다.

이 문서는 **확정된 결정을 한곳에 기록**하고, **지금 코드가 무엇을 할 수 있고 무엇을 못 하는지**를 파일·행 단위로 확인해, 스킬마다 새로 만들어야 할 기능을 정리한다. 어떤 순서로 만들지, 규칙 문서를 어떻게 고칠지는 같은 폴더의 [Plan.md](Plan.md)에 있다. 이번 단계는 **문서만** 만든다 — 코드·에셋·규칙 문서 본문은 바꾸지 않았다.

**표기:** `[사실]` = 코드·에셋·문서를 직접 읽어 확인한 것(2026-11-02, HEAD `6e1d3167` 기준) · `[전달]` = 메인 세션이 전한 사용자 결정(대화 경과 요약, 이 Task 문서가 첫 기록) · `[계산]` = 사실 값으로 계산한 것 · `[추정]` = 확인하지 않은 판단 · `[제안]` = 문서 담당의 제안(결정 아님).

### 2-4. 쿨다운 — 건물 단위 잠금, 잠금 시간은 이미 스킬 값

- 남은 시간 저장: `SkillActivationUseCase.cs` 57행 `Dictionary<int, float>` — **키는 건물 Id**(56행 주석).
- 발동 성공 시 `SkillActivationUseCase.cs` 146행 `StartCooldownLocal(buildingId, skill.Cooldown)` — **잠금 시간은 방금 쓴 스킬의 쿨다운 값**이다.
- → P4(「건물 단위 잠금 유지 · 스킬별 잠금 시간 차등」)는 **지금 구조 그대로 데이터 값만 바꾸면 된다** `[사실 + 판단]`. 코드 변경이 필요한 부분이 아니다.
- `[계산]` 참고: 10분(600초) 경기에 10~15회면, 잠금이 끝나자마자 계속 쓴다고 할 때 평균 잠금은 600 ÷ 15 = **40초** ~ 600 ÷ 10 = **60초**다. 실제로는 건물 완성 전 시간과 쓰지 않고 쉬는 시간이 있으므로 이 값은 **상한 쪽 기준**일 뿐이며, 숫자 확정은 P2에 따라 밸런싱 단계에서 한다. 지금 값은 10~15초(2-1 표)다.

### 2-6. 멀티플레이 동기화와 연출 — 스킬 연출은 아직 0

- 발동 요청: `Scripts/Infrastructure/Network/NetworkSkillController.cs` 141행 `RequestActivateSkillServerRpc(int buildingId, int skillSlot, Vector3 aimWorld, bool hasAim, …)` — 조준 좌표는 **점 1개**(규칙 26과 일치).
