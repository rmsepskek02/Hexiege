# Plan — 중립 골드광산 대칭 배치 구현

## 이 작업이 무엇인지 (자연어 설명)

중앙의 두 중립 골드광산을 좌우로 더 넓게 옮겨, Blue와 Red가 같은 거리에서 경쟁하게 합니다. 현재 사용하는 FlatTop 10×20 맵에 사용자가 선택한 `(2,10)`, `(8,10)`을 적용해 각 성에서 10헥스로 맞춥니다. 게임 로직과 AI는 유지하고 광산 좌표 두 개만 바꾸는 최소 코드 수정입니다.

또한 이번 맵에만 적용되는 임시 판단으로 끝나지 않도록, 앞으로 만드는 모든 맵에서 시작 광산과 중립 광산의 거리 및 초기 접근성이 양측에 같아야 한다는 맵 공통 규칙을 새 문서로 남깁니다. 아래 기준은 game-design-lead 검토를 거쳐 확정했습니다.

구현 후에는 FlatTop 좌표를 프로젝트 방식으로 변환해 모든 성-광산 조합의 거리와 정적 접근성이 양측에 같은지 확인합니다. PointyTop은 현재 사용하지 않으므로 이번 구현·검증에서 제외하고, 실제 도입하는 맵 설계 작업에서 별도 좌표를 확정합니다. 사용자 요청에 따라 이 단계에서는 `Testcase.md`를 만들거나 QA 절차를 추가하지 않습니다.

---

## 구현 원칙

- 기존 금광 배치 흐름을 유지하고 좌표 데이터만 변경한다.
- 기존 로직은 제거하거나 주석 처리하지 않는다.
- 현재 실제 사용하는 `GameConfig.asset`의 FlatTop 10×20을 공정성 계산 기준으로 삼는다.
- 헥스 거리는 프로젝트의 `HexGrid.OffsetToCube()`와 `HexCoord.Distance()` 정의를 기준으로 판단한다.
- `GameDesignDocument.md`의 "중앙 부근 중립 금광 2개로 쟁탈전 유도" 의도를 유지한다.
- `GameSystemRules_AI.md` 규칙 27의 동적 `HasGoldMine` 조회 방식을 보존한다.
- 모든 orientation과 맵 config에 광산 공정성 규칙을 적용하고, 새 맵 또는 배치 변경 때 정적 검증한다.

## 구현 항목

### 1. 중립 광산 좌표 변경

**수정 파일:** `Assets/_Project/Scripts/Bootstrap/GameBootstrapper.Map.cs`

- `PlaceGoldMines()`의 `neutralMines`를 다음과 같이 변경한다.
  - `(3, midRow)` → `(2, midRow)`
  - `(7, midRow)` → `(8, midRow)`
- `midRow` 계산과 `SetGoldMine()` 호출 구조는 그대로 유지한다.
- 시작 금광과 시작 채굴소 좌표는 변경하지 않는다.

**근거:**

- `GameDesignDocument.md` 자원 시스템 — 중립 금광 2개를 중앙 부근에 배치해 쟁탈전을 유도한다.
- `GameConfig.asset` — 현재 사용하는 FlatTop 맵은 10×20이다.
- `HexGrid` / `HexCoord` — 새 좌표는 Blue 성과 Red 성에서 각각 10헥스다.
- `GameSystemRules_AI.md` 규칙 27 — AI는 좌표가 아니라 `HasGoldMine`을 동적으로 조회하므로 좌표 변경과 양립한다.

### 2. 오래된 숫자 주석 정리

**수정 파일:** `Assets/_Project/Scripts/Bootstrap/GameBootstrapper.Map.cs`

- `blueRow`의 과거 10×29 기준 숫자 `27`을 제거하고 "Blue Castle 행"이라는 계산 의미만 남긴다.
- `midRow`의 과거 10×29 기준 숫자 `14`를 제거하고 "맵 중앙 행"이라는 계산 의미만 남긴다.
- 계산식과 실행 로직은 변경하지 않는다.

**근거:**

- `GameConfig.asset` — 현재 높이는 20이므로 실제 계산 결과는 각각 18과 10이다.
- `CLAUDE.md` 주석 규칙 — 초급 개발자도 코드의 의도를 이해할 수 있는 정확한 설명을 유지한다.

### 3. 모든 맵의 골드광산 공정성 규칙 신설

**신규 파일:** `Assets/_Project/Docs/GameSystemRules/GameSystemRules_Map.md`

game-design-lead 검토로 확정한 다음 내용을 작성한다.

1. 모든 팀 전용 시작 광산은 **개수**, **자기 성 중심 기준 헥스 거리**, **경제 효과**가 팀별로 동일해야 한다.
2. 각 중립 광산은 개별적으로 Blue/Red 성 중심까지의 `HexCoord.Distance`가 동일해야 한다. 여러 광산의 평균이나 총합만 같은 것은 공정한 배치로 보지 않는다.
3. **정적 고정 장애물과 초기 건물**을 반영한 **성 인접 이동 가능 영역 → 광산 인접 이동 가능 타일의 최단 접근거리**도 양측이 동일해야 한다.
   - 포함: 맵 초기 상태의 고정 장애물, 금광을 포함한 이동 불가 타일, 초기 건물.
   - 제외: 동적 유닛, 경기 중 사용자가 건설한 건물, 일시적 혼잡.
4. 이 기준은 FlatTop/PointyTop 등 모든 orientation과 모든 맵 config에 적용한다. 새 맵 생성 또는 성·광산·정적 장애물 배치 변경 시 정적 검증한다.

**근거:**

- 사용자 확정 요구 — 모든 맵에서 골드광산은 양측 플레이어에게 평등하게 배치되어야 한다.
- `HexCoord.Distance` — orientation별 offset을 큐브 좌표로 변환한 뒤 사용할 프로젝트 표준 헥스 거리다.
- `GameDesignDocument.md` 자원 시스템 — 중립 금광은 양측이 경쟁하는 핵심 경제 거점이다.

## 검증 계획

### 정적 좌표 검증

`HexGrid.OffsetToCube(..., FlatTop)`과 `HexCoord.Distance()`의 공식으로 아래 결과를 다시 확인한다.

| 조합 | 기대 거리 |
|------|-----------|
| Blue 성 `(5, 18)` → 왼쪽 광산 `(2, 10)` | 10헥스 |
| Blue 성 `(5, 18)` → 오른쪽 광산 `(8, 10)` | 10헥스 |
| Red 성 `(5, 1)` → 왼쪽 광산 `(2, 10)` | 10헥스 |
| Red 성 `(5, 1)` → 오른쪽 광산 `(8, 10)` | 10헥스 |

또한 두 광산이 10×20 경계 안에 있고, 서로 다른 타일이며, 기존 시작 금광과 겹치지 않는지 확인한다.

**근거:** `HexGrid.OffsetToCube`, `HexCoord.Distance`, `GameConfig.asset`.

### 정적 접근거리 검증

- 현재 맵 초기 상태의 정적 고정 장애물, 이동 불가 타일, 초기 건물을 통과 불가로 취급한다.
- Blue/Red 성의 인접 이동 가능 영역에서 각 중립 광산의 인접 이동 가능 타일까지 최단 경로를 계산한다.
- 좌우 광산 각각에 대해 Blue와 Red의 최단 접근거리가 같은지 확인한다.
- 동적 유닛, 경기 중 사용자가 건설한 건물, 일시적 혼잡은 제외한다.

**근거:** 신규 `GameSystemRules_Map.md` 공정성 규칙 초안 3.

### 코드 검증

- 변경 diff를 확인해 `neutralMines` 좌표와 오래된 숫자 주석 외 실행 코드가 바뀌지 않았는지 확인한다.
- 프로젝트에 사용 가능한 비대화형 컴파일/정적 검사 명령이 있으면 실행한다.
- Unity Editor 실기 QA와 `Testcase.md` 작성은 사용자가 요청하지 않았으므로 이번 범위에 포함하지 않는다.

**근거:** `WORKFLOW.md`의 TC/QA는 사용자 명시 요청이 있을 때만 진행한다는 규칙.

## 예상 결과

- 초기 맵 생성 시 중립 금광이 offset `(2, 10)`, `(8, 10)`에 배치된다.
- 각 성에서 각 중립 금광까지의 헥스 거리가 모두 10으로 같아진다.
- 중립 광산 사이 거리는 4헥스에서 6헥스로 늘어난다.
- AI는 `HasGoldMine` 동적 조회를 계속 사용하므로 별도 좌표 수정 없이 새 광산 위치를 선택한다.
- 시작 금광, 채굴소, 성, 이동 불가 처리 등 기존 금광 로직은 유지된다.
- 모든 맵에 적용할 광산 공정성 기준이 전용 규칙 문서에 남고 두 문서 인덱스에서 검색 가능해진다.

## 구현 및 정적 검증 완료 기록

### 구현 결과

- 현재 사용하는 FlatTop 10×20 맵의 중립 광산을 `(2,10)`, `(8,10)`으로 변경했다.
- PointyTop은 현재 미사용이므로 좌표 확정과 검증에서 제외했다.
- 중립 광산 배치와 오래된 숫자 주석 외 기존 금광 로직은 유지했다.

### 규칙 검증 결과

| 검증 항목 | 결과 |
|-----------|------|
| Blue/Red 성 `HexCoord` | Blue `(5,16,-21)`, Red `(5,-1,-4)` |
| 중립 광산 `HexCoord` | 왼쪽 `(2,9,-11)`, 오른쪽 `(8,6,-14)` |
| 성 중심→중립 광산 거리 | B-L/B-R/R-L/R-R = `10/10/10/10` |
| 정적 BFS 접근거리 | B-L/B-R/R-L/R-R = `8/8/8/8`, 모두 도달 가능 |
| BFS 차단 집합 | 성 2 + 시작 광산/초기 채굴소 2 + 중립 광산 2 |
| 시작 광산 | Blue `(3,18)`, Red `(3,1)`, 팀별 1개 |
| 자기 성→시작 광산 거리 | `2/2` |
| 시작 광산 정적 접근거리 | `0/0`, 모두 도달 가능 |
| 초기 채굴소·경제 효과 | 팀별 1개, 동일 `MiningGoldPerSecond` |

신규 `GameSystemRules_Map.md`가 요구하는 중립 광산의 개별 헥스 거리 대칭, 정적 접근거리 대칭과 도달 가능성, 시작 광산 및 초기 경제 조건 대칭을 모두 충족한다.

### 컴파일 확인

현재 환경에서 `dotnet`과 Unity 실행 파일을 찾을 수 없어 Unity 컴파일은 실행하지 못했다. 이번 변경은 좌표 상수와 주석의 최소 수정이며, 정적 좌표·경계·거리·BFS 검증은 완료했다.
