# Plan — 지원 스킬 공통 전제(C-1 · C-4) + 포격 지원

## 이 문서는 무엇인가

지금 게임의 스킬 건물에는 **테스트용 임시 스킬**이 들어 있고, 스킬을 써도 **이펙트가 보이지 않는다.** 이 계획은 진짜 지원 스킬을 붙이기 위한 **첫 코드 작업**이다(사용자 「추천대로 진행하고 task 문서 작성해」, 2026-11-03 — 상위 Plan 5-1 결정 31). 세 가지를 한다.

- **스킬 이펙트가 양쪽 화면에 같이 보이게 한다(C-1).** 지금 멀티플레이에서는 "스킬을 썼다 · 쿨다운 몇 초"만 상대에게 전해진다. 이것을 "어느 건물이 몇 번 칸 스킬을 어디에 썼다"까지 전하도록 바꿔서, 내 화면과 상대 화면이 **같은 자리에 같은 이펙트**를 띄우게 한다. 앞으로 나올 모든 스킬이 이 길을 쓴다.
- **스킬 칸을 진짜 스킬로 바꾼다(C-4).** 세 종족의 스킬 칸 5개에 확정된 스킬 15개를 넣고, 스킬 데이터에 **이름 · 설명**을 적는 칸을 만든다. 아직 코드가 없는 스킬은 **"사용 가능" 표시를 꺼 두어** 눌러도 쓰이지 않게 하고, 쿨다운도 돌지 않게 한다. 지금의 임시 스킬 자산은 **지우지 않고 남겨 둔다**(되돌릴 수 있게).
- **포격 지원을 완성한다(인간 1번 칸).** 이미 만든 포격 이펙트(포탄 7발이 한꺼번에 떨어진다)를 연결하고, **포탄이 땅에 닿는 0.4초 뒤에** 피해가 들어가도록 서버가 피해를 그만큼 늦춘다. 이 "늦게 터지는 장치"는 나중에 메테오(1.5초 뒤 낙하)가 그대로 다시 쓴다.

현재 코드 상태와 근거(파일 · 행)는 [Research.md](Research.md)에 있다. 추천안은 game-programmer가 코드를 읽고 낸 것이며, **사용자 결정이 아니다.** 7절의 사용자 확인 Q1~Q6을 정한 뒤, 이 Plan을 사용자가 승인해야 구현을 시작한다(WORKFLOW [4]).

## 3. 항목별 방법

### 3-1. C-1 발동 연출 동기화 — 데이터 형태 `[추천 — 프로그래머: A]`

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A (추천)** | Application 값 객체 하나(이름 예: 「스킬 발동 표현」) — 건물 Id · 팀 · **슬롯** · 조준 여부 · **조준 좌표(도메인)** · 발동 순번 · 착탄 지연(초) | 받는 쪽이 팀 → 종족 → 로드아웃 → 슬롯으로 SkillData를 다시 찾아 VFX · 반경을 얻는다(양쪽 빌드가 같다는 것은 스키마가 보장). 전송량 작음. 메테오는 「착탄 지연」 칸으로, EMP는 대상 탑 목록을 **별도 RPC**로 확장 | 로드아웃 순서가 다른 빌드끼리 섞이면 다른 VFX — 스키마 상향으로 막음 |
| B | 반경 · VFX 키까지 실어 보냄 | 받는 쪽 조회 없음 | 데이터 중복, 스킬 규칙 7(데이터 한 곳)과 어긋남 |
| C | 쿨다운 RPC는 두고 연출 전용 RPC 신설 | 기존 RPC 무변경 | 같은 사건에 RPC 두 개 → 도착 순서 문제. 스키마 상향은 어차피 필요 |

- **발동 순번을 넣는 이유:** 같은 건물이 쿨다운 뒤 다시 쓴 발동과 늦게 오는 착탄을 짝지을 열쇠다. 메테오 착탄 폭발을 따로 재생할 때 필요하다.
- **강화 상태 VFX(상위 4절 20):** 맵 전체 팀 버프의 대상은 기존 `StatusAppliedClientRpc`(팀 단위)로 이미 양쪽에 재현된다 `[사실]`. C-1 페이로드에 유닛 목록을 싣지 않는다. 상태 VFX는 그 상태 적용 경로에 붙이는 것이 맞다고 프로그래머가 판단했다. 발동 뒤 새로 생산된 유닛 포함 여부(상위 4절 19)는 **여전히 열려 있다** — 이 Task 범위 밖.

**흐름 (추천안 A):**

| 역할 | 순서 |
|---|---|
| 싱글 | 패널 → Activate 성공 → UseCase가 「확정」 이벤트 발행 → 화면 구독자가 VFX 재생 |
| Host (서버이자 클라이언트) | ServerRpc → Activate 성공 → 「확정」 이벤트(Host 화면이 이걸로 재생) → NetworkSkillController가 구독해 새 ClientRpc 브로드캐스트 |
| 순수 클라이언트 | ClientRpc 수신(`if (IsServer) return;` 뒤) → 쿨다운 미러 + 「수신」 이벤트 발행 → 같은 화면 구독자가 재생 |
| 빨강(뒤집힌) 화면 | 페이로드는 도메인 좌표 그대로. 화면 쪽에서 `ViewConverter.ToView(aim)`로 변환. 프리팹이 원형이라 회전은 항등. 포탄 무늬가 180° 돌아 보일 수 있다 `[추정 — 게임에서 확인]` |

- Host 화면이 「확정」과 「수신」을 두 번 재생하지 않게 수신부의 `IsServer` 가드를 유지한다(공격 표현 선례와 같은 방식 — Research 3-3).
