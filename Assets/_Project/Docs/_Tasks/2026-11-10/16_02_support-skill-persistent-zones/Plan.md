# Plan — 지원 스킬 2-Z 지속 상태 구역 (서리 감옥 · 수액 늪) + 구역 · 얼음 상태 VFX 칸

## 이 문서는 무엇인가

이 계획대로 하면 다음처럼 된다.

- 정령 **서리 감옥**을 지도 한 지점에 쓰면 그 자리에 **얼음 구역이 몇 초 동안 남는다.** 그동안 구역 안의 적 유닛은 **얼어서 움직이지도 공격하지도 못한다.** 구역에 나중에 걸어 들어온 적도 얼고, 구역이 끝나면 풀린다.
- 초월 **수액 늪**을 쓰면 그 자리에 **수액 구역**이 남는다. 그동안 구역 안의 적 유닛은 **크게 느려진다.** 들어온 적도 느려지고, **걸어 나가거나** 구역이 끝나면 원래 속도로 돌아온다.
- 바닥에 깔리는 **구역 이펙트**(서리 V3 · 수액 V9)와, 얼어붙은 유닛 몸에 붙는 **얼음 이펙트**(V4)를 넣을 **칸이 스킬마다** 생긴다. 이펙트 프리팹은 아직 없어서 이번 작업이 끝나도 화면에는 보이지 않고 **효과만 동작한다.** 나중에 프리팹을 만들어 칸에 넣기만 하면 **코드를 고치지 않고 바로 보인다** — 내 화면과 상대 화면 모두 같은 구역 · 같은 유닛에.
- 인간 **연막탄**도 같은 「구역」 스킬이지만 핵심인 「원거리 공격 회피」가 다른 큰 기능이라 이번엔 꺼진 채로 둔다. 이번에 만드는 구역 장치 위에 나중에 얹을 수 있게 만든다.

숫자(반경 · 몇 초 · 몇 배)는 **시험용 임시값**이며 밸런싱 단계에서 정한다. **사용자가 알아야 할 것:** 추천안(Z-2)대로 하면 멀티 접속 호환 번호가 8 → 9로 올라가, 테스트 때 **에디터와 기기 두 빌드를 모두 새로 설치해야** 서로 경기할 수 있다.

현재 코드 상태와 근거(파일 · 행)는 [Research.md](Research.md)에 있다. 아래 **Z-1~Z-21은 사용자가 정할 항목**이며, 각 칸의 「추천」은 메인 세션의 추천이다(**사용자 결정이 아니다**). 결정과 이 Plan의 승인이 있어야 구현을 시작한다(WORKFLOW [4]). *(2026-11-11 — 사용자 「추천대로 진행하자」로 Z-1~Z-21 모두 추천안 확정 · Plan 승인. 2절 각 항목의 `[제안 — 메인 세션 추천]` 표기는 작성 당시 그대로 두었다 — 확정 여부는 1절 표가 기준이다.)*

### Z-1. 구역 효과의 저장 · 합성 `[제안 — 메인 세션 추천]`

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| Z1 짧은 재부여 | 틱마다 구역 안 유닛에게 짧은 상태를 기존 상태 시스템으로 다시 건다 | 코드 최소 | **순풍 소실 버그** — 같은 종류는 통째로 교체되므로(Research 5-5) 수액이 순풍 기록을 덮어, 늪을 나간 뒤 순풍이 사라진다. 이탈 해제가 최대 2틱 늦다 |

- `[제안 — 문서 담당]` 위험: 이동 배율 · 공격 가능 여부를 `UnitCombatUseCase` 접근자가 아니라 상태 시스템에서 **직접** 읽는 곳이 있으면 구역 효과를 놓친다 — 구현 때 프로그래머가 그런 호출이 있는지 확인해 보고한다(8절 R-7).

### Z-2. 상대 화면 표시 · 동기화 `[제안 — 메인 세션 추천]`

| 안 | 구역 VFX | 얼음 상태 VFX(V4) | 스키마 | 한계 |
|---|---|---|---|---|
| N-A | 발동 채널(C-1) 재사용 | Client가 화면 위치로 스스로 판정 | 8 그대로 | 보간 지연만큼 경계 유닛이 서버와 다름 |
| **N-B(추천)** | 발동 채널(C-1) 재사용 | 서버가 틱마다 **바뀐 유닛 Id만** 묶어 보냄(새 RPC — EMP Id 배열 선례) | **8 → 9** | 전송 지연만(EMP R-7과 같음) |

- **영향(사용자가 알아야 할 것):** 스키마 9가 되면 **에디터와 기기 두 빌드를 모두 새로 설치해야** 멀티 테스트를 할 수 있다 — 스키마 8 빌드와는 경기 시작 확인에서 거부된다. 테스트 비용이 늘어난다.
- 구역 VFX는 어느 안이든 각 화면이 자기 빌드의 스킬 데이터에서 반경 · 지속 · 프리팹을 찾고, 끝은 로컬 타이머로 정한다(Research 7절).

### Z-3. 「구역 안」 판정 기준 `[제안 — 메인 세션 추천]`

- 추천: 유닛이 선 **타일 중심 ↔ 조준점** 거리 ≤ 반경 — 지금 모든 스킬 범위 판정 · EMP(스킬 규칙 27) · 물안개와 같다(Research 5-3).
- 결과: 유닛 타일 좌표는 **타일 경계를 넘을 때** 바뀌므로, 구역에 들어가고 나가는 순간도 타일 경계를 지날 때다. 화면에서 모델 가장자리만 원에 걸친 유닛은 대상이 아닐 수 있다(EMP R-13과 같은 성질).
- 다른 안: 화면 몸 위치 기준 — 서버에는 그 값이 없다(이동은 타일 단위 커밋).

### Z-4. 판정 주기 · 자리 `[제안 — 메인 세션 추천]`

- 추천: 서버 권위 틱마다 다시 판정 — 멀티는 서버 전투 틱(씬 값 0.1초), 싱글은 게임 루프 매 프레임. 멀티는 상태 틱 · 유닛 전투 루프 **앞**에 두어 같은 틱에 공격 관문이 구역 결과를 보게 하고, 싱글은 유닛 상태 틱 앞(EMP 가드 선례)이다(Research 5-4).
- 근거: 비용이 작고, 구역 안에서 막 생산된 유닛도 다음 틱에 들어간다(결정 4 「나중에 들어오는 유닛도」). 스킬 규칙 25 「서버의 권위 틱」.

### Z-5. 같은 스킬 구역 겹침 `[제안 — 메인 세션 추천]`

- 추천: **효과는 1회만.** 같은 팀의 서리 감옥 두 개가 겹쳐도 빙결은 하나, 수액 늪 두 개가 겹쳐도 0.4배 한 번(0.16배가 아님). 유닛은 겹친 구역 중 하나라도 남아 있으면 계속 걸린다.
- 근거: 스킬 규칙 13 「배율은 겹치지 않는다」, 물안개 규칙 13 「중첩되지 않는다」.
- 참고: 건물 글로벌 쿨다운(스킬 규칙 3)이라 한 건물로는 구역 지속(4 · 6초) 안에 다시 쓸 수 없다 — 겹침은 **같은 종족 스킬 건물이 둘**일 때 생긴다.

### Z-6. 다른 출처의 같은 종류 겹침 (D11 뒤 절반) `[제안 — 메인 세션 추천]`

- 한 플레이어(팀)는 한 경기에 **한 종족**이다. 스킬은 **자기 스킬 건물**에서만 쓴다.
- 서리 감옥 = **정령**으로 플레이해 **MagicSpirit**을 짓고 **2번 칸**, 수액 늪 = **초월**로 플레이해 **WillowShrine**을 짓고 **1번 칸**(상위 Plan 1-2 · 1-3, 셋업 도구 슬롯 값 — Research 4-2).
- **AI는 스킬을 쓰지 않는다**(Research 10절). 대신 **내가 AI 유닛에게 쓴다** — 싱글로 가능하다. 두 스킬 모두 **적 유닛**에게만 걸린다.
- **적 유닛이 구역에 들어오고 나가는 장면이 필요하다.** 적 유닛이 걸어오는 길 앞에 구역을 깔면 「들어오면 걸림」을 볼 수 있다. 「걸어 나가면 풀림」은 **수액 늪**으로 본다 — 서리 감옥에서 언 적은 움직이지 못해 스스로 나가지 못할 것으로 보인다(Research 6절 문서 담당 관찰 — 프로그래머 확인).
- **같은 스킬 겹침(Z-5)** 은 쿨다운이 건물 단위라 **같은 종족 스킬 건물을 둘** 지어야 볼 수 있다.
- **순풍 × 수액(Z-6)** 은 순풍 · 수액이 모두 초월 스킬이라 **초월 대 초월 멀티**에서만 생긴다 — 상대(초월)가 자기 유닛에 순풍을 건 채 내 수액 늪에 들어와야 한다. 가능하면 1회.
- **스키마 9(Z-2 N-B)** — 멀티는 **에디터와 기기 두 빌드를 모두 새로 설치**해야 한다.
- **시전 건물 파괴(Z-7)** 는 구역을 깐 뒤 그 스킬 건물을 **철거**하면 싱글에서도 볼 수 있다 `[제안 — 문서 담당]`(철거 버튼 = 스킬 패널 6번 칸, 스킬 규칙 9).
