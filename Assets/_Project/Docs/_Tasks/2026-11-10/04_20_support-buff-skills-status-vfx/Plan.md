# Plan — 지원 스킬 1차 강화 4종 + 강화 상태 VFX 경로

## 이 문서는 무엇인가

이 계획대로 하면 다음처럼 된다.

- 인간 **전술 지령**, 정령 **화염의 축복**, 초월 **숲의 포효**를 쓰면 **맵 전체 아군 유닛의 공격력이 잠시 오른다.** 초월 **숲의 순풍**을 쓰면 **아군 유닛이 잠시 빨라진다.** 지금은 네 스킬 모두 「사용 불가」로 꺼져 있다.
- 효과를 받는 유닛마다 몸에 붙는 **강화 상태 이펙트**를 넣을 수 있는 칸이 **스킬마다 따로** 생긴다. 네 스킬의 이펙트는 서로 다른 그림이어도 된다 — 칸이 스킬마다 있기 때문이다. 이펙트를 유닛에 붙이고, 유닛을 따라다니게 하고, 효과가 끝나거나 유닛이 죽으면 떼는 **장치는 네 스킬이 함께 쓴다.**
- 이펙트 프리팹은 아직 없다. 그래서 이번 작업이 끝나도 화면에는 이펙트가 보이지 않고 **효과만 동작한다.** 나중에 프리팹을 만들어 그 스킬 칸에 넣기만 하면 **코드를 고치지 않고 바로 보인다.** 칸이 비어 있으면 진단 로그가 「비어 있다」고 한 줄 남긴다.
- 즉시 발동 스킬(조준 없이 버튼만 누르는 스킬)의 **발동 순간 이펙트**도 지금은 칸을 채워도 나오지 않는다. 어디에 띄울지가 정해지지 않았기 때문이다. 이 자리를 정해 두면 같은 방식으로 프리팹만 넣으면 된다(D3).

숫자(공격력 몇 배 · 몇 초)는 **시험용 임시값**이며 밸런싱 단계에서 정한다. 전술 지령의 **생산 속도** 부분은 새 기능이 필요해 이번에 하지 않는다.

현재 코드 상태와 근거(파일 · 행)는 [Research.md](Research.md)에 있다. 아래 **D1~D14는 사용자가 정할 항목**이며, 각 칸의 「추천」은 메인 세션의 추천이다(**사용자 결정이 아니다**). 결정과 이 Plan의 승인이 있어야 구현을 시작한다(WORKFLOW [4]). *(2026-11-10 — 사용자 「추천대로 진행하자」로 D1~D14 모두 추천안 확정 · Plan 승인. 2절 각 항목의 `[제안 — 메인 세션 추천]` 표기는 작성 당시 그대로 두었다 — 확정 여부는 1절 표가 기준이다.)*

> **현재 상태 (2026-11-11):** **구현 완료 · 사용자 테스트 PASS.** 네 스킬이 「사용 가능」으로 켜져 효과가 동작하고, 강화 상태 VFX 칸 · 즉시 발동 발동 VFX 갈래가 준비됐다(프리팹은 아직 없다 — 칸이 비어 있다). 결과 · 판정 · 남은 일은 [11절](#11-implementation-and-user-test). *(2026-11-11 갱신 — 직전 「**Plan 승인 — 구현 중.** … 구현은 game-programmer 진행 중.」, 그 전 「첫 판 — **D1~D14 사용자 결정 대기 · 구현 승인 전.**」)*

### D5. 전술 지령 공격력만 `[제안 — 메인 세션 추천]`

- 추천: 켠다. 생산 속도는 새 상태 종류(2-S)라 이번에 없다.

### D6. 화상 · 독 고정 피해 `[제안 — 메인 세션 추천]`

### D10. 값 반영 `[제안 — 메인 세션 추천]`

- 추천: 셋업 도구의 네 줄을 새 값으로(옛 줄은 주석 — 최상단 표) + 자산 값. 자산 값은 에디터에서 도구를 다시 실행하거나 직접 입력한다 — 어느 쪽으로 할지는 구현 때 game-programmer가 정하고 보고한다. 새 칸(강화 상태 VFX)은 도구가 건드리지 않는다(Research 4-2).

### D11. 같은 종류 · 다른 출처 덮어쓰기

### D14. 임시 테스트용 프리팹 `[제안 — 메인 세션 추천]`

- 프리팹이 없으면 이번 테스트는 **효과 + 「빈 칸 경고 로그」** 로만 판정된다 — 부착 · 따라가기 · 정지 · 연장 · 뒤집힌 화면 위치는 **확인되지 않은 채** 끝난다.
- 추천: 기존 프리팹 하나(예: 힐 이펙트 — 이미 상태 이펙트 계약을 지키는 루프 프리팹)를 **한 스킬 칸에만 임시로** 넣어 경로를 확인하고, 테스트 뒤 비운다. 임시 프리팹을 어느 스킬 칸에 넣을지 · 비우는 시점은 테스트 안내 때 메인 세션이 정한다.
- 다른 안: 넣지 않음 — 경로 확인은 VFX 제작 뒤로 미룬다.

## 6. 테스트 절차 초안 `[제안 — 문서 담당 · 메인 세션이 [6] 안내로 옮긴다]`

**🔴 게임 규칙 대조 — 이 조건을 지키지 않으면 볼 수 없다:**
- 한 플레이어(팀)는 한 경기에 **한 종족**이다(`GameRaceContext`가 Blue · Red 종족을 하나씩 든다 — 문서 담당 확인). 스킬은 **자기 스킬 건물**에서만 쓴다.
- 각 스킬은 그 종족으로 플레이하고 그 종족의 스킬 건물을 지어야 한다 — 인간 **FlightFacility**(5번 칸 전술 지령), 정령 **MagicSpirit**(3번 칸 화염의 축복), 초월 **WillowShrine**(4번 숲의 포효 · 5번 숲의 순풍). 건물 · 슬롯 출처: 스킬 규칙 표 · 상위 Plan 1-1 ~ 1-3.
- **AI는 스킬을 쓰지 않는다**(Research 4-3) — 상대 AI가 버프를 거는 장면은 없다. 효과 확인은 내 유닛으로 한다.
- 싱글만으로 네 스킬을 보려면 **최소 3경기**(인간 · 정령 · 초월)가 필요하다. 멀티는 Host와 Client가 다른 종족을 고를 수 있어(EMP 테스트에서 상대 종족이 판마다 달랐다) 2경기로 3종족을 덮을 수 있다 — 예: Host 인간 / Client 초월, 그다음 Host 정령.
