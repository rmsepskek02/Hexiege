# Testcase — 코드 구조 개선 Phase 2

## 이 테스트가 무엇이고 왜 하는가 (자연어 설명)

이번 작업(Phase 2)은 **게임 동작은 전혀 바꾸지 않고 코드 구조만 정리한 작업**입니다.
즉, 화면에서 보이는 동작과 결과는 변경 전과 똑같아야 합니다.

그래서 이 테스트의 목적은 "새 기능이 잘 되는지"가 아니라,
**기존 기능이 바뀐 코드에서도 똑같이 동작하는지**를 확인하는 것입니다.

이번에 손댄 부분은 두 가지입니다.

1. **건물 정보 정리 (생산 건물 판별 / 단계 / 다음 단계)**
   건물을 클릭했을 때 어떤 패널이 뜨는지, 업그레이드 버튼이 보이는지, 철거 시 골드가 얼마나 환불되는지 등이
   변경 전과 동일하게 동작해야 합니다. (TC-01 ~ TC-07)

2. **멀티플레이 시작 시 헥스 타일 설정 정리**
   멀티플레이를 시작했을 때 양쪽(Blue 팀 / Red 팀) 화면에 건물과 타일이 올바른 위치에 표시되어야 합니다. (MULTI-TC-01, MULTI-TC-02)

각 테스트는 사용자가 실제로 게임을 조작해 보고 결과를 직접 기록하는 칸(**결과**)을 비워 두었습니다.

## 테스트 케이스 (TC)

### SINGLE-TC-01: 생산 건물을 클릭하면 생산 패널이 열린다

**전제:**
- 싱글플레이(에디터 단독)로 게임을 시작한 상태
- 맵에 유닛을 생산하는 건물(예: 1단계 훈련소 계열, 또는 임의의 생산 라인 건물)이 하나 이상 배치되어 있음

**동작:**
1. 생산 건물 하나를 클릭한다.

**기댓값:**
- 유닛 생산 패널이 화면에 열린다.
- 액션 패널(철거 등)은 열리지 않는다.

**결과:** (사용자 실기 테스트 후 기록)

### SINGLE-TC-02: 비생산 건물을 클릭하면 생산 패널이 아닌 액션 패널이 열린다

**전제:**

**기댓값:**
- 생산 패널은 열리지 않는다.
- 비생산 건물용 액션 패널(철거 등)이 열린다.

**결과:** (사용자 실기 테스트 후 기록)

### SINGLE-TC-03: 성(Castle)을 클릭하면 어떤 패널도 열리지 않는다

**전제:**
- 싱글플레이로 게임을 시작한 상태

**결과:** (사용자 실기 테스트 후 기록)

### SINGLE-TC-04: 1단계 생산 건물에서 업그레이드 버튼이 표시된다

**전제:**
- 싱글플레이로 게임을 시작한 상태
- 다음 단계가 존재하는 생산 건물(1단계 또는 다음 단계가 남은 2단계 건물)이 배치되어 있음

**동작:**
1. 해당 생산 건물을 클릭하여 생산 패널을 연다.

**기댓값:**
- 생산 패널 안에 업그레이드 버튼이 표시된다.

**결과:** (사용자 실기 테스트 후 기록)

### SINGLE-TC-05: 최고 단계 생산 건물에서 업그레이드 버튼이 표시되지 않는다

**전제:**
- 싱글플레이로 게임을 시작한 상태
- 더 이상 올라갈 단계가 없는 최고 단계 생산 건물(예: 어느 라인의 마지막 단계 건물)이 배치되어 있음

**동작:**
1. 해당 최고 단계 건물을 클릭하여 생산 패널을 연다.

**기댓값:**
- 생산 패널은 열리되, 업그레이드 버튼은 표시되지 않는다.

**결과:** (사용자 실기 테스트 후 기록)

### SINGLE-TC-06: 생산 건물 철거 시 골드 환불이 발생한다 (누적 비용 계산 정상)

**전제:**
- 싱글플레이로 게임을 시작한 상태
- 한 번 이상 업그레이드를 거친 생산 건물(2단계 이상)이 배치되어 있음
- 현재 보유 골드 수치를 미리 확인해 둔다.

**동작:**
1. 해당 생산 건물을 선택한다.
2. 철거를 수행한다.

**기댓값:**
- 건물이 철거되며 골드가 환불된다.
- 환불되는 골드는 그 건물이 거쳐 온 단계들의 누적 비용을 기준으로 계산되며, 변경 전과 동일한 금액이 환불된다.

**결과:** (사용자 실기 테스트 후 기록)

- 최고 단계이므로 업그레이드 버튼은 표시되지 않는다.

**결과:** (사용자 실기 테스트 후 기록)

### MULTI-TC-01: 멀티플레이에서 Blue 팀(Host) 화면에 건물과 타일이 정상 위치에 표시된다

**전제:**
- 한 대는 Host(에디터), 다른 한 대는 Client(빌드)로 멀티플레이를 구성한다.
- Host가 Blue 팀으로 게임에 입장한다.
- 게임이 시작되어 맵이 로드된 상태

**동작:**
1. Host(Blue 팀) 화면을 관찰한다.

**기댓값:**
- 헥스 타일맵이 올바른 방향과 크기로 표시된다.
- 본진 성과 건물, 유닛이 Blue 팀 기준의 정상 위치에 표시된다.
- 변경 전 멀티플레이와 비교해 화면 구성·카메라·렌더링 결과가 동일하다.

**결과:** (사용자 실기 테스트 후 기록 — 에이전트 실기 불가, 사용자 확인 필요)

**전제:**

- Client가 Red 팀으로 게임에 입장한다.
- 게임이 시작되어 맵이 로드된 상태

**동작:**
1. Client(Red 팀) 화면을 관찰한다.

**기댓값:**
- 헥스 타일맵이 올바른 방향과 크기로 표시된다.
