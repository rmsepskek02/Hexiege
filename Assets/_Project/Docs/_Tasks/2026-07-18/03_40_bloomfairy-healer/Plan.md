# Plan — BloomFairy(꽃요정) 힐러 유닛 구현

## 이 작업이 무엇인지 (자연어 설명)

BloomFairy는 **공격을 하지 않는 힐러**입니다. 지금까지 만든 특수 유닛 4종은 전부 "적을 감지 →
공격"하는 구조였는데, BloomFairy는 정반대로 "**부상당한 아군을 감지 → 회복**"합니다.

이 작업의 핵심은 3가지 신규 요소를 만드는 것입니다.
1. **부상 아군 타겟팅** — 기존 전투는 "적만" 찾으므로, "아군 중 가장 많이 다친 대상"을 찾는 탐색을 신설.
2. **힐러 상태머신** — 이동 코루틴에 "부상 아군 발견 → 정지 → 힐 애니 → HoT 부여 → 쿨다운 → 재탐색"
   루프를 추가(공격 루프와 병렬).
3. **시간 지속 효과(HoT) 공용 시스템** — "3초간 총 20HP 회복" 버프를 대상에 붙여 서버가 틱으로 회복.
   이 시스템은 이후 QuakeSpirit·MushroomBomber의 **DoT(지속 피해)** 도 그대로 재사용합니다.

힐의 실제 적용·연출·멀티 동기화(`UnitData.Heal` / `OnEntityHealed` / `NetworkHealthSync` /
`FloatingHpTextSpawner`)는 **TorrentSpirit에서 이미 완성**했으므로 그대로 재사용합니다(규칙 30).

관련 규칙: 특수 공격 시스템 규칙 23~31(`GameSystemRules_Units.md`). 특히 이 작업은
**규칙 28(special-only)·30(힐 서브시스템)·27(OnAttackHit 주입)** 을 직접 사용하고, HoT/DoT
공용 시스템은 **규칙 29의 서버 권위 틱 패턴**(싱글=GameBootstrapper·멀티=NetworkCombatController)을 계승합니다.

## 구현 항목

### (a) 신규: HoT/DoT 시간 지속 효과 공용 시스템 [핵심]

**목적**: "유닛에 붙는 시간 지속 효과"를 서버 권위로 관리. 회복(HoT)·피해(DoT) 모두 처리.
BloomFairy(HoT) + QuakeSpirit·MushroomBomber(DoT) 3유닛 공용.

**배치 레이어**: `Application`(전투 로직과 동일 레이어, 규칙 29의 파도 틱과 대칭).
`UnitCombatUseCase`에 통합하거나 별도 서비스(`TimedEffectService` 등)로 분리 — 구현자 판단.
단, **파도(`ActiveWave`/`TickWaves`)와 동일한 소유·틱 패턴**을 따를 것.

**효과 레코드(대상별)**: 대상 UnitId, 종류(Heal/Damage), 남은 시간, 초당(또는 총량/지속) 적용률,
누적 적용량(반올림/분할 오차 보정용). 대상별로 **동종 효과 1개**만 유지(갱신 규칙).

**틱 적용 방식**:
- 매 틱 `deltaTime`만큼 진행하며 "지금까지 적용됐어야 할 누적량 − 이미 적용한 량"을 이번 틱 적용량으로 계산
  → 분할 오차 없이 **총 20HP 정확히** 도달(피해 DoT도 동일). 마지막 틱에서 잔량 정산.
- Heal → `UnitData.Heal(amount)` + `OnEntityHealed` 발행(규칙 30 인프라 재사용).
- Damage(후속 DoT) → 기존 피해 경로(`ApplyDamageToVictim` 계열) + `OnEntityDamaged`. **BloomFairy 작업
  범위에서는 HoT만 구현**하고, DoT는 동일 구조가 수용 가능함을 설계로 보장(실제 DoT 배선은 해당 유닛 작업 때).

**갱신 규칙(중첩 없음)**: 동일 대상에 동종 효과가 이미 있으면 **남은 시간·총량 리셋**(스택 X). (결정 8)

**대상 종료 처리**: 대상 사망 → 레코드 제거. 풀피 도달(HoT) → 레코드 제거(더 회복할 것 없음). 지속시간 만료 → 제거.

**서버 틱 진입점(규칙 29 계승)**: 싱글 = `GameBootstrapper.Update`(`!IsNetworkMode` 가드),
멀티 = `NetworkCombatController`(IsServer 가드). **이중 틱 금지** — 파도 `TickWaves` 호출 지점 바로 옆에 추가.

### (b) 신규: 부상 아군 탐색 (UnitCombatUseCase)

기존 적 전용 탐색(`FindFirstEnemyInDetectRange` 등, `unit.Team == attacker.Team || !unit.IsAlive → continue`)
의 **팀 필터를 반대로** 한 아군 탐색 메서드 신설. (기존 적 탐색 메서드는 무변경 — 회귀 방지.)

- 조건: `unit.Team == self.Team` **그리고** `unit.IsAlive` **그리고** `unit.Hp < unit.MaxHp`(부상).
- **본인 포함**(결정 3) — 자기 자신도 후보. **아군 유닛만**, 건물 제외(결정 4).
- 사거리: 감지/힐 사거리 4.0(`IEntityPositionProvider` 월드 좌표, 규칙 6과 동일 소스).
- 우선순위: **잃은 체력 비율 `(MaxHp - Hp) / MaxHp` 최대**(결정 1). 동률이면 **거리 최소**(결정 2).
- 반환: 대상 UnitId(없으면 없음 표현). "부상 아군 존재 여부" 헬퍼도 함께(상태머신 진입 판정용).

### (c) 신규: 힐러 상태머신 분기 (UnitView.MoveAlongPathV3)

이동 코루틴에서 매 스텝 전투 진입을 판정하는 부분(현재 `HasEnemyInDetectRange`)에 **힐러 분기**를 병렬 추가.

- **힐러 여부 식별**: BloomFairy를 "힐러"로 인식하는 수단이 필요.
  - 방식 A(권장): `UnitStatsConfig`/데이터에 **역할 플래그**(예: `IsHealer` 또는 `SupportRole`)를 두어
    상태머신이 데이터로 분기. UnitType 하드코딩보다 확장성↑(향후 지원 유닛 재사용). — **채택 권장**.
  - 방식 B: 상태머신에서 `UnitType == BloomFairy` 직접 조건. 단순하나 확장 시 조건 누적.
  - → **방식 A 채택 권장**하되 최종은 game-programmer가 기존 데이터 구조와의 정합성 보고 결정, 사용자 확인.
- **힐 루프**(공격 루프와 병렬, 결정 5·6):
  1. 이동 중 사거리 내 부상 아군 있으면 → 정지.
  2. 대상 향해 회전 → **힐 애니메이션** 재생(시전 중 이동 없음, 공격 유닛의 정지-시전과 동일 UX).
  3. **힐 타격 타이밍(`HitFrameTimes[0]`)에 대상에 HoT 부여**((a) 시스템 호출). ⚠️ **구현 확정(2026-07-18)**: 회복 발동은 애니 이벤트(`OnAttackHit`)가 아니라 상태머신의 `HitFrameTimes` 타이머로 구동한다. 이유 — 이 코드베이스의 `OnAttackHit()`는 데미지를 발동하지 않고 **VFX/SFX·피격 연출만** 담당하며, 실제 데미지도 서버 권위로 `HitFrameTimes` 타이밍에 적용된다(동일 관례). `OnAttackHit`을 힐 발동에 쓰면 ① 데미지와 메커니즘이 갈리고 ② 클립에 이벤트 미주입 시 회복이 영영 발동 안 되는 취약점이 생긴다. 타이밍 값은 동일(`HitFrameTimes[0]`=1.0s)이며 `OnAttackHit`은 힐 연출용으로만 남긴다.
  4. 쿨다운 3s 대기.
  5. 재탐색((b) 호출): 부상 아군 있으면 반복, 없으면 이동 코루틴 복귀(A* 재개).
- 대상이 시전 도중 사거리 이탈/사망 → 다음 재탐색에서 자연 배제(결정 9).

### (d) special-only + 적 공격 흐름과 분리 (규칙 28 관계)

BloomFairy는 **적 주 타깃이 없어** `ExecuteAttack`/`ISpecialAttackBehavior`(적 공격 흐름)에 얹지 않는다.
TorrentSpirit(special-only이나 적을 때림, 규칙 28)과 달리 **힐러 전용 경로**((b)+(c)+(a))로 처리.
특수 공격 레지스트리에는 등록하지 않으며, 상태머신이 힐러임을 알고 힐 루프를 타는 구조(규칙 28의 "특수 로직이
공격 전체를 담당" 취지를 힐 방향으로 확장).

## 위험 요소 / 주의

1. **분할 오차** — "3초 20HP"를 프레임 틱으로 나누면 반올림 누적 오차 발생 가능. → "누적 적용량 diff" 방식으로
   총량 정확히 도달(마지막 틱 정산). DoT도 동일.
2. **이중 틱** — 규칙 29처럼 싱글/멀티 가드로 한 번만 틱. 멀티에서 클라가 틱 돌리면 회복 이중 적용.
3. **힐러 식별 하드코딩** — UnitType 직접 조건은 확장 시 부채. 방식 A(역할 플래그) 권장하되 데이터 구조 정합성 확인.
4. **OnAttackHit 중복** — 힐 클립에 이벤트 2개면 한 시전에 HoT 2번 부여. 규칙 27대로 1개만.
5. **갱신 vs 신규 판별** — 같은 대상 재힐이 스택되지 않게 대상별 동종 효과 1레코드 보장.
6. **본인 포함 타겟팅** — 자가 회복 허용이라 후보에서 self 제외하지 않도록 주의(적 탐색과 반대).
7. **에셋 생성 ≠ 씬 배선**(규칙 25 교훈) — 스탯/플래그/클립 이벤트 입력 후 **런타임 반영까지** 확인.

## 완료 결과 / QA 반영 (2026-07-18)

구현 완료 후 QA에서 3건을 확인했고, 아래와 같이 처리했다(히스토리 보존을 위해 본문은 그대로 두고 하단에 append).

### 이슈1 — 힐 주기 4.0초 (설계 확정, 코드 무변경)

힐 1회 주기 = **발동 준비 1.0s(`HitFrameTimes[0]`) + 발동 후 쿨다운 3.0s = 4.0s**. 구현 항목 (c)6·(e)의 쿨다운 3s는 **힐이 발동된 뒤부터** 카운트되므로 총 주기가 4.0s다.

⚠️ **쿨다운 예외(중요)**: 다른 모든 유닛은 `AttackCooldown`이 발동 준비를 포함한 전체 주기(공격 시작 시 쿨다운 시작, `TryAttack` 패턴)지만, **BloomFairy만 쿨다운이 발동 준비를 미포함**한다. 이는 의도된 설계이며 버그가 아니다 — **코드 무변경, 문서만 반영**(StatsReference BloomFairy 행 + GameSystemRules_Units 규칙 36 신설). 다른 유닛과 같게 되돌리지 말 것.

### 이슈2 — 힐러 최전선 유휴 (수정 완료)

힐러가 A* 경로 끝(적 진영 앞)에 도달한 뒤 부상 아군을 감시하지 않고 서 있던 문제 → 경로 종료 후에도 도는 **유휴 감시 루프 `HealerIdleWatchV3`** 추가로 해결. 사거리 내 부상 아군이 생기면 즉시 힐 루프에 진입한다(규칙 35 신설).

### 이슈3 — 캐스트 중 풀피 대상 (수정 완료)

힐 캐스트(시전) 도중 대상이 다른 힐·자연회복으로 풀피가 되어도 계속 시전하던 문제 → **`CastHeal`에 `Hp < MaxHp` 가드 추가**로, 발동 시점에 대상이 풀피면 힐을 부여하지 않도록 수정.
