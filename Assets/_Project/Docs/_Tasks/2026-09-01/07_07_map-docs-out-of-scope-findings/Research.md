## 0. 이 작업이 무엇이고 왜 하는지 (자연어 설명 — CLAUDE.md 규칙 13)

지난 회차에 무작위 맵 관련 문서들을 처음부터 끝까지 읽어 내려가면서 어긋난 곳을 고쳤습니다.
그때 **고칠 범위 밖이라 손대지 않고 「나중에 볼 것」으로 적어만 둔 항목이 5건** 남았습니다.
이 문서는 그 5건이 **지금 실제로 어떤 상태인지 눈으로 확인한 기록**입니다.

5건은 성격이 두 갈래로 갈립니다.

- **말투·표기 문제 3건** — 게임이 어떻게 동작하는지는 그대로이고, 문서에 적힌 **이름과 설명이 부정확하거나 좁게 적혀 있는 것**입니다.
  읽는 사람이 그 낱말로 코드를 찾으면 아무것도 안 나오거나, 요약만 읽고 「이건 안 해도 되는구나」로 잘못 이해하게 됩니다.
- **게임 동작이 달라지는 문제 2건** — 문서끼리 **서로 다른 것을 지시하고 있어**, 어느 쪽을 따라 만드느냐에 따라
  실제 게임이 다르게 동작합니다. 하나는 컴퓨터 상대(AI)가 건물 지을 자리를 고르는 기준이고,
  다른 하나는 맵 준비가 실패했을 때 뜨는 창을 배경을 눌러 닫을 수 있는지 여부입니다.
  두 번째는 잘못 만들면 **선택지가 하나도 없는 화면에 플레이어가 갇힐 수 있습니다.**

이 문서에서는 **아무것도 고치지 않습니다.** 어디에 무엇이 어떻게 적혀 있는지 확인하고,
왜 문제인지와 그 근거를 정리하는 것까지입니다. 실제 문서 교정은 같은 폴더의 `Plan.md`를
사용자가 승인한 뒤에 진행합니다(WORKFLOW [4]).

### ④ 🔴 `GameSystemRules/GameSystemRules_AI.md` 규칙 26 — 사양 변경

**위치**: `Assets/_Project/Docs/GameSystemRules/GameSystemRules_AI.md` **243~251행**
(243행 규칙 제목 「**규칙 26. BFS 기반 배치 타일 선택**」, 소속 섹션 = **6. 건물 배치 로직**)

**현행 (인용 — 확인용, 244~249행)**

```
AI가 건물을 배치할 타일은 다음 방식으로 결정한다.

1. Red 성채를 시작점으로 BFS 탐색
2. Red 팀 소유 + `IsWalkable=true` 타일 중 가장 가까운 타일을 후보로 선택
3. **후보 타일이 기존 Red 생산 건물의 인접 6타일에 해당하면 건너뜀**
4. 조건을 만족하는 첫 번째 타일에 배치
```

#### 대면 결함 — `TechnicalDesignDocument.md` 판정식 절(525~549행)

```text
IsWalkable = TileKind != Blocked      (528~530행)
          && MineKind == None
          && !HasBuilding

일반 건설  = TileKind == Normal        (536~539행)
          && MineKind == None
          && !HasBuilding
          && 기존 소유권 조건
```

- 차이는 **`!= Blocked` 대 `== Normal`**, 즉 **건설 불가 타일** 하나입니다.
  같은 문서 **549행**이 `TileKind.NoBuild는 이동·점령은 허용하고 일반 건설만 막는다(MiningPost는 예외)` 라고 못박습니다.
  즉 이동 판정은 **통과**시키고 일반 건설은 **막는** 타일이 존재합니다.
- 같은 문서 「기존 코드 전환 요구」(582~588행) **588행**이 이미
  `이동, 스폰, 경로탐색은 계산된 IsWalkable을 읽고, 건설·점령은 위의 전용 조건을 사용한다` 고 정합니다.
  **규칙 26 은 건물 지을 자리를 고르는 데 이동용 조건을 쓰므로 이 방침에 어긋납니다.**

#### 언제 드러나는가

- 현재 고정 맵에는 건설 불가 타일이 없어 드러나지 않습니다.
- **무작위 맵에서는 드러납니다.** 다만 **⚠️ 지시서와 다른 점 (실측)**: 지시서는 「무작위 맵은 **유형마다** 건설 불가 구역을 둔다」고 적었으나,
  `GameSystemRules_RandomMap.md` 3장 ⑤ 실측 결과 **맵 유형 5종 중 3종만** 건설 불가 구역을 가집니다.

  | 맵 유형(규칙) | 3장 ⑤ 건설 불가 구역 | 행 |
  |---|---|---|

**요약이 규칙을 좁히는 자리**가 있을 수 있습니다. 이번 범위는 맵 절 2건으로 닫혀 있어 **다른 절은 대조하지 않았습니다.**
같은 방식의 전수 점검이 필요하면 별도 task 로 제안합니다.

**(마) `GameSystemRules_UI.md` 규칙 8 「현재 예시」 목록(169~171행)에 맵 준비 실패 UI 가 없다**
⑤ 로 M-2 가 모달로 확정되면 **모달 예시에 추가할 수 있는 자리**가 생깁니다.
또한 규칙 M-1(224행)이 이 UI 를 `맵 준비 실패 팝업`이라는 일반 서술로 부르는데,

**둘 다 ⑤ 의 확정 방향(M-2 한 줄)에 포함되지 않으므로 고치지 않고 `Plan.md`에서 제안만 합니다.**
