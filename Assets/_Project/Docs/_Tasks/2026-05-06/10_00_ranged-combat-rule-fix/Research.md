## 이 작업이 무엇인지

BUG-005/006 수정이 GameSystemRules.md의 원거리 유닛 규칙(규칙 13, 15)을 위반한 채로 구현되었다.
테스트 결과 3가지 시각적 문제가 발견되었으며, 모두 규칙 위반에서 비롯된 동일한 원인을 공유한다.
이 문서는 위반 원인을 분석하고 올바른 수정 방향을 도출한다.

---

## 발견된 증상 3가지 (런타임 테스트 후)

1. **이동경로가 타일을 벗어남**: 피스톨러(원거리)가 이동 중 전투에 진입하면 타일 위가 아닌 허공에 물리적으로 고정된다.
2. **피스톨러가 뭉침**: 여러 피스톨러가 같은 타일 위치에 몰려 겹쳐 보인다.
3. **불꽃정령이 접근 즉시 사망**: 뭉쳐있는 피스톨러들의 동시 사격을 받아 불꽃정령이 공격 범위에 진입하자마자 죽는다. (증상 2의 결과)

## 근본 원인 — 규칙 위반

### 어떤 규칙을 위반했는가

**GameSystemRules.md 규칙 13:**
> "원거리 유닛: 공격 사거리 내에 적이 진입하면 현재 위치(이동 슬롯)에서 멈추고 즉시 공격한다.
> **별도 공격 슬롯 이동 없이 이동 슬롯 위치가 그대로 공격 위치가 된다.**"

**GameSystemRules.md 규칙 15:**
> "원거리 유닛: **이동 슬롯을 유지한 채** 공격했으므로 전투 종료 시 별도 처리 없이
> 현재 이동 슬롯 위치에서 A*를 바로 재개한다."

두 규칙 모두 원거리 유닛이 이동 슬롯을 **유지**해야 함을 명시한다.

### 어떻게 위반했는가

BUG-005/006 수정에서 원거리 전투 진입 시 다음 코드를 추가했다:

```csharp
ReleaseV2MoveSlotIfClaimed();  // ← 이동 슬롯 해제
ReleaseOccupancyIfPending();    // ← 점유 해제
_unitData.ClaimedTile = null;
```

이것은 **근접 유닛(규칙 11)의 패턴을 원거리 유닛에 잘못 적용**한 것이다.

| 유닛 타입 | 적용 규칙 | 올바른 슬롯 처리 |
|---------|---------|--------------|
| 근접 (Melee) | 규칙 11: "이동 슬롯을 해제하고 공격 슬롯을 할당한다" | 이동 슬롯 해제 → 공격 슬롯 획득 → 적에게 직진 |
| 원거리 (Ranged) | 규칙 13: "이동 슬롯 위치가 그대로 공격 위치가 된다" | **이동 슬롯 유지** → 그 자리에서 공격 |

### 왜 이 규칙을 안 봤는가

BUG-005/006 Research.md와 Plan.md 작성 시 `GameSystemRules.md`를 참조하지 않았다.
근접 유닛 분기에서 슬롯 해제 패턴을 발견하고, 원거리 분기에도 동일하게 적용하면 된다고 판단했다.
두 유닛 타입의 슬롯 처리 규칙이 반대라는 사실을 코드 분석 과정에서 놓쳤다.

## 규칙 위반으로 인한 연쇄 문제

### 증상 1 원인 (타일 벗어남)

```
TILE_MOVE from=(5,6) to=(5,7)
SLOT_CLAIM tile=(5,7)               ← 슬롯 클레임됨 (toPos = 슬롯 위치)
[이동 중 Lerp 진행]
ENEMY_DETECTED
PRE_COMBAT_SLOT_RELEASE tile=(5,7)  ← 슬롯 해제 (규칙 위반)
STATIONARY_COMBAT_START currentTile=(5,6)  ← 물리 위치: (5,6)과 (5,7) 사이 허공
```

슬롯을 해제한 뒤 `transform.position` 스냅 없이 전투에 진입 → Lerp 도중 위치(타일 사이 허공)에 물리적으로 고정.

### 증상 2 원인 (피스톨러 뭉침)

슬롯과 점유가 해제되면 타일이 빈 것으로 인식된다. 뒤따르는 피스톨러들이 이 타일로 이동해 모두 같은 위치에 집결한다.

로그 근거:
```
UnitID 10, 12, 14, 16, 18, 20 → 모두 STATIONARY_COMBAT_START currentTile=(5, 6) 동시 기록
```

### 증상 3 원인 (불꽃정령 즉사)

증상 2의 결과다. 6명의 피스톨러가 한 자리에서 동시 사격하므로, 불꽃정령이 사거리에 들어오면 즉시 사망한다. 불꽃정령 자체의 이동/접근 로직에는 문제가 없다. (로그 상 MELEE_PURSUIT_START, ATTACK_SLOT_CLAIM 정상 발생 확인)

## 올바른 동작 (규칙 기반)

원거리 유닛이 Lerp 이동 중 적을 감지하면:

1. 이미 클레임된 슬롯 위치(`toPos`)로 `transform.position`을 스냅한다.
   → 타일 위에 물리적으로 위치함 (허공 고정 없음)
2. 이동 슬롯은 그대로 유지한다 (규칙 13).
   → 슬롯 해제로 인한 뭉침 없음
3. 그 자리에서 전투한다 (규칙 13).
4. 전투 종료 후 이 슬롯 위치에서 A*를 재개한다 (규칙 15).

이 방식이면 BUG-005/006의 원래 문제(유령 점유)도 함께 해결된다:
- 유닛이 물리적으로 슬롯 위치에 있으므로 슬롯과 실제 위치가 일치 → 유령 점유 없음
