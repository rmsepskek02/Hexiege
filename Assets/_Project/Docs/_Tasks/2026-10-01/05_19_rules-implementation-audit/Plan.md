## 이 문서가 무엇이고 왜 지금 쓰는가 (자연어 설명)

이 프로젝트에서는 「코드에 적힌 설명글(주석)」이 **실제와 다르게 적혀 있는** 일이 잦았습니다. 읽는 사람은 설명글을 믿고 판단하므로,
거짓 설명글은 **프로그램이 멀쩡히 돌아가는 동안 조용히 다음 사람을 틀리게 만듭니다.**
사용자가 이번에 *"주석도 검사하고 거짓주석 다 정리해"* 라고 지시했고, 그래서 **화면(UI)과 무작위 맵 쪽 파일 89개의 설명글을 처음부터 끝까지 읽어**
거짓인 것 **162곳**을 찾아 고쳤습니다. 고친 것은 설명글뿐이고 **프로그램이 하는 일은 한 줄도 바꾸지 않았습니다.**

이 문서는 세 가지를 적습니다. ① **끝난 일** — 무엇을 어디까지 했는지. ② **아직 안 한 일** — 같은 종류의 거짓이 아직 남은 곳과, 판정조차 못 한 곳. ③ **사용자가 정해 줘야 앞으로 갈 수 있는 일** — 코드·씬·기획·규칙 문서에 관한 결정들.
조사 결과의 상세(왜 그렇게 판정했는지, 새로 드러난 사실 다섯 가지)는 같은 폴더의 **`Research.md` §12-6-2 ~ §12-6-9** 에 있고, 이 문서는 거기서 **할 일만** 뽑아 적습니다.

### 🔴 먼저 밝혀 둘 것 — 이 문서는 작업이 끝난 뒤에 쓰였다

세션을 시작할 때 사용자는 **「task 문서를 작성한다」를 선택**했습니다(`CLAUDE.md` 작업 시작 전 체크리스트 [2] · `WORKFLOW.md` [2]). 그런데 호출 세션(메인 세션)은 **`Plan.md` 없이 `.cs` 65개 파일을 고쳤습니다.** 이 폴더에는 그동안 `Research.md` 하나뿐이었습니다.
그래서 이 `Plan.md` 는 **`WORKFLOW.md` [4] 가 정한 「계획 → 사용자 승인 → 구현」 순서를 따르지 않았다.** 아래 「끝난 일」은 **계획이 아니라 사후 기록**이고, 「승인 대기」부터가 정상 순서(계획 → 승인)를 따르는 부분이다.
🔴 **이 사실을 숨기지 않고 적는다.** (이 서술의 근거는 호출 세션의 전달이다 — 이 문서가 세션 기록을 직접 확인한 것은 아니다.)

### 🔴 기존 로직 제거 — 0건 (`WORKFLOW.md` [4] 가 요구하는 최상단 기술)

이번에 **제거한 것은 거짓 주석 문장뿐**이다. 동작 코드에서 제거한 것은 **0건**이다 — 주석과 문자열 리터럴을 걷어낸 코드 본문의 대조에서 **변경 0건**(전달값 · `Research.md` §12-6-2-6). 그러므로 「비활성화 우선」 원칙이 적용될 대상이 없었다.

### 근거 규칙 (`WORKFLOW.md` [4] — 수정 항목마다 어느 규칙에 근거하는지)

- **이번 작업의 근거는 `GameSystemRules` 의 규칙이 아니라 사용자 지시다.** 주석을 검사하라는 규칙 문서는 없다. 이 사실이 「주석을 대상으로 한 검사가 이번이 처음」이었던 이유 중 하나다.
- 규칙 번호가 필요한 곳은 아래 「승인 대기」 표의 **근거 규칙 칸**에 적었다. `GameSystemRules.md` 인덱스를 먼저 읽고 해당 파일을 확인했다. 🔴 **인계가 규칙 번호를 주지 않은 항목은 번호를 지어내지 않고 「미특정」이라 적었다**(`CLAUDE.md` 규칙 10).
- `GameSystemRules_UI.md` 는 절마다 번호가 1부터 다시 시작하므로 **절 이름을 함께 적었다.**

**방법:** 숫자로 범위를 좁히지 않는다. **거짓 「주장」을 먼저 정하고 그 주장을 파일 전수로 찾는다**(원인이 「범위를 숫자로 좁혀 지시한 것」이었다). 건물 액션 패널의 한 자리는 「예:」로 완충돼 있어 **먼저 판정**한다.
