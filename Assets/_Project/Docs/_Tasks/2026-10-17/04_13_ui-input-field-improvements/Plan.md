# 인풋필드 공통 개선 계획

입력하다가 다른 곳을 눌러도 기존 내용을 원하는 위치부터 이어서 수정할 수 있게 만드는 작업이다. 이번에 합의한 개선은 구현과 안내한 사용자 테스트까지 전체 수용 완료다. Android 총 9개 필드 가림/복원과 삼성 키보드 동작, Unity Editor Play/Game 창의 로그인/회원가입 Tab・Shift+Tab 이동을 확인했다. 정확한 APK/빌드 해시는 미제공이며 PC standalone 실기로 확대하지 않는다. 최종 완료 범위는 Research 23절 및 아래 19절을 따르며 중복 테스트를 요청하지 않는다.

> **기존 로직 제거 경계:** 기존 버튼의 무조건 활성화·닉네임 값 변경 직접 구독·방 참가 직접 람다의 대체 지점은 공통 상태·동일 명령 경로와 중복되어 비활성화 주석으로 보존했다. 작성 당시에는 실기 확인 전 삭제를 완료 처리하지 않는 경계였으며, 이후 사용자 테스트는 19절에서 수용 완료됐다. 주석 최종 삭제・코드 정리는 이번 문서 승인과 별도여서 실행하지 않았다. 기존 인증 검증·닉네임 검증·인증 취소·방 참가 계약은 유지했다.

- 작성일: 2026-10-17 (KST)
- 브랜치: `codex/ui-improvements` (메인 세션 생성·전환 인계)
- 근거 조사: [Research.md](Research.md)
- 승인 상태: 최초 구현과 후속 재작업 당시의 Android 일부 정상 보고를 거쳐, 현재는 합의한 구현과 안내한 테스트 전체를 사용자 수용했다. 최신 문서 갱신 승인에 따라 기존 두 문서만 동기화하며 상시 문서・메모리・코드 정리는 이번 승인 범위에 포함하지 않는다. 최종 수용은 19절을 따른다.
- 최초 적용 결과: 공통 `Assets/_Project/Scripts/Presentation/UI/InputFormController.cs`와 meta 추가, 기존 7개 C# 수정. 기존 6개 View 초기화·Bind에서 입력 참조 9개를 런타임 연결했다. 최초 변경에서는 씬·프리팹·패키지 변경과 추가 Inspector 작업이 없었다. 정확한 최초 9개 소스·meta 및 Task 2개 목록은 [Research.md 8절](Research.md#8-최종-구현검사-인계)에 있다. 후속 3개 변경 파일은 Research 10절에서 별도로 기록한다.

## 1. 적용 범위와 동작 기준

## 2. 구현 순서와 의존 관계

### 단계 A. 커서 문제와 적용 지점 확정

game-programmer가 9개 씬 설정과 실제 View 초기화·전환을 다시 확인한다. Research에 기록한 TMP 자동 전체 선택 분기와 값 대입 경로를 구분하여, 실제 값 초기화와 전체 선택 덮어쓰기를 혼동하지 않는다. 설치 패키지를 직접 수정하지 않고 프로젝트 쪽에서 기존 TMP 편집 기능을 보존하는 접근을 제안한다.

단계 B의 전제는 모든 필드의 공통 정책 적용 지점이 확인되는 것이다. 자동 전체 선택을 끄는 방식이 우선 검토 대상이지만 `m_ResetOnDeActivation`까지 무조건 함께 변경한다고 확정하지 않는다. 코드 기본값 변경으로 기존 씬 직렬화 값을 교정했다고 간주하지 않는다.

### 단계 B. 공통 편집·필드 이동 연결

공통 편집 정책을 9개 필드에 적용하고, 각 화면의 명시적 입력 순서·마지막 실행 연결을 마련한다. 숨겨진 화면·비활성 필드로 이동하거나 제출하지 않게 한다. 값 변경, 제출, 필드 이동 구독의 등록·해제 책임을 정하고 재바인딩으로 중복 등록되지 않도록 한다.

Enter·소프트 키보드 완료·Tab 이동은 한글 조합과 구분한다. 편집 종료 이벤트만으로 제출을 실행하지 않는다. 다른 곳을 클릭해 편집이 끝나는 상황이 요청 실행으로 이어져서는 안 된다. 적용된 `InputFormController.cs`는 New Input System 조합 이벤트 프레임과 다음 프레임을 보호하고 TMP submit 다음 프레임에 필드 이동·기존 버튼 실행을 처리한다. 실제 기기 이벤트·편집 결과는 미확인이다.

### 단계 C. 기존 화면 실행·검증과 통합

각 View의 기존 버튼 실행 경로를 보존하면서 완료 입력도 같은 검증·진행 상태를 통과시킨다. 이미 닉네임 2개 화면에 있는 실시간 검증을 재사용하고, 요청 후 버튼을 단순히 항상 켜지 않도록 현재 입력값·가시성·요청 상태를 함께 반영한다.

이메일은 기존 앞뒤 공백 정리 기준을 유지하고 비밀번호 원문은 바꾸지 않는다. 닉네임은 기존 Application 검증을 유지하되 조합 중 오류 시점만 다룬다. 방 코드의 문자·길이·대소문자 기준은 실제 Lobby 참가 계약을 확인한 뒤 기존 동작에 맞춘다. 서버 계정 존재·비밀번호 불일치를 임의의 특정 필드 오류로 분해하지 않는다.

### 단계 D. 화면 종료·요청 생명주기 정리

실제 숨김·뒤로가기·팝업 닫기·씬 이동 경계와 입력 정리를 연결한다. CanvasGroup 숨김에서도 처리되도록 하고, 같은 화면에서 잠깐 포커스를 옮기는 경우와 구분한다. 로그인·가입 화면 종료 시 비밀번호를 비우며, 최초 닉네임 새 화면 준비와 닉네임 변경 팝업의 현재 닉네임 채움 동작은 보존한다.

명시적 열기·닫기를 `LoginRootView.HideGroup/ShowGroup`, 팝업 `Show/Hide`, `CustomJoinView.SetVisible/Unbind`에 연결했다. busy·화면 Session 검사, 로그인 요청 중 Android 뒤로가기 차단, 비밀번호 Close 삭제, 재설정 지연 복귀 취소를 적용했다. 소스 적용과 기기 동작 확인을 구분한다.

이전 화면에서 시작한 비동기 요청의 완료가 숨겨진 화면의 포커스·버튼을 되살리지 않는지 검토한다. 비밀번호 재설정의 기존 지연 복귀는 화면 이동과의 충돌 여부를 확인한다. 인증 취소·계정 삭제·세션 유지 정책 변경으로 확장하지 않는다.

### 단계 E. 메인 검토·사용자 인계

game-programmer 결과를 메인이 9개 목록·동작 기준·보존 계약과 대조했다. 최종 소스·meta 9개 해시가 인계와 일치하고, 최종 Runtime 컴파일 exit 0·errors 0·warnings 23 및 신규 helper의 컴파일 포함·별도 DLL 출력을 확인했다. 추가 Inspector 작업은 없다. Unity·기기 동작과 사용자 수용은 별도 미확인으로 인계한다.

이번 승인으로 Unity 실행·빌드·QA·Testcase 작성까지 진행하지 않는다. 사용자 명시적 지시 없는 TC·QA 제안도 하지 않는다. 사용자 테스트 완료 후 상시 문서·메모리 반영은 별도 승인 경계를 따른다.

## 4. 후속 제외 항목과 미확정

- 비밀번호 보기 버튼과 전면 레이아웃·스타일 개편은 별도 후속이다. 키보드 가림 대응·자동 스크롤은 최초 제외 항목이었으나 최신 사용자 승인으로 아래 7절의 이번 확장 범위에 포함됐다.
- 계정 연동 입력란 배선 복구·새 UI 제작, 구형 LobbyUI 삭제·리팩토링은 제외한다.
- 기기별 커서·IME·소프트 키보드 이벤트 순서는 정적 소스로 정상 판정하지 않는다.
- 최초 소스에 공통 처리·ColorTint 선택/필드 오류·조합 종료 후 닉네임 안내를 적용했다. 이후 Android 일부 정상 수용은 Research 9절, 후속 수정 결과는 10절을 따른다. 사용자 합의 동작을 기존 규칙의 확정 조항으로 꾸며 기록하지 않는다.
- 상시 문서·메모리 갱신, 커밋·푸시 등 Git 변경은 이번 동기화 범위 밖이다.

- 최초 문서 생성은 이 폴더의 Research/Plan 두 문서였고, 이번에는 기존 두 문서에 Android 사용자 보고・후속 구현 및 검사 인계를 동기화했다. 문서 담당자는 새 문서·Testcase·meta를 생성하지 않았다. 최초 구현 담당자의 helper·meta 추가와 구분한다.

## 6. Android 결과에 따른 재작업 범위

사용자 보고에 따라 승인된 재작업을 진행하고 2026-10-18 소스 적용 및 검사 결과를 반영했다. 정상 보고된 전체 9개 이어쓰기・한글 입력・재진입 시 비밀번호 비우기는 유지하고, 사용자 보류인 항목 2를 기술적 불가능으로 확정하지 않는다. 4・6번 진행 차단의 수정 후 실기 확인은 대기 중이다.

1. **로그인・가입 버튼 복구:** 이메일・비밀번호를 채우고 키보드를 닫아도 비활성 상태였다는 보충 보고를 반영했다. 공통 처리에서 현재 편집 폼만 전역 IME 이벤트를 수용하고 키보드 종료・포커스 이탈・Close에서 잔여 조합 상태를 해제했다. 조합 확정 Enter의 두 프레임 보호는 유지한다. 종료 이벤트 누락 경로를 대체환경에서 재현・교정했지만 실제 Android 이벤트 원인은 확정하지 않았다. 사용자는 비밀번호 한글 여부를 기억하지 못하며 문자 종류와 무관한 입력을 요구했다. 문자 종류 필터는 추가하지 않았고 비밀번호 원문・기존 회원가입 최소 6자・확인 일치는 유지한다.
2. **잘못된 방 코드 실패 복구:** `BattleViewModel.JoinGame`에서 정상 오류 반환과 전파 예외 모두 기존 오류 상태 경로를 거치게 했다. await 뒤 연결 종료・오류 메시지가 있는 실패에만 로딩을 닫고 참가 실패 안내를 표시한다. 성공 시 맵 준비 로딩은 유지하고 `OnNetworkError` 자체 본문은 변경하지 않았다. 정상 반환・예외 실패 복구 및 성공 로딩 유지 검사 통과는 실제 서버・Android 통합 확인과 구분한다.
3. **비밀번호 재설정 입력 기본값:** Login 씬 placeholder fileID `1890503128`의 문구 한 줄을 `이메일 주소를 입력하세요`로 수정했다. 실제 입력값의 빈 문자열은 유지한다.
4. **커서 표시・손가락 위치 편집:** 공통 런타임 연결 9개 필드에 모바일 별도 입력창을 숨기는 설정과 폭 3의 파란 커서를 적용했다. 소프트 키보드는 유지하며 TMP 인플레이스 커서・터치 위치・기존 터치 드래그 경로를 사용한다. 별도 네이티브 커서 손잡이 추가는 없으며 색상・설정 검사만으로 Android 손가락 조작 완료를 판정하지 않는다.

후속 수정은 helper・BattleViewModel・Login 씬의 기존 3개 파일이며 전체 경로・SHA256・임시 검사 근거는 Research 10절이 원본이다. 메인이 3개 해시 일치・최종 컴파일 후 소스 무변경, Runtime errors 0・warnings 23, helper 명시 포함・임시 DLL 출력, 변경 형식 검사 exit 0을 확인했다. 실제 helper와 네트워크 메서드 추출본을 대체 객체에 결합한 회귀 루프 18개 PASS는 Android 실기 재현을 뜻하지 않는다. 문서 담당자도 소스 분기・씬 문구・회귀 로그를 대조했다.

현재는 **후속 구현・정적 검사・대체환경 회귀 확인 / 수정본 Android 수용 대기**다. 기존 인증・root 정책 변경, 키보드 가림・자동 스크롤, 전면 레이아웃 변경은 제외한다. 이번 문서 작업에서는 새 파일・상시 문서・메모리・TC 생성 및 QA테스터 실행・Git 변경을 하지 않았다. Python 정합성 검사 실행 불가와 `_Tasks/` 검사 제외 한계는 5절 그대로 유지하며 이번에는 실행환경 탐색・검사 재시도를 하지 않았다.

## 7. 최신 Android 결과에 따른 확장 작업

6절은 이전 후속 수정 인계 당시의 기록이다. 이후 사용자는 버튼 복구・길이와 일치 검증・로그인 실패 재입력・닉네임 오류 복구・없는 방 코드 실패 처리・전체 9개 커서・재설정 안내를 정상 확인했다. 정확한 수용 범위와 미확인은 [Research 11절](Research.md#11-후속-android-결과와-다음-작업-승인)을 따른다. 새 결과 때문에 기존 정상 항목을 전부 미확인으로 되돌리지 않는다.

### A. 정상 방 코드 참가 실패 원인 조사와 수정

- 전제: 사용자 확인은 같은 빌드・서로 다른 계정이다. 정상 코드도 실패 때와 같은 현상으로 참가하지 못했다는 보고이며 정확한 실패 단계・원인은 미확정이다.
- 참가 요청과 하위 연결・준비 흐름, 오류 상태・로딩 종료 시점을 근거로 분리하여 조사한다. 발견된 원인에 맞춰 최소 범위로 수정하고 성공 시 준비 로딩 유지와 실패 후 재시도를 함께 보존한다.
- 서버 프로토콜・계정 정책・네트워크 전면 리팩토링으로 확대하지 않는다. 예상 변경 파일을 실제 적용 목록으로 보고하지 않으며, 구현 결과 인계 후 이 Task에 확정 파일・근거・한계를 추가한다.

### B. 키보드를 닫지 않아도 버튼 상태 갱신

- 필수값・표시 상태・요청 중 상태에 따른 버튼 준비 판단과, 한글 조합 확정 Enter의 다음/제출 보호를 구분한다. 키보드를 연 상태에서도 필수 입력이 완료되면 활성화되어야 한다.
- 버튼 클릭・완료 입력의 기존 검증 경로, busy 중복 차단, 실패 후 재입력, 숨김 폼 제출 차단을 유지한다. 비밀번호 문자 종류 필터나 새 조합 정책을 추가하지 않는다.
- 착수 소스의 `CanSubmit`에 IME 조합 조건이 함께 들어 있는 것은 Research 11절의 직접 소스 근거다. 구현 담당자의 준비 상태 분리 방향은 진행 중이며 완료・기기 해결로 기록하지 않는다.

### C. 전체 입력란의 키보드 가림 대응

- 대상은 기존 9개 입력란이다. 선택한 입력란이 키보드 위의 실제 가용 영역에서 보이도록 적합한 부모를 이동하고, 필드 전환 시 다시 계산하며 키보드 종료・화면 닫기 때 원래 배치로 복원하는 방향이다.
- `GameSystemRules_UI.md` 「공통 UI 규칙」 규칙 1~4의 반응형・앵커・Safe Area와 규칙 5의 표시/숨김 책임을 유지한다. 기존 규칙에 키보드 가림 동작이 이미 명시됐다고 해석하지 않으며, 직접 요구 출처는 이번 사용자 승인이다.
- 구현 담당자는 `MobileKeyboardAvoidance.cs`와 meta, 기존 helper 연결을 예정하고 키보드 영역 및 Android 가시 영역의 조건부 측정을 검토 중이다. 플러그인・Manifest 변경 없이 기존 Canvas 좌표와 Safe Area를 고려하는 방향이며, 실제 구현 파일・방법은 인계 후 확정한다.
- 비밀번호 보기 버튼・상시 레이아웃 전면 개편은 제외한다. 이번 가림 대응을 과거의 제외 범위로 계속 분류하지 않는다.

### D. 인계와 다음 사용자 확인

이번 확장 소스・검사 인계 전까지 이전 컴파일・대체환경 PASS를 새 수정본 PASS로 재사용하지 않는다. 메인은 실제 변경 파일과 검사 범위・한계를 대조하고, Android에서 정상 방 참가・키보드를 연 채 버튼 활성화・필드별 가림과 배치 복원을 우선 확인하도록 안내한다.

사용자가 함께 확인하겠다고 한 미확인 항목은 그때 다시 안내한다. **한글 조합**은 닉네임에 한글을 입력하고 중간 글자를 수정해 깨짐・중복・누락이 없는지와 확정 Enter만으로 저장되지 않는지, **화면 닫기**는 입력 중 뒤로가기로 이전 화면에 돌아갈 때 키보드・커서가 사라지는지를 쉬운 순서로 설명한다. 기존 비밀번호 빈 값 수용은 유지하며 불필요한 전체 중복 테스트를 요구하지 않는다. Tab・Shift+Tab의 기존 Android 보류도 유지한다.

현재 상태는 **확장 범위 승인・구현 진행 중 / 확장 소스・새 검사・기기 수용 미확인**이다. 이 문서 수정은 기존 Research/Plan 두 파일만 대상으로 하며 상시 문서・메모리・Testcase・QA・Git 변경・Unity 실행・빌드를 추가하지 않는다. Python alias 실행 실패와 `_Tasks/` 검사 제외 한계는 5절에 기록한 그대로이며 실행환경 탐색은 하지 않았다.

## 8. 확장 구현 인계와 남은 작업

7절은 확장 착수 당시 기록이다. 현재는 **키보드 UI 소스 구현・정적/대체환경 검사 확인 / Android 수정본 확인 대기 / 정상 방 참가 미해결・참가 기기 로그 필요**다.

- 실제 변경은 `MobileKeyboardAvoidance.cs`와 meta 추가, 기존 `InputFormController.cs` 및 6개 입력 View 수정이다. 정확한 9개 경로・manifest・소스 동작은 [Research 12절](Research.md#12-확장-ui-구현검사-인계와-정상-방-참가-미해결)이 원본이다. 이번 확장에서는 씬・Manifest・플러그인・비밀번호 정책을 바꾸지 않았고 Inspector 작업이 없다.
- 버튼 준비 조건과 IME Enter 보호를 분리했다. 요청 직전 Android 마지막 글자 반영은 기존 문자・길이 검증을 우회하지 않으며, 동일 버튼 누름 회차에서만 문자 보존과 이동 고정을 적용한다. 화면・키보드 종료 때 자기 이동량을 원복한다. 실제 측정한 가시 영역을 쓰고 추정 키보드 높이・새 스크롤・화면 축소는 추가하지 않는다.
- 메인과 문서 담당자는 현 9개 SHA256을 manifest와 대조했다. Runtime errors 0/warnings 23, Android 조건 선택 errors 0/warnings 27이며 두 선택에 신규 helper 2개가 포함됐다. Android 선택은 UNITY_ANDROID 포함・UNITY_EDITOR 제외다. 대체환경 34항목 PASS와 이전 조건 복원 시 준비 상태 FAIL을 확인했다. 기하 경계 1000건은 34항목 중 하나다. 실제 JNI・TMP 렌더・Android 손가락・성능・빌드 완료・사용자 수용은 증명하지 않는다.
- 정상 방 코드 참가 원인은 확보한 Editor 로그로 판정할 수 없어 관련 코드를 고치지 않았다. 같은 빌드・다른 계정 조건을 유지하며 참가 Android의 실패 직후 로그가 필요하다. 가능하면 Host 로그도 함께 확보한다. USB 연결 후 `Hexiege > Logs > Save Device Logs`로 저장되는 `_Logs/{날짜}/{시각}_logcat/RuntimeLog_device.txt`를 사용하며 기존 로그 삭제는 필요 없다.

다음 Android 확인은 열린 키보드에서 버튼 활성화・한 번 탭 제출・마지막 한글 보존, 9개 필드 가림・전환・원복을 우선한다. 가용 화면이 작으면 입력란을 우선하므로 모든 버튼・오류 안내의 동시 노출 보장은 아니다. 기존 커서・이어쓰기 수용은 유지하면서 이동 처리의 영향만 확인한다.

사용자가 미확인한 항목도 다시 쉬운 절차로 안내한다. 닉네임에 `가나다`를 쓰고 중간 글자를 수정해 깨짐・중복・누락이 없는지 본다. 글자 확정용 Enter가 있다면 확정만으로 저장되지 않아야 한다. 입력 중 화면 뒤로가기・닫기로 이전 화면에 돌아가면 키보드・커서가 사라지고 배치가 복원돼야 한다. 기기 뒤로가기가 먼저 키보드만 닫은 상태와 화면 종료를 구분한다. 비밀번호 빈 값 정상 수용과 Tab・Shift+Tab 보류는 유지한다.

이번 문서 변경은 기존 Research/Plan뿐이다. 상시 문서・메모리・TC・QA・Git 변경・Unity 실행・빌드를 추가하지 않았고 Python alias 실패의 기존 한계를 유지했다. 정상 방 원인・수정이 미해결이므로 전체 완료로 보고하지 않는다.

## 9. 새 Android 결과에 따른 첫 탭 재작업

8절은 이전 구현 인계 시점의 기록이며 최신 사용자 결과는 Research 13절을 따른다. 키보드를 연 상태의 필수값 준비 전환과 한글 `가나다` 중간 편집은 수용됐다. 정상 방 코드 참가도 이번에 성공했으므로 추가 네트워크 수정・참가 기기 로그 요청은 현재 진행의 필수 조건이 아니다. 이전 실패 원인 자체가 기술적으로 확정된 것은 아니다.

로그인과 화면의 뒤로가기 버튼에서 첫 탭은 키보드만 내리고 두 번째 탭이 동작한다. 따라서 한 번 탭 제출・화면 닫기 목표는 미충족이며, 기존 34개 대체환경 PASS로 실기 실패를 정상 판정하지 않는다. 화면 이동 후 재진입 시 비밀번호 비움・다시 입력 가능은 정상 수용을 유지한다.

구현 담당자가 첫 탭 소비와 제스처 대상・포커스/키보드 전환・TMP 재열기 경로를 조사・수정 중이다. 사용자 추가 요구인 “이미 올라와 있는 키보드는 새로 열지 않기”는 **입력란을 옮길 때**의 상황으로 확인됐다. 필드 전환 중 키보드 유지의 최소 설계는 별도 검토 중이며 적용 완료가 아니다. 실제 수정 범위・새 코드・검사는 최종 인계 뒤 확정한다. 현재 새 완료・검사 결과는 없다.

다음 확인은 첫 탭 로그인・첫 탭 화면 닫기와 이미 열린 키보드 유지 동작을 중심으로 한다. 회원가입 오류 안내는 이전 정상 수용을 유지하고 불필요하게 재확인을 요구하지 않는다. 전체 9개 가림・복원 결과는 아직 미보고이므로 PASS로 기록하지 않는다. 기존 커서・이어쓰기・비밀번호 정리 수용 및 Tab・Shift+Tab 보류를 유지한다. 현재 상태는 **첫 탭 재작업 중 / 새 코드・검사 인계 대기**이며 전체 완료가 아니다.

## 10. 첫 탭 수정 인계와 미적용 요구

9절의 착수 기록 이후 첫 탭 대응 소스와 최종 검사 근거가 인계됐다. 변경은 공통 helper 2개 수정, `InputFormPointerRelay.cs`와 meta 신규 추가의 4개다. 정확한 경로・임시 근거・검증 경계는 [Research 14절](Research.md#14-첫-탭-재작업-최종-소스와-검증-경계)을 따른다. 메인과 문서 담당자는 manifest 4개와 현 소스 SHA256 일치를 확인했다.

- 실제 PointerDown/Up 전달자를 폼 내부 Button들에 연결하고 손을 뗄 때의 raycast 판정까지 이동・복원을 보호한다. 포커스 알림에서 즉시 위치를 바꾸지 않으며 클릭 실행은 기존 Button에 맡긴다. 별도 반복 클릭 fallback은 없다.
- 표시 중 폼의 참조 수에 따라 Android `consumesOutsideTouches=false`를 임시 적용하고 마지막 폼 종료・pause・Destroy 때 읽어둔 이전값을 복원한다. 기본값・실제 기기값은 추정하지 않는다. `closeKeyboardOnOutsideTap`은 설치 IL에서 완전 alias이므로 별도 조작・독립 선행 닫기 방지로 설명하지 않는다.
- 최종 Runtime errors 0/warnings 23, Android 조건 선택 errors 0/warnings 30이며 양쪽 응답 파일에 helper 3개가 포함됐다. Android는 UNITY_EDITOR 제외다. 30개는 기존 27개와 새 소비 설정 obsolete 3개다. 실제 설치 입력 모듈 본문 발췌와 helper/relay의 대역 검사 Green 84・실패 0을 확인했다. RED는 제출 단독 PASS・뒤로가기/포커스 이동 FAIL이며 로그인의 실제 원인 확정은 아니다. 정적 검사와 대역 검사는 JNI・TMP/native・손가락 실기를 보증하지 않는다.

현재 판정은 **첫 탭 소스 수정・정적/대체환경 검사 확인 / Android 수정본 수용 대기**다. 다음에는 키보드를 연 채 로그인 버튼 한 번 탭과 화면 UI 뒤로가기 버튼 한 번 탭, 마지막 한글・배치 복원을 확인한다. 기존 정상 수용은 유지하며 9개 가림 전수 미보고는 그대로 둔다.

**필드 전환 중 키보드 유지는 아직 미적용이다.** 사용자 발생 조건은 입력란을 옮길 때로 확정됐지만 TMP의 native Close/Open을 바꾸는 구조는 이번 첫 탭 수정에 들어가지 않았다. 소비 설정 대응을 이 요구의 완료로 간주하지 않는다. 이 미적용 요구와 실기 확인이 남으므로 전체 완료로 보고하지 않는다. Unity 실행・APK 빌드・native 검증・상시 문서・메모리・TC・QA・Git 변경은 수행하지 않았고 Python 검사기의 기존 한계를 유지한다.

## 11. 잔여 구현을 묶고 사용자 테스트는 한 번에 진행

> 이 절은 통합 구현 착수・최소 설계 검토 당시의 기록이다. 아래 진행 중・미확정 문장은 그 단계의 상태로 보존하며 현재 통합 구현・최종 검사 결과는 12절을 따른다.

사용자 지시에 따라 첫 탭 수정과 필드 전환 시 키보드 유지까지 함께 구현・검토한 뒤 한 번의 사용자 통합 테스트로 인계한다. 첫 탭 수정본만 먼저 확인하도록 중간 빌드・중복 테스트를 요청하지 않는다. 현재 구현 담당자는 실제 TMP 수명주기를 근거로 최소 설계・구현 가능성을 검토 중이며, 새 소스・수치・manifest는 최종 인계 뒤 확정한다.

통합 테스트 안내는 남은 첫 탭 제출・화면 닫기, 입력란 전환의 키보드 유지, 마지막 글자・가림과 배치 복원을 한 흐름에 묶는다. 이전 정상 수용을 보존하고 이미 확인한 비밀번호 오류・닉네임 복구 등 유사 항목을 불필요하게 반복하지 않는다. 아직 미보고인 9개 가림을 PASS로 기록하지 않는다. 정상 방 참가의 추가 로그 수집은 현재 필수 후속이 아니다.

기존 Research/Plan 두 문서의 승인된 연속 작업으로 진행하며 새 문서 질문을 하지 않는다. 상시 문서・메모리・TC・QA・Git 변경・새 문서 생성은 하지 않는다. 현재는 **잔여 구현 검토・진행 중 / 통합 소스・검사 인계 전 / 사용자 통합 확인 대기**이며 전체 완료가 아니다.

### 필드 전환 유지의 최소 구현 방향

설치 GameActivity 원본의 필드 전환 Hide→Show 문제 주석과 Show/Hide 구현을 확인한 메인・구현 담당자 인계를 근거로 진행한다. TMP subclass와 meta를 추가하고 기존 9개 씬 입력란의 script GUID만 교체하되 fileID・참조・UnityEvent・직렬화 설정은 보존한다. 실제 최종 파일명・manifest는 구현 후 확정한다.

같은 현재 폼의 입력란 전환에만 `OnDeselect`의 protected `mSoftKeyboard` 분리를 적용하고 base 나머지 처리를 수행한다. 대상 입력란은 기존 TMP Open으로 secure・키보드 종류・길이・문자열을 재설정한다. 따라서 목표는 화면 키보드를 닫았다 다시 여는 동작의 제거이며 managed wrapper 동일성은 요구하지 않는다. 다른 화면・빈 곳・버튼・pause・명시적 Close에서는 정상 종료를 유지한다.

패키지 수정・reflection・공유 native 키보드 직접 브릿지는 사용하지 않고 공통 폼 전환・정리만 좁게 연결한다. 기존 코드 최종 삭제는 하지 않으며 문서 최상단의 제거 경계를 유지한다. 이전 wrapper 수명・마지막 문자・선택 범위・대상 실패・GC 경계를 검토하고, 첫 탭 수정과 합친 최종 검사 뒤 사용자 통합 확인을 한 번 요청한다. 현재는 설계 인계・구현 진행 중이며 적용 완료나 실기 수용으로 보고하지 않는다.

## 12. 필드 전환 통합 구현과 한 번의 실기 확인

11절의 검토 이후 `ContinuousInputField.cs`와 meta 추가, 공통 helper 2개와 Login/Lobby 씬 수정의 6개 파일이 인계됐다. 씬은 기존 9개 필드의 GUID・class만 바꾸고 직렬화 payload를 유지했다. 정확한 경로・수명 정리・검증 한계는 [Research 16절](Research.md#16-첫-탭과-필드-전환-통합-구현-인계)을 따른다. 10절의 필드 전환 미적용은 그 당시 기록이다.

같은 현재 폼 전환만 explicit Hide를 생략하고 기존 TMP Open으로 target 조건을 갱신한다. 이전 wrapper는 편집 세션 동안 임시 보관하고 current 정상 종료 뒤 old들을 정리한다. 빈 영역・제출・화면 이탈・pause・실패・timeout에서는 정상 닫기/정리를 유지하고 전환 활성화까지 한 프레임 이동량을 유지한다. native Done으로 이미 닫힌 키보드까지 유지했다고 해석하지 않는다.

통합 최종 manifest 6개와 현 파일의 SHA256 일치를 메인과 문서 담당자가 확인했다. 이번 전환 단계의 6개이며 작업 전체 누적 파일 수와 구분한다. Runtime errors 0/warnings 23, Android 조건 선택 errors 0/warnings 30이며 두 응답 파일 모두 helper 4개를 명시적으로 포함한다. Runtime은 UNITY_ANDROID・UNITY_EDITOR 포함, Android 선택은 UNITY_ANDROID 포함・UNITY_EDITOR 제외다. 최종 생명주기 대역 검사는 17개/실패 0, 포인터 회귀는 84개/실패 0이다. 설치 TMP 본문 발췌를 사용한 검사라도 실제 TMP 렌더・native/window・raycast 입력을 실행한 것은 아니다. 세부 근거는 Research 16절을 따른다.

현재는 **통합 소스・씬 구현 및 최종 정적/대체환경 검사 확인 / 사용자 Android 통합 실기 확인 대기**다. Android 빌드・native 실기는 수행하지 않았다. 첫 탭 제출・화면 닫기, 필드 전환 키보드 유지, 마지막 글자・가림・원복을 한 번에 확인하도록 안내하고 중간/중복 테스트는 요청하지 않는다. 기존 Android 수용은 유지하며 9개 가림 전수 결과는 미보고로 둔다. 상시 문서・메모리・TC・QA・Git 변경은 하지 않았고 Python 검사기의 기존 실행 불가 한계를 유지한다. 전체 완료로 보고하지 않는다.

## 13. 이메일 전환과 뒤로가기 고정 재작업

12절 이후 Android 결과에서 비밀번호↔확인 전환과 키보드를 연 상태의 로그인 한 번 탭은 수용됐다. 이메일↔비밀번호는 여전히 키보드가 닫혔다 다시 열려 재작업 대상이다. 회원가입 뒤로가기 버튼은 폼 상향 이동에 따라 화면 위로 벗어나므로, 사용자가 요구한 “어떤 상황에서도 같은 위치”를 이번 수정 범위에 포함한다. 정확한 사용자 결과는 Research 17절을 따른다.

두 수정을 묶어 마친 뒤 이메일↔비밀번호 전환 유지와 뒤로가기 위치 고정, 가려져 확인하지 못했던 화면 UI 뒤로가기 한 번 탭 및 종료/배치 복원을 한 번에 확인한다. 새 구현・검사・manifest는 아직 인계되지 않았으므로 이전 17/0・84/0 결과를 새 수정 완료로 재사용하지 않는다.

현재 집중 확인 범위와 과거 보류/미보고를 구분한다. 기존 정상 커서・검증・닉네임・잘못된 코드・정상 방 참가 등은 수용을 유지하고 네트워크 작업을 추가하지 않는다. 9개 가림 전수 미보고와 Tab・Shift+Tab 보류도 유지한다. 중간/중복 테스트는 요청하지 않으며 전체 완료로 보고하지 않는다. 이번 동기화는 기존 두 문서에 한정한다.

## 14. 이메일 전환과 고정 헤더 후속 인계

13절의 재작업 착수 뒤 공통 Form/Avoidance와 Login/Lobby 씬의 4개 수정이 인계됐다. 사용자 키보드는 삼성 키보드다. 코드 경로 재현을 실제 삼성 IME 원인 확정으로 확대하지 않는다. 정확한 경로・동작・근거는 [Research 18절](Research.md#18-이메일-전환과-고정-뒤로가기-후속-구현)을 따른다.

전환 target의 focused・nonnull 비종료 연결은 active=false 일시값만으로 종료하지 않는다. Done・Canceled・실패・timeout・실제 종료 정리는 보존한다. 뒤로가기는 원래 위치의 고정 헤더에 남기고 입력 본문과 오류 안내만 이동・클리핑한다. 인증 3개와 커스텀 참가의 기존 초기 배치는 앵커・레이아웃 검사를 통해 보존한다. 폼은 참조 연결 완료 뒤 표시・native 수명을 시작한다.

새 대역 검사는 생명주기/배치 24개・실패 0, 포인터 84개・실패 0, 씬 검사 67개 True・False 0이다. 기존 active 조건 복원 사본의 최종 `red-final.log`는 24개 중 mode 재구성 경계 1개 실패이며 초기 18/1과 구분한다. Runtime errors 0/warnings 23, Android 조건 선택 errors 0/warnings 30이며 helper 4개 포함을 확인했다. 씬 공백 9줄 정리 뒤 최종 manifest 4개와 현 파일 일치를 메인・문서 담당자가 확인했고 메인 변경 형식 검사 exit 0도 인계됐다. 소스 무변경이므로 공백 정리 후 컴파일을 반복하지 않았다. native 삼성 실기와 빌드는 수행하지 않았다.

사용자는 이메일↔비밀번호 유지, 고정 뒤로가기 위치, 가려져 못 했던 화면 버튼 한 번 탭 종료・복원을 한 번에 확인한다. 기존 수용은 유지하고 9개 가림 전수 미보고・Tab 보류는 이번 집중 확인과 구분한다. 중간/중복 테스트・네트워크 작업은 추가하지 않는다. 기존 두 문서 외 상시 문서・메모리・TC・QA・Git 변경은 하지 않으며 Python 검사기의 기존 한계를 유지한다. 전체 완료가 아니다.

## 15. 저장 로그의 원인 범위 분리

사용자 저장 로그를 읽기만 하여 분석했다. 원본 경로・SHA256・관측 시각・집계는 Research 19절이 원본이다. PID 9573의 이전 전환・pause drain과 PID 31104의 최신 13:53:19.960~23.336 구간을 분리한다.

최신 구간은 retained/target-activated와 키보드 표시 False/True가 각각 9회이고 retired-drain/gap-preserved는 각각 0회다. 다음 필드 활성화・설정 갱신 구간에서 OS/GameActivity 표시 변화가 발생한 것은 확인했지만 특정 native 호출・삼성 정책・완전한 교정 방법은 미확정이다. 이전 pause 정리를 최신 원인으로 합치거나, 별도 입력창 hideInput 미지원일 수 있는 경고를 소프트 키보드 Hide 원인으로 단정하지 않는다.

추가 읽기 분석 인계 뒤 수정 방향을 확정한다. 현재 코드 변경・새 검사・중간 실기 요청은 없으며 결함 미해결로 둔다. 원시 로그는 수정・삭제・업로드하지 않고 private custody 원칙을 유지한다. 기존 수용・9개 가림 전수 미보고・Tab 보류는 유지하며 이번 문서 변경은 기존 두 파일뿐이다.

최종 읽기 분석에서 구현 담당자도 9회/drain 0회를 독립 확인했다. False→True의 45~84ms는 로그 간격이며 화면 애니메이션 시간이 아니다. 같은 Unity frame의 retained/target 활성화 사이 native 변화이므로 해당 구간을 C# EndIdle 정리 분기로 설명하지 않는다. 별도 native 입력칸 hideInput의 GameActivity 미지원 경고도 소프트 키보드 Hide 증거가 아니다.

후속 **후보**는 로그인/회원가입에서 Default+secure native 연결을 유지하고 게임 내 이메일 평문 표시・기존 검증을 유지하는 것이다. 이메일 키보드의 `@` 배치・자동완성 편의를 잃을 수 있고 TMP 기본 Open과 분리 설계가 필요하다. 아직 사용자 선택・구현・검증 전이므로 확정 계획으로 승격하지 않는다. 타입 유지 native 갱신 대안도 restartInput 깜빡임을 피한다는 보장이 없다. Activity 전환・앱 전체 변경을 권고하지 않는다. 추가 로그/동일 테스트 대신 이 편의 손실에 대한 선택이 필요한 단계이며, 새 코드・빌드는 진행하지 않았다.

## 16. 승인된 공통 보안 키보드 연결 교정

사용자는 이메일 전용 `@` 배치/자동완성 편의 손실과 게임 내 이메일 평문・비밀번호 마스킹 유지를 확인하고 교정 진행을 승인했다. 15절의 사용자 선택 전 후보는 당시 기록으로 보존한다. 현재 로그인/회원가입에서 native Default+secure 단일 연결을 재사용하여 필드 전환마다 Open을 재호출하지 않는 설계 검토・구현 단계다.

필드별 UI 입력 종류・이메일 검증・커서・입력값 분리를 유지하고 다른 단일 입력 폼의 키보드 종류는 보존한다. public/protected 기반 접근을 검토하며 설치 패키지 private 수정・reflection・Activity 전환은 하지 않는 방향이다. 정확한 변경 파일・새 코드・검사 수치・manifest는 최종 설계/구현 인계 뒤 확정한다. 승인 자체를 구현・native 해결로 기록하지 않는다.

기존 Research/Plan의 연속 작업으로 진행하고 새 문서 질문・중간 빌드・반복 테스트를 요청하지 않는다. 원시 로그 custody와 무수정/무업로드, 기존 정상 수용・9개 가림 전수 미보고・Tab 보류를 유지한다. 기존 두 문서 외 상시 문서・메모리・TC・QA・Git 변경은 하지 않으며 전체 완료가 아니다.

## 17. 공통 보안 연결 구현 인계

> 이 절은 구현・최종 정적 검사 인계 당시 기록이다. 당시 삼성 실기 미확인은 그 단계의 상태로 보존하며 이후 통합 사용자 수용은 18절을 따른다.

16절의 승인/설계 검토 이후 ContinuousInputField・InputFormController・Login 씬의 3개 수정이 인계됐다. 로그인/회원가입의 serialized opt-in 두 폼만 native Default+secure 연결을 재사용하며 다른 단일 입력 폼은 유지한다. 첫 Open 뒤 정상 필드 전환은 text/limit/selection만 갱신한다. 이메일 화면 평문/검증・비밀번호 마스킹과 기존 뒤로가기/가림/첫 탭 동작을 보존한다. 정확한 경계는 [Research 21절](Research.md#21-공통-보안-키보드-연결-구현과-검증-경계)을 따른다.

TMP base 활성화 초기화는 참조 null 경계에서만 임시 shouldHideSoftKeyboard로 기본 Open을 억제하며 finally 복원한다. 선택/session/재진입 종료, 소유 handle, selection clamp, 취소 시 focused 참조 해제, Done/Canceled/실패/timeout/Close/pause 정리를 검토했다. UI 입력 종류/validator 임시 변경・private 패키지 수정・reflection・Activity 전환은 없다. 비밀번호 관리자 정책 전체 차단을 보장하지 않는다.

최종 대조로 동일 32항목의 Green 32/0・공통 활성화 guard만 끈 Red 32/23・포인터 84/0을 확인했다. Runtime errors 0/warnings 23, Android 조건 정적 컴파일 errors 0/warnings 30이며 이번 3개 manifest와 현 파일 해시가 모두 일치한다. 메인은 opt-in 두 폼・변경 형식 exit 0・이전 Avoidance/Lobby 보존도 확인했다. 이번 3개 범위와 전체 누적 변경 수를 구분하고 상세 해시・근거는 Research 21절에 둔다.

현재는 소스・씬・최종 정적/대체환경 검사 확인이며 실제 삼성 native・Android 빌드・사용자 수용은 미확인이다. 기존 수용・9개 가림 미보고・Tab 보류를 유지하고 중간/반복 테스트는 요청하지 않는다. Python 검사기의 기존 한계를 유지하고 전체 완료로 보고하지 않는다.

## 18. 통합 사용자 수용과 별도 남은 확인

> 이 절은 통합 수용 직후의 기록이다. 당시 다른 4개 미보고・Tab 보류는 이후 19절의 사용자 확인으로 닫혔으며 원문은 이력으로 보존한다.

사용자의 “모두 정상작동” 보고는 안내한 Android 삼성 키보드 통합 절차 전체의 수용이다. 로그인 이메일↔비밀번호・회원가입 이메일↔비밀번호↔확인 키보드 유지, 값 보존・이메일 평문/비밀번호 마스킹, 선택 필드 가림 없음과 복원, 열린 키보드 로그인 한 번 탭, 고정 뒤로가기와 화면 버튼 한 번 탭 닫기, 재진입 비밀번호 두 칸 비움・재입력을 포함한다. 집중 교정은 사용자 수용 완료이며 [Research 22절](Research.md#22-삼성-키보드-통합-사용자-수용과-남은-범위)에 상세 범위를 기록했다.

근거는 사용자 보고이며 정확한 APK 해시・빌드 실행 로그는 제공되지 않았다. 이전 소스 manifest・32/0 Green・32/23 Red・84/0 포인터・컴파일 0/23 및 0/30을 이 실기 보고와 혼동하지 않는다. 기존 커서・검증・닉네임・방 실패/참가 등의 수용을 유지하며 이미 확인한 기능을 반복 테스트하지 않는다.

가림/원복은 로그인 2개와 회원가입 3개가 수용됐다. 다른 4개인 재설정 이메일・최초 닉네임・닉네임 변경・방 코드의 가림과 키보드 종료 후 배치 복원은 아직 미보고다. PC Tab・Shift+Tab은 Android 확인 불가로 보류를 유지한다. 이 별도 범위를 남기며 모든 인풋필드의 전체 검증 완료로 확대하지 않는다. 계정 생성・유료 닉네임 변경을 테스트 조건으로 강제하지 않는다.

사용자가 승인한 이번 문서 갱신은 기존 두 파일만 수행했다. 상시 문서・메모리・Testcase・QA・코드/주석・씬・빌드 실행・원시 로그・Git 변경은 하지 않았다. Python 실행 불가와 `_Tasks/` 검사 제외 한계를 유지하고 문서 내용・연결은 직접 검토한다.

## 19. 합의한 구현・안내 테스트 전체 수용 완료

사용자가 나머지 4개 정상 동작과 Editor 이동 확인까지 보고하고 문서 갱신을 승인했다. 재설정 이메일・최초 닉네임・닉네임 변경・방 코드의 가림/복원도 정상으로, 기존 로그인 2개・회원가입 3개와 합쳐 총 9개 가림/복원이 수용됐다. 18절의 미보고・보류는 이제 현재 잔여가 아니다.

Unity Editor Play/Game 창에서 로그인 이메일→비밀번호→이메일, 회원가입 이메일→비밀번호→확인→이메일의 Tab 순환과 Shift+Tab 역방향도 정상이다. 값 보존・선택 필드 즉시 입력・오제출 없음까지 사용자 수용으로 기록한다. Editor 결과를 PC standalone 빌드 실기로 확대하지 않는다. 정확한 APK/빌드 해시・실행 로그는 미제공이며 기존 정적/대체환경 근거와 별개다. 상세 범위는 [Research 23절](Research.md#23-인풋필드-개선-전체-사용자-수용-완료)을 따른다.

**이번 합의 범위의 인풋필드 개선은 구현과 안내한 테스트까지 전체 수용 완료다.** 기존 커서・검증・닉네임・방 참가・삼성 키보드 전환/첫 탭/고정 뒤로가기/재진입 수용을 유지하며 중복 테스트를 요구하지 않는다. 전면 레이아웃・비밀번호 보기・미배선 계정 연동은 범위 밖 후속이므로 잔여 필수 테스트로 추가하지 않는다. 보존 주석 삭제・코드 정리는 별도 범위로 남기고 이번 갱신에서 수행하지 않는다.

변경은 기존 Research/Plan 두 문서뿐이다. 코드・씬・빌드・상시 문서・메모리・Testcase・QA・원시 로그・Git 변경은 하지 않았다. Python 실행 불가와 `_Tasks/` 검사 제외 한계는 유지하며 재검색하지 않고 저장 문서의 수용 범위・링크・의미를 직접 검수한다.
