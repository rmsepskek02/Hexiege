# Testcase: 닉네임 설정 흐름 수정 + UGS OIDC 브릿지 해결

## 이 문서가 무엇인가

이메일 회원가입 직후 닉네임을 저장하면 "Access token is missing" 에러가 나던 문제를 고치기 위해,
**닉네임 설정 시점을 "UGS 세션이 있는 첫 로그인 성공 직후"로 통일(C안)** 하고,
그동안 미해결로 남아 있던 **UGS OIDC 브릿지(실계정이 UGS 세션을 못 받던 문제)** 를 UGS Dashboard에 OIDC 제공자를 등록하여 해결했다.
아래 테스트 케이스는 세 로그인 경로(Google / 익명 / 이메일)와 새 닉네임 흐름이 실기기에서 의도대로 동작하는지 확인한 결과다.

모든 케이스는 실기기 단독 로그인 테스트이므로 접두사는 `SINGLE-`을 사용한다.

---

## 테스트 케이스

### SINGLE-001: 이메일 회원가입 → 인증 화면 직행

**전제:** 로그인 선택 화면에서 "이메일로 로그인/회원가입"을 통해 회원가입 화면에 진입한 상태. 신규(미가입) 이메일 사용.

**동작:**
1. 이메일, 비밀번호, 비밀번호 확인을 입력하고 회원가입 버튼을 누른다.

**기댓값:**
- 회원가입이 완료되면 인증 메일이 발송된다.
- **닉네임 설정 화면이 뜨지 않고** 곧바로 이메일 인증 대기 화면으로 이동한다.

**결과:** PASS — 회원가입 직후 닉네임 화면 없이 인증 대기 화면으로 직행함을 확인. 인증 메일은 스팸함에서 확인됨.

---

### SINGLE-002: 이메일 인증 후 첫 로그인 → 닉네임 설정 → 저장 성공 → 로비

**전제:** SINGLE-001에서 가입한 계정의 이메일 인증을 완료(메일함/스팸함의 인증 링크 클릭)한 상태. 아직 한 번도 닉네임을 저장하지 않은 계정.

**동작:**
1. 이메일 로그인 화면에서 이메일과 비밀번호를 입력하고 로그인 버튼을 누른다.
2. 닉네임 설정 화면이 뜨면 닉네임을 입력하고 확인 버튼을 누른다.

**기댓값:**
- 로그인이 성공하면 최초 로그인으로 판정되어 닉네임 설정 화면이 표시된다.
- 닉네임 확인 시 **"Access token is missing" 같은 토큰 에러 없이** 닉네임이 정상 저장된다.
- 저장 완료 후 로비 화면으로 이동한다.

**결과:** PASS — 최초 로그인 시 닉네임 화면이 뜨고, 토큰 에러 없이 닉네임 저장 성공 후 로비로 이동함을 확인. UGS OIDC 제공자 등록으로 실계정이 UGS 세션(access token)을 정상 획득한 결과.

---

### SINGLE-003: Google 최초 로그인 → 닉네임 설정 → 저장 성공 → 로비

**전제:** Google Play Games 계정이 설정된 기기. 해당 계정으로 아직 닉네임을 저장한 적이 없는 상태.

**동작:**
1. 로그인 선택 화면에서 "Google로 로그인"을 누른다.
2. 닉네임 설정 화면이 뜨면 닉네임을 입력하고 확인 버튼을 누른다.

**기댓값:**
- Google 로그인이 성공하면 최초 로그인으로 판정되어 닉네임 설정 화면이 표시된다(기존과 동일한 흐름).
- 닉네임 확인 시 토큰 에러 없이 정상 저장된다.
- 저장 완료 후 로비 화면으로 이동한다.

**결과:** PASS — Google 경로는 기존 흐름 그대로 닉네임 화면 → 저장 성공 → 로비 이동 확인. OIDC 제공자 등록으로 Cloud Save 토큰 에러 해소.

---

### SINGLE-004: 익명 로그인 → 게스트로 바로 로비

**전제:** 로그인 선택 화면. 익명으로 시작하기를 선택하려는 상태.

**동작:**
1. "익명으로 시작하기"를 누른다.
2. 경고 팝업에서 "계속 익명으로 진행"을 누른다.

**기댓값:**
- 닉네임 설정 화면 없이 자동 생성된 게스트 표시 이름으로 진행된다.
- 곧바로 로비 화면으로 이동한다.

**결과:** PASS — 닉네임 화면 없이 게스트로 바로 로비 진입 확인. 익명은 UGS 익명 로그인(OIDC 미사용)이라 이번 OIDC 이슈와 무관하게 기존대로 정상 동작.
