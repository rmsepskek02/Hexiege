# Research — 싱글플레이 맵 준비 실패 UI (규칙 M-4)

---

## 이 작업이 무엇이고 왜 하는가 (자연어 설명 — CLAUDE.md 규칙 13)

**한 줄로**: 혼자 하는 게임(싱글플레이)에서 **새 맵을 만들지 못했을 때, 화면에 아무 말도 하지 않고 사용자를 빈 화면에 가둬 두는 문제**를 없애기 위한 사전 조사다.

조금 더 풀어 쓰면 —

이 게임은 경기를 시작할 때마다 지도를 **그 자리에서 새로 뽑는다.** 보통은 한 번에 잘 뽑히지만, 아주 드물게 **100번을 다 뽑아도 규칙에 맞는 지도가 안 나오고, 마지막 보험으로 준비해 둔 예비 지도까지 읽지 못하는** 경우가 있다. 그런 일은 「게임 파일(에셋)이 빠졌거나 깨졌을 때」에만 생긴다.

문제는 **그때 화면이 아무 말도 하지 않는다**는 것이다.

- **경기를 처음 시작할 때** 실패하면 → 땅(헥스 타일)이 그려지지 않은 **텅 빈 전투 화면**만 남는다. 안내도 없고, 나갈 버튼도 없다.
- **경기가 끝난 뒤 「다시하기」를 눌렀을 때** 실패하면 → 더 나쁘다. 「다시하기」는 **결과 화면을 먼저 닫고** 지도를 만들기 때문에, 실패하면 **결과 화면도 없고 지도도 없고 안내도 없다.** 결과 화면에 있던 「로비로」 버튼까지 함께 사라져서 **사용자가 스스로 나갈 방법이 전혀 없다.**

멀티플레이(둘이 하는 게임) 쪽은 이 상황을 알리는 규칙(규칙 M-2·M-3)이 이미 만들어져 실기에서 검증까지 끝났다. **싱글플레이만 남았다.** 그 남은 하나가 규칙 M-4 이고, 이 조사는 그 규칙을 실제 코드로 구현하기 전에 **① 지금 코드가 정확히 어떻게 되어 있는지 ② 무엇을 어디에 붙여야 하는지 ③ 건드리면 위험한 곳이 어디인지**를 확인한 기록이다.

이 문서는 **조사 기록이며 아무것도 결정하지 않는다.** 무엇을 어떻게 고칠지는 같은 폴더의 [Plan.md](Plan.md) 가 담고, 그 Plan 은 **사용자 승인 전까지 확정이 아니다.**

### 1-2. 규칙 M-4 가 지금 어디까지 정해 놓았는가

규칙 M-4 는 **날짜 블록이 다섯 겹**으로 쌓여 있다. 아래는 그 순서대로 정리한 것이다(모두 이 문서 작업 중 직접 읽어 확인).

| 시점 | 무엇이 정해졌는가 |
|------|-----------------|
| 본문(첫 불릿) | **최초 경기 준비 실패 = 모달 (Modal) 타입 · `Retry`/`Lobby` 표시.** 표시 문구 · loading UI 처리는 ⚠️ 미정으로 못 박음 |
| 본문(둘째 불릿) | **재경기 맵 준비 실패 = 결과 화면의 기존 선택지를 복원한다.** 팝업 여부는 ⚠️ 미정 |
| 2026-09-14 개정 | 「같은 맵/새 맵」 선택이 없어져 복원 대상을 「결과 화면의 기존 선택지」로 바꿈(**뜻은 그대로**) |
| 2026-09-16 확정 | **재경기 맵 준비 실패는 「알림 팝업」(규칙 D-5 구조 · 규칙 8 의 모달)으로 알린다** |
| 2026-09-22 (2차) | 🔴 **규칙 M-3 의 「팝업 → 상태 줄」 개정을 이 규칙에 번지게 하지 않았다.** 사유 ①은 싱글에도 적용 / ②는 적용 안 됨 / ③은 **「자리는 있으나 도달 경로를 확인하지 못했다」.** ⚠️ **미정 2가지를 못 박음** — ①상태 줄로 알릴 것인가 ②닿는 경로를 만들 것인가. 그래서 **M-3 은 상태 줄 · M-4 는 팝업**으로 수단이 갈렸다 |
| 2026-09-28 (3차) 확정 | **표시 문구 = `맵 준비에 실패했습니다`**(멀티와 같은 문구) · **loading UI = 닫는다** · **버튼 라벨 = 「다시하기」/「로비로」** · **재시도 횟수 제한 없음** · **사유 5종을 구분해 보여 주지 않는다.** ⚠️ **구체적인 구현 방식(배치 · 팝업인가 다른 위젯인가)은 닫지 않았고 `game-design-lead` 에게 넘겼다** |

🔴 **즉 이번 작업이 상대할 「살아 있는 미정」은 2026-09-22 (2차) 블록의 두 가지다**(파일 위치: `GameSystemRules_UI.md` **287행**에서 시작하는 블록 · 표는 292~296행 · 미정 2가지는 302~304행 · 「두 규칙이 서로 다른 수단을 갖는다」는 306행).

### 1-3. 이번 설계가 기대는 다른 규칙

| 규칙 | 확인한 내용 |
|------|-----------|
| **규칙 8**(팝업 타입 구분) | 모달 예시 목록에 **「맵 준비 실패 UI (멀티 최초 경기 · 싱글 최초 경기)」가 이미 적혀 있다**(180행). 모달 정의는 2026-09-16 에 「명시적 응답이 필요한 팝업」으로 넓혀졌고 **판정 기준은 「화면을 진행시키려면 팝업 안에서 눌러야 하는가」** 다 |
| **규칙 9**(배경 탭) | 모달은 배경 탭으로 닫히지 않는다. *"확인/취소 버튼"* 은 「버튼이 2개」가 아니라 「배경이 아니라 버튼으로만 닫힌다」는 뜻으로 읽는다(2026-09-16 보강) |
| **규칙 D-1** | 상태 줄 = **결과 화면의 타이머 텍스트 자리 하나**이고, **별도 팝업을 새로 띄우지 않는다**가 이 화면의 선례다 |
| **규칙 D-3** | 🔴 **로비 복귀 버튼은 어떤 상태에서도 비활성화하지 않는다.** 근거는 *「두 버튼이 동시에 꺼지면 사용자가 스스로 화면을 빠져나갈 방법이 없어진다」* |
| **규칙 D-4** | 평시 카운트다운 60초 · 이탈 판정 시 30초 재시작. ⚠️ **맵 준비 실패로 인한 재시작은 이 규칙이 아니라 규칙 M-3(전체 길이)** 이며 **섞어 읽지 않는다** |
| **규칙 D-7** | 상태 줄의 상태는 **넷**(평시 / 재경기 준비 중 / 재경기 실패 / 상대 이탈)이고 **우선순위는 「이탈 > 실패 > 평시」**. 문구 표(2026-09-24)와 개행 형태 표(2026-09-27)가 각각 단일 소스다. **판단 기준 = 「사람을 기다리면 타이머가 돈다 / 시스템을 기다리면 타이머가 멈춘다」** |
| **규칙 18**(RandomMap) | 🔴 **가르는 것은 화면 문구 하나뿐이고 기준은 「연결 끊김인가」 하나뿐**이다. 그 밖의 사유(해시 불일치·역직렬화 실패·공정성 검증 실패·미지원 버전·용량 초과·timeout)는 **전부 기본 문구**. **실제 문구는 이 규칙이 정하지 않고 `GameSystemRules_UI.md` 로 미뤄 두었다** |
| **TDD 「🔴 최상위 원칙」**(147행) | **플레이어는 자신이 Host 인지 Client 인지 알 수 없다** — 화면·승패·이탈 처리가 역할과 무관하게 같아야 하며, **개별 규칙이 이 원칙과 충돌하면 고칠 대상은 개별 규칙** |

> ⚠️ **낱말 주의(정확히 적는다)**: 규칙 M-4 의 2026-09-28 (3차) 블록은 *「사유를 잘게 나누어 문구를 늘리지 않는다」* 를 **규칙 18 의 문장으로 인용**하고 있으나, 그 문장 그대로의 표현은 **규칙 D-7 의 2026-09-24 확정 블록**에 있다. 규칙 18 본문이 가진 표현은 *「가르는 것은 화면 문구 하나뿐이다」* · *「절차를 복제하지 않고 표시만 가른다」* 다. **기준의 내용은 같고 문장이 있는 자리가 다르다** — 이번 Plan 은 **두 자리를 함께** 근거로 적는다.

5. **규칙 D-4 와 규칙 M-4 285행의 적용 범위 개정**을 항목으로 세우되 **승인 사항으로 표시**하는가(§2-6-2).
6. **싱글 강제 실패 수단**을 만들 것인가(판단 항목).
7. **낡은 문구 2건**을 언제 어떻게 고치는가.
