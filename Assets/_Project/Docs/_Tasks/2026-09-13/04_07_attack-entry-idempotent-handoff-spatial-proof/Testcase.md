# 공격 진입 멱등 인계와 대미지 위치 증거 — 테스트 케이스

이 문서는 공격 범위에 진입하는 유닛이 멈추거나 공격을 시작하지 못하는 문제와 대미지 숫자의 표시 위치를 멀티플레이 실기에서 서로 분리해 확인한다. 자동 검증 결과는 실기 결과를 대신하지 않으며, 사용자가 확인한 화면 결과와 같은 경기의 Host·Client 로그를 함께 판정 근거로 사용한다.

## 테스트 환경

- 구성: Unity Editor Host + Android Client
- 실행 일자: 2026-09-13
- 같은 경기 식별값: `993718220d45194886d85f22bd4e8cade81e2992baf80a5152b7127a2fd69a3e`
- 사용자 육안 결과: 근거리 유닛들이 공격하지 않았고, 대미지 텍스트 위치는 정상

### MULTI-1: 공격 범위 진입 직전의 이동·공격 연속성

**전제:** Host와 Client가 같은 경기에 접속해 있고, 근거리 유닛과 원거리 유닛이 적을 향해 이동한다.

**동작:**
1. 양 진영에서 유닛을 생산한다.
2. 유닛이 적에게 접근해 이동에서 공격으로 전환되는 순간을 관찰한다.
3. 공격 직전에 멈춘 채 공격으로 이어지지 않는 유닛이 있는지 확인한다.

**기댓값:**
- 유닛은 공격 가능한 위치에 도달하면 불필요한 대기 없이 정지·회전·공격으로 이어진다.
- 공격 화면 인계 실패 때문에 이동과 공격 사이에 갇히는 유닛이 없어야 한다.

**결과:** FAIL — 사용자 육안에서 근거리 유닛들이 공격하지 않았으며, Host 로그에도 공격 화면 인계 실패 87회와 총 423프레임의 보류가 기록됐다.

### MULTI-2: 근거리 유닛의 실제 공격 수행

**전제:** 양 진영에 근거리 유닛이 생산되어 적과 근접할 수 있다.

**동작:**
1. 근거리 유닛들이 적에게 접근하도록 경기를 진행한다.
2. 각 유닛이 공격 동작을 시작하고 실제 피해를 발생시키는지 관찰한다.

**기댓값:**
- 근거리 유닛은 공격 사거리에 도달한 뒤 공격 동작과 피해를 정상적으로 반복한다.
- 특정 근거리 종류가 공격 진입 단계에서 지속적으로 제외되지 않는다.

**결과:** FAIL — 사용자는 근거리 유닛들이 모두 공격하지 않았다고 확인했다. 로그에서도 여러 근거리 종류의 공격 진입 실패가 확인됐다. 개별 종류별 육안 결과는 별도로 확인하지 않았으므로 종류별 성공·실패로 확대하지 않는다.

### MULTI-3: 대미지 텍스트 표시 위치

**전제:** Host와 Client 양쪽에서 공격 피해가 발생하고 대미지 숫자가 표시된다.

**동작:**
1. 피해를 받는 유닛 주변의 대미지 숫자 위치를 관찰한다.
2. Host와 Client 화면에서 숫자가 다른 위치나 엉뚱한 대상 주변에 나타나는지 확인한다.

**기댓값:**
- 대미지 숫자는 피해를 받은 대상의 화면 위치에 표시된다.
- 좌우 반전된 Client에서도 다른 위치로 이탈하지 않는다.

**결과:** PASS — 사용자가 대미지 텍스트가 올바른 위치에 표시된다고 확인했다. 같은 경기의 위치 비교 기록에서도 불일치가 없었다.

### MULTI-4: 발생한 공격 결과의 Host·Client 전달과 표시 수렴

**전제:** 같은 경기에서 Host가 피해 결과를 만들고 Client가 이를 받아 화면에 표시한다.

**동작:**
1. 경기를 진행해 공격과 피해를 충분히 발생시킨다.
2. 경기 종료 후 Host가 만든 결과 수와 Client가 받은 결과 수를 비교한다.
3. 화면 표시가 필요한 결과 수와 실제 표시 수를 양쪽에서 비교한다.

**기댓값:**
- Host가 만든 공격 결과가 Client에 누락되거나 거부되지 않는다.
- 화면 표시가 필요한 결과는 Host와 Client에서 각각 한 번씩 표시된다.

**결과:** PASS — 발생한 공격 결과 2,298건이 Client에 모두 수신됐고, 화면 표시 대상 2,036건이 Host와 Client 양쪽에서 모두 2,036건 표시됐다. 이 판정은 근거리 공격 자체가 발생하지 않은 문제를 정상으로 간주하지 않는다.

### MULTI-5: 공격 수행 유닛 종류의 전체 범위 확인

**전제:** 전체 유닛 종류의 공격 경로를 확인할 수 있도록 경기를 구성한다.

**동작:**
1. 가능한 유닛 종류를 생산해 공격 상황을 만든다.
2. 경기 종료 후 실제 공격 수행 증거가 확보된 종류 수를 확인한다.

**기댓값:**
- 전체 25종의 공격 수행 증거가 확보된다.
- 일부 종류의 공격만으로 전체 공격 시스템을 정상 판정하지 않는다.

**결과:** FAIL — 실제 공격 수행 증거는 25종 중 4종에서만 확보됐다.

### MULTI-6: Host·Client 역할 교대 회귀

**전제:** 첫 경기와 반대로 Android가 Host, Unity Editor가 Client가 되도록 새 경기를 시작할 수 있다.

**동작:**
1. Host와 Client 역할을 바꿔 같은 공격 시나리오를 반복한다.
2. 근거리 공격, 공격 전 멈춤, 대미지 숫자 위치와 결과 전달을 다시 확인한다.

**기댓값:**
- 역할을 바꿔도 공격 진입과 피해 표현 결과가 동일해야 한다.

**결과:** 미확인 — 최신 실기에서는 역할 교대 경기 결과가 제공되지 않았다.

## 정적 분석 및 로그 분석 결과 (qa-tester)

### BUG-001: 근거리 공격 진입 시 확정 타겟이 전달되지 않아 인계가 실패함

- 심각도: Critical
- 관련 TC: MULTI-1, MULTI-2, MULTI-5
- Host는 공격 진입 인계 실패를 87회 기록했고, 상세 64건과 초과 23건으로 종료했다. 최종 이동 판정은 FAIL이다.
- 상세 64건의 유닛 식별값을 같은 세션의 생산 로그와 대조한 결과는 LittleKnight 14건, EmberSpirit 14건, TideSpirit 14건, DustSpirit 12건, FlameSpirit 6건, SpearMan 4건이다. 이는 로그상 실패 종류이며, 사용자가 각 종류를 개별 육안 판정했다는 의미가 아니다.
- SpearMan은 실패 기록에 포함되지만 공격 시작 성공 기록도 1건 존재한다. 따라서 해당 종류의 모든 개체가 항상 실패했다고 판정하지 않는다.
- 이동 후보 위치에서 확인한 타겟 정보가 공격 진입 알림에 포함되지 않고 유닛 식별값만 전달된다. 수신 측은 아직 이동이 확정되지 않은 현재 위치를 기준으로 공격 사거리 내 타겟을 다시 찾으며, 타겟을 찾지 못하면 인계를 확인하지 않는다. 작은 사거리의 근거리 유닛이 이 경계에 집중적으로 걸린다.
- 원거리와 일부 근거리에서 발생한 공격 결과의 생성·전달·표시 수렴은 정상이다. 이 정상 축은 공격 진입 실패를 상쇄하지 않는다.
