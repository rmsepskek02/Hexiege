# 공격 진입 타겟 전달 경계 교정 — 테스트 케이스

이 문서는 이동 중 확정한 공격 대상을 공격 시작 단계까지 그대로 전달하도록 교정한 결과를 확인한다. 이전 실패 경기와 동일한 유닛 구성으로 다시 시험해 공격 진입 실패가 사라졌는지 비교하며, 이번에 생산하지 않은 나머지 유닛은 현재 교정의 실패로 간주하지 않는다. 자동 로그 판정과 사용자의 화면 관찰 범위는 서로 구분해 기록한다.

## 테스트 환경

- 구성: Unity Editor Host + Android Client
- 실행 일자: 2026-09-13
- 최신 같은 경기 식별값: `abe1fb66044f1aa5efbb99d4420fa901e48c927ebbf3c24ef30b72f181c1f5c1`
- 비교 대상 이전 경기 식별값: `993718220d45194886d85f22bd4e8cade81e2992baf80a5152b7127a2fd69a3e`
- 사용자 설명: 이전 시험과 동일한 유닛만 시험했으며, 나머지 유닛은 이번에도 의도적으로 시험하지 않음
- 화면 관찰 기록 경계: 사용자는 시험 완료를 알렸지만 이번 시험에서 개별 현상을 모두 육안 PASS로 선언하지는 않았으므로, 아래 결과는 같은 범위의 저장 로그 회귀 판정을 중심으로 기록함

### MULTI-1: 동일 근거리 유닛의 공격 진입 회귀

**전제:** 이전 실패 시험에서 사용한 것과 같은 근거리 유닛을 포함한 구성으로 Host와 Client가 같은 경기에 접속해 있다.

**동작:**
1. 이전 시험과 동일한 종류의 유닛을 생산한다.
2. 근거리 유닛이 적에게 접근해 공격을 시작하도록 경기를 진행한다.
3. 경기 종료 후 이전에 실패했던 근거리 종류가 실제 공격 시작 단계에 진입했는지 확인한다.

**기댓값:**
- 이전에 공격 진입 실패가 기록된 근거리 종류가 모두 공격 시작 단계에 진입한다.
- 특정 근거리 종류가 공격 진입 경계에서 계속 제외되지 않는다.

**결과:** PASS — 이전 실패 대상인 LittleKnight, EmberSpirit, TideSpirit, DustSpirit, FlameSpirit, SpearMan 6종 모두 최신 Host 로그에서 정상 승인된 공격 시작 기록이 확인됐다. 이는 사용자가 이전과 동일한 유닛을 시험했다는 설명과 같은 범위의 로그 회귀 판정이며, 생산하지 않은 나머지 종류까지 시험했다는 의미는 아니다.

### MULTI-2: 공격 진입 인계 실패 해소

**전제:** 근거리 유닛이 이동 중 적을 선택하고 공격 가능한 위치에 도달한다.

**동작:**
1. 근거리 유닛이 적에게 접근하는 상황을 반복해서 만든다.
2. 이동에서 공격으로 전환되는 동안 공격 진입 인계 실패와 정지 상태 위반이 발생하는지 확인한다.
3. 이전 실패 경기의 집계와 최신 경기의 집계를 비교한다.

**기댓값:**
- 공격 진입 인계 실패가 한 건도 발생하지 않는다.
- 정지한 상태에서 걷기 표현이 남는 위반이 발생하지 않는다.
- 정상적인 공격 준비 보류는 실제 실패와 분리되어 기록된다.

**결과:** PASS — 같은 유닛 범위에서 공격 진입 인계 실패가 이전 87건에서 최신 0건으로 감소했다. 최신 경기의 정지 상태 걷기 위반, 실패 상세, 실패 초과 기록도 모두 0건이다. 총 431프레임의 보류는 실패가 아니라 정상적인 인계 대기 집계이며, 공격 준비 전 대상 변경 보류 2건도 무시나 실패 없이 정상 축으로 기록됐다.

### MULTI-3: Host 공격 결과와 Client 수신 수렴

**전제:** Host에서 공격과 피해 결과가 발생하고 Client가 같은 경기 결과를 수신한다.

**동작:**
1. 충분한 공격과 피해가 발생하도록 경기를 진행한다.
2. 경기 종료 후 Host가 만든 공격 결과와 Client가 수락한 결과를 비교한다.
3. 실패하거나 거부된 결과가 있는지 확인한다.

**기댓값:**
- Host가 만든 결과가 Client에 누락되지 않는다.
- 결과 생성 실패와 Client 거부가 없어야 한다.

**결과:** PASS — Host가 만든 공격 결과 2,703건과 Client가 수락한 결과 2,703건이 일치했다. Host 결과 실패와 Client 거부는 모두 0건이다.

### MULTI-4: 대미지 표시 수와 위치 회귀

**전제:** Host와 Client 양쪽에서 화면 표시가 필요한 피해가 발생한다.

**동작:**
1. 피해를 충분히 발생시킨 뒤 화면 표시 대상 수와 실제 표시 수를 비교한다.
2. Host와 Client의 피해 위치 비교 기록에서 불일치가 있는지 확인한다.

**기댓값:**
- 화면 표시가 필요한 피해가 Host와 Client에서 모두 누락 없이 표시된다.
- 피해 표시 위치 비교에서 불일치가 발생하지 않는다.

**결과:** PASS — Host와 Client 모두 화면 표시 대상 2,410건을 2,410건 표시했고 실패는 0건이다. 위치 비교는 Host 2,144건과 Client 2,036건에서 모두 불일치 0건이다. 이는 저장 로그 기준 회귀 PASS이며, 사용자가 이번 시험의 모든 대미지 표시를 개별 육안 PASS로 선언했다는 뜻으로 확대하지 않는다.

### MULTI-5: 이번 시험의 유닛 종류 범위

**전제:** 이번 시험은 이전 실패 경기와 동일한 유닛 종류만 비교 대상으로 삼는다.

**동작:**
1. 경기 종료 후 실제 공격 증거가 기록된 종류 수를 확인한다.
2. 사용자가 의도한 시험 범위와 비교한다.

**기댓값:**
- 이전 실패 경기와 같은 대상 유닛의 회귀 여부를 판단할 수 있어야 한다.
- 의도적으로 생산하지 않은 종류를 현재 교정의 실패로 판정하지 않는다.

**결과:** PASS — 실제 공격 증거는 25종 중 9종에서 확보됐다. 사용자는 이전과 동일한 유닛만 시험했고 나머지는 의도적으로 시험하지 않았다고 명시했으므로, 9/25는 이번 Task의 실패나 미완료 사유가 아니다. 전체 25종 확인은 별도 통합 회귀 범위다.
