- **목적·질문:** 게임의 목적·플레이 경험·시스템 역할과 기획 확정 여부를 설명한다.
- **포함:** 게임 컨셉·흐름·시스템의 기획 의도와 미확정 기획.
- **제외·담당:** 상세 동작은 [게임 규칙](GameSystemRules.md), 수치는 [스탯](StatsReference.md), 구현 상태는 [현재 현황](PROJECT_STATUS.md), 실행 경위는 [이력](History/ImplementationVerificationHistory.md).

- **갱신:** 사용자가 기획을 확정·변경할 때 해당 본문을 교체한다. 구현 완료 인계는 추가하지 않는다.

## VFX의 기획 방향

공격은 원래 유닛의 의미를 읽을 수 있게 표현하고 피해·힐의 권위 판정과 구분한다. Mushroom 착탄은 짧은 포자 burst이며 지면에 남는 damage zone이 아니다. 지속 poison/burn은 실제 recipient 효과 수명을 따르고 같은 owner 갱신은 재시작하지 않는다.

종족별 타워는 외형을 구분하되 Human의 Assault 재사용과 Tank/Cannon의 Tank 선택을 혼동하지 않는다. 실제 preset·파일·연결은 [VFX/SFX 목록](Assets/VFXSFXList.md), 제작·배선 계약은 [제작 가이드](Assets/VFXSFXGuide.md)가 담당한다. [이전 사양·변경 원문](History/ImplementationVerificationHistory.md#role-maintenance-20261016-r2-gdd-vfx). 이 절은 게임 피해 수치나 개별 실기 수용을 새로 확정하지 않는다.

기획 확정/미확정은 이 문서, 실제 구현·개별 수용은 [현재 상태](PROJECT_STATUS.md)와 [전투 감사표](Assets/UnitCombatAssetMatrix.md)에서 구분한다.

## 🎮 게임 개요

### 기본 정보
- **장르**: 실시간 전략 게임 (RTS)
- **플랫폼**: 모바일 (Android/iOS)
- **화면 방향**: 세로 모드 (Portrait)
- **플레이 모드**: PvP 1v1 실시간 매칭
- **평균 플레이 타임**: 10분 (서든데스 2분 포함, 최대 12분)

### 핵심 컨셉
육각형 타일맵 기반의 공성전 RTS 게임. 플레이어는 건물을 건설하고 유닛을 생산하여 상대방의 본기지를 파괴하는 것이 목표입니다. 유닛은 AI로 자동 제어되며, 플레이어는 전략적 건물 배치와 생산 관리에 집중합니다.

### 차별화 포인트
- 육각형 타일 기반 공간 전략
- 타일 점령 = 인구수 확장 메커니즘
- 자동/수동 생산 하이브리드 시스템
- 3종족 고유 특성

### 비주얼 스타일
- **그래픽**: 3D 이소메트릭 (Clash of Clans/Royale 스타일 카툰)
- **아트 방향**: 밝고 친근한 느낌
- **뷰**: Orthographic 55도 틸트 3D

### 카메라 시스템
- **기본 뷰**: Orthographic + X축 55도 틸트 (이소메트릭)
- **화면 이동**: 한 손가락 드래그 (Pan)
- **확대/축소**: 두 손가락 핀치 (Zoom)
- **줌 범위**: 최소 0.5x ~ 최대 2.0x (조정 가능)
- **이동 제한**: 맵 경계 내로 제한

<a id="핵심-게임플레이"></a>

## 🎯 핵심 게임플레이

### 게임 흐름
```
게임 시작
  ↓
초기 타일 할당 (7~10개)
  ↓
자원 수집 (자원 건물 건설)
  ↓
유닛 생산 (생산 건물 + 랠리 설정)
  ↓
타일 점령 확장 (인구수 증가)
  ↓
전선 관리 (방어타워, 마법)
  ↓
업그레이드 투자
  ↓
상대 본기지 공격
  ↓
승리!
```

### 플레이어 행동
1. **건물 건설**: 타일 선택 → 건물 타입 선택 → 건설
2. **유닛 생산**: 생산 건물 선택 → 유닛 타입 설정 (자동/수동)
3. **랠리 포인트**: 생산 건물 → 타일 지정
4. **마법 사용**: 스킬 건물 → 마법 선택 → 타겟 지정
5. **건물 업그레이드**: 건물 선택 → 업그레이드 버튼

### 인구수 시스템
**공식**: `총 인구수 = 보유 타일 수`

**인구 소비**:
- 건물: 각 1 인구
- 유닛: 각 1 인구

**예시**:
```
보유 타일: 20개
건물: 본기지(1) + 생산건물(3) + 타워(1) = 5개
사용 가능 인구: 20 - 5 = 15마리 유닛
```

### 자원 시스템

골드는 건설·생산·연구 사이의 선택을 만드는 경기 내 자원이다. 기본 수입 없이 광산에 채굴소를 세워 지속 수입을 얻으며, 초기 골드는 그 경기에서 확정한 맵이 정한다. 멀티에서는 Host가 보낸 같은 값을 Client도 소비한다.

광산은 이동 불가 자원 오브젝트이며 인접 아군 영토를 확보한 뒤 채굴소를 건설한다. 시작 광산·중립 광산과 광산 군집은 맵 공정성 규칙에 따라 접근 가능해야 한다. 정확한 시작 골드·채굴 수입·건설/생산 수치는 [StatsReference](StatsReference.md#자원-시스템), 배치·광산 공정성은 [무작위 맵 규칙](GameSystemRules/GameSystemRules_RandomMap.md)을 따른다. [이전 상세 수치·좌표 설명](History/ImplementationVerificationHistory.md#role-maintenance-20261016-r2-gdd-economy).

## 🏗️ 건물 시스템

건물은 경제·생산·방어·직접 스킬·팀 강화·회복으로 역할을 나눈다. 현재 종족별 자산명·단계·비용·HP는 [StatsReference](StatsReference.md), 자산과 enum 대응은 [AssetList](Assets/AssetList.md)가 원본이다.

### 1. 유닛 생산 건물 (Barracks)

유닛을 자동/수동 생산하고 랠리 목표를 정하는 전선의 거점이다. 단계 상승은 상위 유닛을 해금하는 전략 투자다. 생산 큐·업그레이드·철거·환불의 정확한 동작은 [건물 패널 규칙](GameSystemRules/GameSystemRules_BuildingPanelsUI.md)과 [건물 규칙](GameSystemRules/GameSystemRules_Buildings.md)을 따른다.

### 2. 자원 건물 (Resource Collector / MiningPost)

광산에 채굴소를 세워 지속 수입을 얻는다. 광산 접근과 영토 확장이 경제 경쟁을 만든다. 채굴소 등급 업그레이드는 현재 지원하지 않으며 이전 확장안은 [미확정 건물 기획](#미확정-건물-기획)에 남긴다. AI 수입 배율은 난이도 설정과 별개로 구분한다.

### 3. 스킬 건물 (Skill Building)

플레이어가 직접 전장에 피해·상태변경·회복을 발동하는 수단이다. 마나 없이 건물별 쿨다운을 사용하며, 종족별 스킬셋으로 전략 차이를 만든다. 공통 메커니즘·패널·조준은 [스킬 규칙](GameSystemRules/GameSystemRules_Skills.md), 구체 목록·수치·아이콘은 아직 미확정이다.

### 4. 방어 타워 (AutoTower)

고정 위치에서 적을 자동 공격해 전선을 지킨다. 종족별 타워는 AutoTower를 공유하되 표현은 종족 키로 선택한다. Transcendence 타워는 **VineTower**이며 MistShrine과 별개다. 타워 단계 확장은 별도 기획 대상이다. [동작 원본](GameSystemRules/GameSystemRules_Buildings.md#방어-타워-시스템).

### 5. MistShrine (물안개 신전) — 초월 전용 힐 건물

공격하지 않는 회복 건물이다. 건물 중심 물안개 범위 안의 아군 유닛·건물(Castle·시전자 포함)을 지속 회복하며 범위 밖에서는 끊긴다. 물안개끼리는 중첩하지 않고 연구소 자연회복과는 함께 적용한다. 수동/자동 시전과 범위·지속/쿨다운·중첩의 상세 계약은 [물안개 규칙](GameSystemRules/GameSystemRules_Buildings.md#mistshrine-물안개-힐-시스템), 패널은 [건물 패널](GameSystemRules/GameSystemRules_BuildingPanelsUI.md)을 따른다. 효과 수치는 임시이며 밸런싱 미확정이다.

### 6. 연구소 (Research Lab) — 유닛 강화 시스템

골드와 시간을 투자해 자기 팀 유닛을 강화하며 완료 효과는 이미 생산된 유닛에도 소급 적용한다. 공격·방어·이동과 초월 전용 자연회복을 종족별 그룹 트랙으로 구성한다. 연구소는 단계 업그레이드 대신 병렬 연구 거점으로 사용한다. [강화·연구 패널 원본](GameSystemRules/GameSystemRules_Upgrade.md)·[수치표](StatsReference.md)를 따른다.

### 본기지 (Main Base)

파괴되면 패배하는 핵심 목표다. 종족별 HP를 가지며 현재 공격·골드 수리·Lv2~5 확장은 지원하지 않는다. MistShrine의 회복 대상이 될 수 있다는 점과 직접 수리 조작은 구분한다. 옛 확장 아이디어는 [미확정 기획](#미확정-건물-기획)으로 보존한다.

상세 규칙·수치 사본과 과거 정정 과정은 [기존 건물 기획 원문](History/ImplementationVerificationHistory.md#role-maintenance-20261016-r2-gdd-buildings)에 보존한다. 현재 구현·검증은 [PROJECT_STATUS](PROJECT_STATUS.md)를 따른다.

## 🪖 유닛 시스템

### 유닛의 역할과 흐름

플레이어는 유닛을 직접 조작하지 않고 생산·랠리·배치로 전선을 운영한다. 유닛은 목표로 자동 이동하며 적을 발견하면 전투하고 타일 도착으로 영토를 넓힌다. 이동 중 다른 유닛의 현재·선점 타일은 A* 차단 근거가 아니며 겹침을 허용한다. 생성 시 점유 자격은 이동과 별도다. [이동·공격 원본](GameSystemRules/GameSystemRules_Units.md).

권총병은 저비용 러시, 돌격소총병은 범용 주력, 저격총병은 느린 고화력 원거리라는 역할을 가진다. 전체 종족 roster·기본 수치·타격/주기는 [StatsReference](StatsReference.md), 실제 클립·설정·수용은 [전투 감사표](Assets/UnitCombatAssetMatrix.md)에서 관리한다. 이 기획 요약은 밸런싱 확정을 뜻하지 않는다.

### 특수 유닛 능력 설계

| 유닛 | 전장에서 만드는 차이 |
|---|---|
| BattleAxe | 정면에 뭉친 적 유닛을 부채꼴로 쓸어내는 근접 광역 딜러. 주 타깃 중복 피해·건물 AoE는 제외 |
| TorrentSpirit | 앞으로 이동하는 파도 전선이 적 유닛·건물에 피해, 아군 유닛에 회복. 기본 단일 공격 없는 special-only이며 파도당 대상별 한 번 |
| BloomFairy | 적을 공격하지 않는 순수 힐러. 부상 아군 유닛(자신 포함)을 고르고 HoT를 부여. 준비 뒤부터 쿨다운을 세는 별도 힐 예외 유지 |
| MushroomBomber | 주 타깃 직접 피해와 착탄 주변 적 유닛 DoT를 결합. 건물은 직접 피해만 받으며 지면 damage zone은 없음 |
| InfernoSpirit | 범위 피해 없이 맞힌 주 타깃에게 지속 피해. 적 건물에는 직접 피해만 |
| QuakeSpirit | 주 타깃과 주변의 피해 배율을 구분하는 즉발 원형 공격. 주변 적 건물도 스플래시 대상 |

아군에게 피해를 주지 않으며 판정·피해·회복은 권위 경로가 결정한다. 정확한 범위·타깃·중복 제외·힐 예외는 [유닛 규칙](GameSystemRules/GameSystemRules_Units.md)의 특수 공격 계약, 멀티 시각/회차는 [동기화 규칙](GameSystemRules/GameSystemRules_UnitCombatSynchronization.md), 수치와 선택 경계는 StatsReference를 따른다. [이전 상세 사본·기획 설명](History/ImplementationVerificationHistory.md#role-maintenance-20261016-r2-gdd-units).

## 🌍 종족 시스템

### 인간계 (Human)
**컨셉**: 중세~현대 무기 기반 군대

**유닛 예시**:
- 검사, 창병, 궁수
- 권총병, 기관총병, 저격수
- 기병, 탱크

**종족 특성**:
- 균형잡힌 스탯
- 생산 속도 +10%
- 범용성 높음

---

### 정령계 (Spirit)

## 🗺️ 타일 시스템

### 타일과 영토

헥스 타일의 소유권(중립·Blue·Red)과 지형/건설 자격은 독립이다. 유닛 도착과 건물 주변 확장으로 영토를 넓히고 보유 타일이 인구를 만든다. 이동 가능한 건설 금지 구역과 이동·선택·점령이 불가능한 완전 차단 지형을 구분한다. 광산은 이동 불가이며 조건을 만족하는 채굴소만 건설한다.

### 이동·생성과 동적 차단

다른 유닛 점유·선점은 이동 차단 목록에 넣지 않는다. 건물·정적 지형·광산의 차단과 스폰 시 점유 검사는 별개다. 동적 건물로 막히면 우회 경로를 찾고 적 건물 공격 또는 아군 PathBlocked로 처리한다. 같은 목표의 재평가·환경 revision·정지 모션은 [유닛 규칙 45](GameSystemRules/GameSystemRules_Units.md#유닛-이동-시스템)가 원본이다.

### 무작위 대전 맵 (확정 기획)

현재 범위는 FlatTop 11×21이며 맵 생성 요소는 정확한 180도 대칭을 따른다. 두 팀은 동일 맵·초기 경제·접근 공정성에서 경쟁하며 전투 진입 전에 내부 seed·맵 유형·미리보기를 공개하지 않는다. 유형별 고유 경험은 다음과 같다.

| 유형 | 핵심 경험 |
|---|---|
| 완전개방 | 지형 개입 없이 병력과 경제 판단을 비교하는 기준 전장 |
| 장애물 개방 | 열린 전장에 분산 장애물로 경로·교전 지점 변화 |
| 협곡 | 좁아지는 중앙 통로의 정면 충돌 |
| 외곽 | 중앙 차단을 둘러싼 좌우 병력 분배 |
| 3갈래 | 세 통로의 병력 배분과 합류 판단 |

좌표·광산·폭·확률·초기 공간·폴백 값은 [맵 공정성](GameSystemRules/GameSystemRules_Map.md)과 [무작위 맵 규칙](GameSystemRules/GameSystemRules_RandomMap.md)이 단일 원본이다. 실패한 후보 때문에 최초 선택 확률을 바꾸지 않고 검증된 유형별 폴백을 사용한다. 맵 상성 밸런스는 생성 공정성과 별도다. 데이터·전송은 [네트워크 TDD](TechnicalDesignDocument_Network.md)를 따른다.

### 재경기 맵 선택

싱글·멀티 모두 매번 새 무작위 맵을 준비하고 같은 맵/새 맵 선택 UI를 두지 않는다. 우연히 같은 전장이나 폴백이 연속 나오는 것은 허용하며 기록으로 구분한다. 팀·종족 등 경기 설정은 유지한다. 준비 실패 시 화면·기존 맵·연결 복구는 [경기 운영](GameSystemRules/GameSystemRules_MatchFlow.md)과 [경기 UI](GameSystemRules/GameSystemRules_MatchFlowUI.md)를 따른다. 최초 멀티 실패의 로비 복귀와 싱글 재시도 선택은 구분한다.

상세 타일/맵/전송 사본과 과거 설계 변경은 [이전 원문](History/ImplementationVerificationHistory.md#role-maintenance-20261016-r2-gdd-tiles)에 보존한다.

## ⚙️ 생산 시스템

### 자동·수동 생산의 목적

자동 생산은 원하는 유닛 조합을 반복해 전선 관리를 줄이고, 수동 생산은 당장 필요한 유닛을 끼워 넣는 선택이다. 길게 누르기로 자동 등록·해제, 짧은 탭으로 수동 등록한다. 모드 해제로 이미 차감한 생산을 잃지 않고 수동 큐로 이관한다.

### 생산에서 전선까지

골드·인구 자격과 큐 진행, 생성 타일 대기, 완료 후 자동 이동을 구분한다. 랠리를 지정하면 그 근처로 모이고 이후 적 Castle을 향해 진군한다. 랠리 해제·마커·스폰 대기·자동 자원 부족·슬롯 취소/환불 등 정확한 조건은 [생산 패널 규칙](GameSystemRules/GameSystemRules_BuildingPanelsUI.md)과 [건물 랠리 규칙](GameSystemRules/GameSystemRules_Buildings.md)을 따른다.

패널 배치는 생산 가능한 타입·잠금·큐·진행·골드/인구를 한곳에서 읽게 한다. 시각 예시는 [UI 가이드](UIGuidelines.md), 연결 구조는 [TDD](TechnicalDesignDocument.md), 시간·비용은 [StatsReference](StatsReference.md)를 따른다. [기존 상세 사본·개정·UI 예시](History/ImplementationVerificationHistory.md#role-maintenance-20261016-r2-gdd-production).
