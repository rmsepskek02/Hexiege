## 🎮 게임 개요

### 기본 정보
- **장르**: 실시간 전략 게임 (RTS)
- **플랫폼**: 모바일 (Android/iOS)
- **화면 방향**: 세로 모드 (Portrait)
- **플레이 모드**: PvP 1v1 실시간 매칭
- **평균 플레이 타임**: 10분 (서든데스 2분 포함, 최대 12분)

### 핵심 컨셉
육각형 타일맵 기반의 공성전 RTS 게임. 플레이어는 건물을 건설하고 유닛을 생산하여 상대방의 본기지를 파괴하는 것이 목표입니다. 유닛은 AI로 자동 제어되며, 플레이어는 전략적 건물 배치와 생산 관리에 집중합니다.

### 차별화 포인트
- 육각형 타일 기반 공간 전략
- 타일 점령 = 인구수 확장 메커니즘
- 자동/수동 생산 하이브리드 시스템
- 3종족 고유 특성

### 비주얼 스타일
- **그래픽**: 3D 이소메트릭 (Clash of Clans/Royale 스타일 카툰)
- **아트 방향**: 밝고 친근한 느낌
- **뷰**: Orthographic 55도 틸트 3D

### 카메라 시스템
- **기본 뷰**: Orthographic + X축 55도 틸트 (이소메트릭)
- **화면 이동**: 한 손가락 드래그 (Pan)
- **확대/축소**: 두 손가락 핀치 (Zoom)
- **줌 범위**: 최소 0.5x ~ 최대 2.0x (조정 가능)
- **이동 제한**: 맵 경계 내로 제한

## 🎯 핵심 게임플레이

### 게임 흐름
```
게임 시작
  ↓
초기 타일 할당 (7~10개)
  ↓
자원 수집 (자원 건물 건설)
  ↓
유닛 생산 (생산 건물 + 랠리 설정)
  ↓
타일 점령 확장 (인구수 증가)
  ↓
전선 관리 (방어타워, 마법)
  ↓
업그레이드 투자
  ↓
상대 본기지 공격
  ↓
승리!
```

### 플레이어 행동
1. **건물 건설**: 타일 선택 → 건물 타입 선택 → 건설
2. **유닛 생산**: 생산 건물 선택 → 유닛 타입 설정 (자동/수동)
3. **랠리 포인트**: 생산 건물 → 타일 지정
4. **마법 사용**: 스킬 건물 → 마법 선택 → 타겟 지정
5. **건물 업그레이드**: 건물 선택 → 업그레이드 버튼

### 인구수 시스템
**공식**: `총 인구수 = 보유 타일 수`

**인구 소비**:
- 건물: 각 1 인구
- 유닛: 각 1 인구

**예시**:
```
보유 타일: 20개
건물: 본기지(1) + 생산건물(3) + 타워(1) = 5개
사용 가능 인구: 20 - 5 = 15마리 유닛
```

> **구현 현황:** `PopulationUseCase`가 `HexGrid.CountTilesOwnedBy()`로 최대 인구를, 유닛+건물 수로 사용 인구를 실시간 계산.

### 자원 시스템
**골드 (인게임 자원)**:
- 시작 골드(확정 기획, 미구현): 무작위 맵의 중립 광산 수에 따라 200~700 (광산 1~6개에 각각 700/600/500/400/300/200)
- 맵 경제 테스트 모드(확정 기획, 미구현): `MapTestModeEnabled=true`일 때만 실제 시작 골드 5000. 초기 골드 외 규칙에는 영향 없음
- 싱글은 로컬 설정, 멀티는 Host 설정이 권위이며 Client도 Host가 확정한 실제 시작 골드를 동일하게 적용
- 기본 수입: 0 골드/초 (채굴소 없이는 수입 없음)
- 채굴소(MiningPost) 건설 시 초당 10 골드 수입
- 시작 광산과 중립 광산의 기본 채굴량은 모두 10 골드/초로 동일하며, 차등 채굴량은 추후 확장 시 검토
- 건물 건설/유닛 생산에 소비

**금광 (Gold Mine)**:
- 맵에 배치되는 자원 오브젝트이며, 팀별 시작 광산과 경쟁 대상인 중립 광산으로 구분
- 금광 타일은 **이동 불가** (유닛 통과 불가)
- 금광 타일은 일반 건물 건설 불가, 채굴소만 건설 가능
- 건설 조건: 인접 6타일 중 최소 1개가 자기 팀 소유
- 유효 광산은 도달 가능한 이동 가능 인접 타일이 1개 이상이면 되며, 광산 군집을 허용
- 시작 광산: 팀별 1개와 초기 채굴소 1개. Blue/Red `(3,19)/(7,1)` 또는 `(7,19)/(3,1)` 중 무작위 선택
- 중립 광산: 맵 유형에 따라 1~6개. 홀수는 중앙 단독 1개+대응쌍, 짝수는 모두 180도 대응쌍
- 중앙 단독 광산은 양 성에서 같은 접근거리, 대응 광산 쌍은 교차 접근거리가 같아야 함

**건물 비용**:
| 건물 | 비용 |
|------|------|
| 배럭 (Barracks) | 100 골드 |
| 채굴소 (MiningPost) | 50 골드 |

**유닛 생산 비용**:
| 유닛 | 비용 | 생산 시간 | 인구 |
|------|------|-----------|------|
| 권총병 (Pistoleer) | 50 골드 | 5초 | 1 |
| 돌격소총병 (Assault) | 100 골드 | 10초 | 1 |
| 저격총병 (Sniper) | 200 골드 | 15초 | 1 |

> **현재 구현 현황:** `ResourceUseCase`가 팀별 골드를 관리. `ProductionTicker`가 매 프레임 `TickIncome()`으로 채굴소 수입 누적. 건물 배치 시 골드 차감 검증, 유닛 생산 시 골드+인구 검증 후 차감. 기존 런타임은 금광 상태에 `HexTile.HasGoldMine`을 사용한다. 무작위 맵 목표 모델의 `TerrainKind`·`BuildRule`·`MineKind`·`HasBuilding` 분리와 계산형 `IsWalkable`은 확정 설계이며 미구현이다.

### 3. 스킬 건물 (Skill Building)

각 종족의 액티브 스킬을 사용하는 특수 건물. 종족별 자산명은 Human `FlightFacility`, Spirit `MagicSpirit`, Transcendence `WillowShrine`. (Spirit·Transcendence는 enum `MagicBuilding`을 공유하며 스킬셋은 종족 키로 분기.)

**핵심 설계 (요약)**:
- 자원: **마나 없음, 쿨다운만**. 쿨다운은 **건물별 글로벌**(스킬 1개 사용 시 그 건물의 모든 스킬 버튼이 함께 잠김).
- 건물당 **최대 5개** 스킬. **건물 업그레이드 없음** → 건설 즉시 전부 사용 가능.
- UI: 범용 `BuildingActionPanelUI` 3×3 그리드 재사용(스킬 1~5 / 철거 6 / 예약 7~9).
- 스킬 타입 3종: ① 즉발 범위 피해 ② 범위 지속 피해(장판 DoT) ③ 전역 상태변경(버프·디버프·제어·회복 통합).
- 발동: 즉시 발동(타입 ③) / 지점 지정(타입 ①·②, 모바일 조준 — 스킬 버튼 탭으로 조준 모드 진입 → 화면 드래그로 범위 이동 → 손 떼면 발동, 하단 X로 취소. 상세는 Skills 문서).
- 멀티플레이: 서버 권위(좌표만 RPC 전송 후 서버 재검증).

**비용**: 200 골드 (세 스킬 건물 공통 — 권위 소스 `Resources/Config/BuildingStatsConfig.asset` 런타임 실제값)

> **상세 규칙은 단일 소스 문서 참조:** [GameSystemRules_Skills.md](GameSystemRules/GameSystemRules_Skills.md)
> **구현 상태: 기획 확정 / 미구현** (구체 스킬 목록·수치는 추후 데이터로 확정). 현재는 배치·피격만 되는 시각 오브젝트 + 철거 버튼 공유 상태.

### 4. 방어 타워 (AutoTower) ✅ 구현 완료 (2026-06-01)

**기능**:
- 자동 공격 (고정 위치, 서버 권위 처리)
- 사거리 내 가장 가까운 적 유닛 자동 타게팅
- 배치 즉시 공격 가능 (쿨다운 0 초기값)

**종족별 스탯** (수치의 권위 소스는 `StatsReference.md` — 아래는 ×10 스케일 값):
- Human(CannonTower): 공격력 150 / 쿨다운 5.0s / 상대 진영 방향 초기 회전
- Spirit(RuneSpire): 공격력 150 / 쿨다운 3.5s (전 종족 중 최단)
- Transcendence(**VineTower**): 공격력 150 / 쿨다운 5.0s

**공통 사거리**: 4.0타일

> **⚠️ 2026-08-10 정정:** 이 문서는 이전까지 Transcendence의 방어 타워를 **MistShrine**으로 잘못 적고 있었다(범위 힐 기능이 딸린 타워로 서술).
> **Transcendence 방어 타워는 `VineTower`이며, MistShrine은 공격하지 않는 별도 힐 건물(`BuildingType.HealShrine` = 6)이다.**
> 방어 타워는 3종족 모두 `BuildingType.AutoTower`(= 2)로, 두 건물은 enum부터 별개다.
> MistShrine은 아래 §5 참조.

> **미구현**: 방어 타워 업그레이드(단계 확장)는 별도 작업 예정. (스킬 건물의 스킬 기능은 위 §3 스킬 건물 및 [GameSystemRules_Skills.md](GameSystemRules/GameSystemRules_Skills.md) 참조 — 방어 타워 `RuneSpire`와 스킬 건물 `MagicSpirit`은 별개 건물.)

### 5. MistShrine (물안개 신전) — 초월 전용 힐 건물 ⏳ 기획 확정 / 구현 미착수 (2026-08-10 재설계)

**공격하지 않는 회복 건물**이다. 플레이어가 사용하면 건물 주변에 **물안개**가 깔리고,
물안개가 유지되는 동안 그 안의 **아군 유닛과 아군 건물이 매초 체력을 회복**한다.
물안개가 걷히면 회복이 멈추고, 남은 쿨다운이 지나야 다시 쓸 수 있다.

**핵심 컨셉**:
- **방어 타워가 아니다** — 별도 건물 분류 `BuildingType.HealShrine`(= 6). Transcendence 방어 타워는 VineTower(§4).
- **회복 대상 = 아군 유닛 + 아군 건물 모두.** 시전한 MistShrine 자신과 본기지(Castle)도 포함된다.
- **범위 = 건물 중심 고정 원형.** 지점 조준이 없어 플레이어가 위치를 고를 수 없다(스킬 건물과의 차이).
- **아우라 방식** — 물안개 지속 중 범위 안에 있으면 회복을 받고, 범위를 벗어나면 즉시 끊긴다(시전 시점 스냅샷 아님).
- **1초 단위 회복 틱.** 최대 체력인 대상은 회복되지 않는다.
- **물안개 지속시간 < 쿨다운** — 다시 쓸 수 있을 때까지 공백(다운타임)이 존재한다.
- **시전 비용 없음** — 쿨다운으로만 사용 빈도를 제어한다.
- **시전 건물이 파괴되면 물안개도 즉시 사라진다.**
- **물안개끼리는 중첩되지 않는다** — 여러 물안개 범위에 겹쳐 있어도 효과는 하나만(더 가까운 건물, 거리가 같으면 건물 Id가 작은 쪽).
- **연구소 자연회복(초월 전용 강화)과는 별개 효과이며 중첩되어 함께 적용된다.**

**조작**: 아군 MistShrine을 클릭하면 전용 패널이 열린다. **짧은 탭 = 수동 시전 / 길게 누르기 = 자동 모드 토글**(생산 패널과 동일한 조작).
**자동 모드 기본값은 OFF**이며, 자동 모드 중 짧은 탭은 자동 모드 해제로 처리한다.
패널이 열려 있는 동안에만 반투명 원형으로 회복 범위를 표시하며, **적 MistShrine은 클릭해도 범위를 보여주지 않는다**(정보 우위 방지).

**밸런싱 미확정**: 회복량 · 물안개 지속시간 · 쿨다운 · 범위 반경 · 회복 텍스트 표시 주기(임시 3초)는 **전부 미확정**이다.
현재 `StatsReference.md`의 값(HP 500 / 건설비 100 / 10 HP/s · 범위 3)은 재설계 이전 수치이며 밸런싱 재검토 대상이다.

> **상세 규칙은 단일 소스 문서 참조:** [GameSystemRules_Buildings.md](GameSystemRules/GameSystemRules_Buildings.md) — **MistShrine 물안개 힐 시스템** (UI 규칙은 [GameSystemRules_UI.md](GameSystemRules/GameSystemRules_UI.md) MistShrine 패널 UI)
> **구현 상태: 기획 확정 / 구현 미착수.** 코드·전용 패널·범위 표시 UI·물안개 VFX 어느 것도 아직 없다(물안개 VFX는 신규 제작 필요).

### 특수 유닛 능력 설계

일반 유닛은 "타겟 1마리를 때린다"가 전부지만, **특수 유닛**은 그 위에 고유한 능력(범위 피해, 지속 피해, 회복 등)을 더한다. 이 절은 그 6종의 **능력이 무엇을·어떻게·왜 작동하는지를 기획 관점에서** 정리한 것이다. 정확한 판정 알고리즘·코드 구조·동기화 처리 같은 **구현 규칙**은 `GameSystemRules/GameSystemRules_Units.md`(규칙 23~42)가 단일 권위 소스이며, 이 절은 그 규칙 번호를 참조로 연결한다. 수치는 `StatsReference.md`(스탯 권위 소스)와 일치한다.

특수 유닛은 능력의 판정 형태로 나누면 다음과 같다.

- **휩쓸기형** — 공격자 앞 부채꼴을 즉시 쓸어 피해 (BattleAxe)
- **착탄형** — 목표 지점에 떨어져 그 주변 원형 범위에 피해 (MushroomBomber, QuakeSpirit)
- **파도형** — 앞으로 밀려나가는 전선이 닿는 대상에 피해/회복 (TorrentSpirit)
- **단일 지속 피해(DoT)** — 때린 딱 1마리에게 시간에 걸쳐 추가 피해 (InfernoSpirit)
- **힐러** — 적을 때리지 않고 부상 아군을 회복 (BloomFairy)

> 공통 원칙: 아군에게는 피해가 없다(기본 규칙 16). 모든 판정·피해·회복은 서버가 최종 결정한다(서버 권위, 규칙 18). 범위 판정은 헥스 타일 소속이 아니라 **월드 좌표(실제 3D 거리)** 기준으로 처리한다(규칙 6·24).

#### 1. BattleAxe (도끼병) — 휩쓸기형 즉발 AoE

큰 도끼로 눈앞을 한 번에 쓸어버리는 근접 광역 딜러다. 한 번 휘두르면 주 타깃뿐 아니라 **공격자 정면 부채꼴 안에 있는 적 유닛 전원**이 동시에 같은 피해를 받는다. 여러 적이 좁은 통로에 뭉쳐 밀고 들어올 때 특히 강하다.

- **판정 형태**: 공격자 → 주 타깃 방향을 기준으로 한 **전방 부채꼴**. 반경 `sweepReach`(실기값 0.75), 부채꼴 반각 120°. 부채꼴 안의 적 유닛 전원에게 **동일 피해(공격력 15)**를 즉시 적용한다.
- **주 타깃 vs 부채꼴**: 주 타깃은 기본 단일 피해로 처리하고, 부채꼴은 그 외의 적 유닛을 추가로 쓸어담는다(주 타깃 중복 피해 없음).
- **제외 대상**: 아군·사망 유닛·공격자 자신·등 뒤의 적(각도로 자연 제외). **건물은 부채꼴 대상이 아니며**, 건물이 주 타깃일 때만 단일 피해를 받는다.
- 상세 규칙: 규칙 23~27.

---

#### 2. TorrentSpirit (물의 상급 정령) — 파도형 이동 AoE + 힐

앞으로 밀려나가는 거대한 물결로 **적은 쓸어 피해를 주고 아군은 회복시키는** 양면 정령이다. 단일 대상 기본 공격이 아예 없고(**special-only**), 파도 자체가 공격의 전부다. 전선을 밀면서 아군을 살리고 적을 깎는 지원형 딜러다.

- **판정 형태**: 전방으로 이동하는 **월드 직사각형 전선**(폭·전방 길이·이동 시간을 가진 파도). 전선이 지나가며 닿는 대상에게 효과를 준다.
- **대상별 효과**: **적 유닛·적 건물 = 피해 20**, **아군 유닛 = 힐 10**. 각 대상은 한 번의 파도로 **1회만** 영향을 받는다(아군 건물은 힐 대상 아님).
- **special-only의 의미**: 단일 공격이 없으므로 파도 판정이 **건물도 반드시 훑어야** 성(승리 조건)을 깎을 수 있다.
- **힐 서브시스템**: 이 유닛을 위해 "아군 회복" 채널을 신설했다(피해와 분리된 별도 연출·동기화). 이후 BloomFairy가 공유한다.
- 상세 규칙: 규칙 28~31.

---

#### 3. BloomFairy (꽃요정) — 힐러 (공격 불가)

적을 전혀 때리지 않고 **부상당한 아군을 회복시키는 순수 힐러**다. 지금까지의 특수 유닛과 근본적으로 다르며, 적 공격 흐름과 완전히 분리된 **힐러 전용 경로**로 동작한다.

- **회복 방식**: 사거리(4.0타일) 안의 부상 아군 중 **잃은 체력 비율이 가장 큰 대상**(동률이면 가장 가까운 대상)을 골라, **3초에 걸쳐 총 20 HP를 서서히 회복**시킨다(HoT). **본인도 회복 대상에 포함**되며, 회복 대상은 **아군 유닛만**(건물 제외)이다.
- **유휴 감시**: A* 경로 끝(최전선)에 도달해 더 갈 곳이 없어도 멈추지 않고, 사거리 안에 부상 아군이 생기면 즉시 다시 힐한다.
- **⚠️ 쿨다운 예외(의도된 설계)**: 다른 모든 유닛은 쿨다운이 "발동 준비 시간을 포함한 전체 주기"지만, **BloomFairy만** 힐이 실제로 발동된 **뒤부터** 쿨다운(3.0초)을 센다. 그래서 실제 힐 주기는 **발동 준비 1.0초 + 쿨다운 3.0초 = 4.0초**다. "힐 한 번 걸고 3초 쉰다"는 체감이 핵심이므로, 이 예외는 확정 설계이며 다른 유닛과 같게 되돌리지 않는다.
- 상세 규칙: 규칙 32~37.

---

#### 4. MushroomBomber (버섯폭격기) — 착탄형 범위 DoT

포자 폭탄을 던져 **착탄 지점에서 폭발**시키는 착탄형 범위 딜러다. 폭발은 두 가지 피해를 동시에 준다 — 폭탄을 맞은 1마리에게 즉시 들어가는 **직접 피해**, 그리고 폭발 반경 안 적 유닛 전원에게 시간에 걸쳐 뚝뚝 들어가는 **지속 피해(DoT)**다.

- **직접 피해**: 주 타깃 1마리에게 **직접 10**(기본 단일 피해, 건물 공성 포함).
- **범위 DoT**: 착탄 중심 기준 **월드 원형 반경**(기본 1.0 = 인접 1칸) 안의 **적 유닛 전원**에게 **초당 2씩 3초간(총 6)** DoT를 건다. DoT는 **1초 간격으로 뚝뚝** 들어가며, 매초 남은 체력이 데미지 텍스트로 표시된다.
- **건물 처리**: **건물은 DoT를 받지 않는다**(직접 피해만). 단, 주 타깃이 건물이어도 폭발은 항상 터지므로 반경 안의 주변 적 유닛에게는 DoT가 걸린다.
- 상세 규칙: 규칙 38~40.

---

#### 5. InfernoSpirit (지옥불 정령) — 단일 대상 on-hit DoT

원거리로 적을 포격하는 고화력 정령으로, **때린 그 1마리에게만 지속 피해를 추가로 남긴다.** MushroomBomber와 달리 **범위가 없다** — AoE가 아니라 주 타깃 단일 대상이다.

- **직접 피해**: 원거리 공격이 주 타깃에게 **직접 25**(기본 단일 피해, 건물 공성 포함).
- **단일 DoT**: 그 **주 타깃 1마리에게만** **초당 5씩 3초간(총 15)** DoT를 추가로 건다(반경 없음). DoT 거동(1초 간격·매초 남은 체력 텍스트·갱신 시 리셋)은 MushroomBomber와 공유하되, 수치는 별도로 분리 관리된다.
- **대상 제한**: DoT는 **적 유닛만** 받는다. 건물이 주 타깃이면 직접 25만 들어가고 DoT는 걸리지 않는다.
- 상세 규칙: 규칙 41~42.

---

#### 6. QuakeSpirit (대지의 정령) — 착탄형 즉발 2단계 AoE

대지를 내리찍어 **착탄 지점 주변을 즉시 뒤흔드는** 착탄형 광역 딜러다. 주 타깃은 온전한 100% 피해를, 주변은 그 절반을 한 번에(즉발) 받는다. **다른 착탄·휩쓸기 유닛과 달리 스플래시가 건물까지 타격한다**는 점이 핵심 차별점이다.

- **직접 피해(100%)**: 주 타깃 1마리에게 **20(공격력 100%)만** 적용한다(주 타깃은 스플래시에서 제외 — 중복 피해 없음).
- **스플래시(50%)**: 착탄 중심 기준 **월드 원형 반경**(`_quakeRadius` 기본 1.0 = 인접 1칸) 안의 **다른 적 유닛 + 적 건물**에게 **10(공격력의 50%, 올림)**을 즉시 적용한다.
- **⚠️ 건물도 스플래시 대상**: BattleAxe·MushroomBomber는 스플래시/부채꼴에서 건물을 제외하지만, QuakeSpirit은 반경 안 적 건물도 50% 스플래시를 받는다(공성 기여). 아군 유닛·건물은 무피해.
- **즉발**: DoT가 아니라 한 타격에 즉시 적용되는 2단계(100%/50%) 피해다.
- 구현 task: `_Tasks/2026-07-20/10_24_quakespirit-impact-aoe/`. 상세 규칙은 구현 후 `GameSystemRules_Units.md`에 별도 등재 예정.

## 🗺️ 타일 시스템

### 육각형 타일
**좌표계**: Cube Coordinates (q, r, s)
```
  / \
 |   |
  \ /
```

**타일 상태**:
1. **중립 (Neutral)**: 회색
2. **파랑 진영 (Blue)**: 파랑색
3. **빨강 진영 (Red)**: 빨강색
4. **금광 (Gold Mine)**: 금광 오버레이 표시, 이동 불가 타일
5. **건설 불가 구역 (No-Build Zone)**: 이동·점령 가능, 일반 건설 불가. 일반 타일과 같은 mesh·높이·소유권 기본 색상 위에 반투명 짙은 회색 대각선 해치 3개 표시
6. **완전 차단 지형 (Blocked Terrain)**: 좌표 데이터에는 존재하지만 standard 타일 mesh/collider 없이 빈 공간으로 표시. 이동·선택·건설·점령·파괴 불가, 시야선은 차단하지 않음

### 타일 점령 규칙
**점령 조건**:
- 유닛이 타일 위로 이동 → 즉시 해당 진영 색상으로 변경
- 건물 건설 시 인접 6타일이 건물 팀으로 자동 점령 (영토 확장)

**타일 탈환**:
- 적 타일에 유닛 진입 시 빼앗기

**타일 중립화**:
- 점령한 타일에 오브젝트 없음
- 인접한 아군 타일 없음
- 위 조건 충족 시 **10초 후 중립화**

### 타일 점유 규칙
**이동 불가 타일**:
- 건물이 있는 타일 (`IsWalkable = false`)
- 금광 타일 (현재 런타임은 `HasGoldMine`, 확정 무작위 맵 설계는 `MineKind != None`; 채굴소 건설 전후 모두 이동 불가)
- 다른 유닛이 있는 타일 (아군/적군 무관)
- **같은 팀** 유닛이 이동 중 선점한 타일 (ClaimedTile)

**적 팀 타일 경합**:
- 적 유닛의 ClaimedTile은 차단하지 않음 → 같은 타일에 적이 진입 가능
- 같은 타일에 적 유닛이 만나면 **전투**로 해결
- 타일 중앙 도착 = 전투 승리 = 점령 (패배 시 도달 불가)

**유닛 생성 불가 타일**:
- 건물이 있는 타일
- 이미 유닛이 점유 중인 타일 (아군/적군 무관)

> 경로탐색(A*) 시 모든 다른 유닛의 Position + 같은 팀 ClaimedTile이 차단 목록에 포함됩니다. 적 팀 ClaimedTile은 차단하지 않아 적과의 타일 경합이 자연스럽게 발생합니다.
> 또한 이동 중 각 스텝마다 다음 타일의 가용성을 실시간 검증하여, 경로 계산 이후 같은 팀 유닛이 해당 타일을 점유/선점한 경우 자동으로 재탐색합니다.

### 건설 불가 구역

- 협곡 중앙부, 외곽형 통로, 3갈래형 분리 대역처럼 맵 유형이 지정한 국소 구역에만 사용
- 세로 방향의 전역 보호 통로는 두지 않음
- 이동과 점령은 허용하며 소유권 색상을 표시
- 일반 건설 패널은 열리지 않고, 건설 시도는 ToastUI로 안내
- 광산 위 MiningPost 건설은 예외
- 일반 `Open` 타일과 같은 mesh·높이·Neutral/Blue/Red 기본 색상을 유지
- 표면에 반투명 짙은 회색 diagonal hatch 3개를 overlay로 표시하며 선택 highlight도 동시에 유지
- 자기 소유 NoBuild 클릭은 선택·highlight하되 건설 패널을 열지 않고 기존 패널을 닫으며 `이 타일에는 건설할 수 없습니다` 토스트 표시
- 중립·적 소유 NoBuild 클릭은 선택만 하고 토스트 없음. 건물 action과 광산 MiningPost 예외는 NoBuild보다 우선

### 완전 차단 지형 표현

- FlatTop 11×21의 좌표와 대칭·hash 데이터에는 계속 포함
- standard hex tile mesh와 collider를 만들지 않아 높낮이 차이 없는 빈 공간으로 표현
- 배경이나 하부 collider가 입력에 잡혀도 blocked 좌표는 선택되지 않음
- blocked/빈 공간 클릭은 이전 선택을 해제하고 건설 패널을 닫되 토스트와 새 타일 선택 이벤트는 없음
- 추후 obstacle asset은 빈 공간의 시각만 대체할 수 있으며 이동·선택·점령·건설 규칙은 유지

### 건물로 경로가 완전히 막힌 경우 (후속 구현)

- 적 건물이 완전히 막으면 가장 가까운 차단 적 건물을 임시 공격 대상으로 삼고, 파괴 후 원래 목적지로 재경로
- 아군 건물이 완전히 막으면 유닛은 `Blocked` 상태가 되어 걷기 첫 프레임에서 정지
- 철거·파괴·랠리 변경으로 길이 열리면 복구 후 재경로
- 건물 배치 시점의 선제적 연결성 검사는 두지 않음

### 무작위 대전 맵 (확정 기획, 구현 예정)

| 항목 | 값 |
|------|----|
| orientation / 크기 | FlatTop 11×21 |
| 회전 중심 | `(5,10)` |
| Red / Blue 성 | `(5,1)` / `(5,19)` |
| 맵 유형 | 완전개방형 / 장애물 개방형 / 협곡형 / 외곽형 / 3갈래형 |
| 유형 확률 | 각각 20% |

- 모든 타일, 광산, 정적 지형, 건설 불가 구역, 장식은 중심 기준 정확한 180도 대칭
- 장식도 존재 여부·종류·스케일·재질 변형·회전 대응이 동일하며 비대칭 예외 없음
- 성과 채굴소는 플레이어 소유 오브젝트로 맵 시각 대칭 대상이 아니며, 위치·점유 조건·초기 경제 효과만 팀별 대칭
- 전역 조명과 UI처럼 맵 생성 요소가 아닌 것은 대칭 규칙 범위 밖
- 성과 시작 채굴소가 초기 소유권을 부여한 뒤 팀별 즉시 건설 가능한 고유 타일은 정확히 10개
- PointyTop은 현재 범위 밖이며 실제 도입 시 별도 설계·검증

**유형별 핵심 경험**:

- 완전개방형: 정적 지형·건설 불가 구역 없음
- 장애물 개방형: 3~17행에 180도 대칭 장애물 군집
- 협곡형: 폭 3/5/7의 대칭 모래시계 통로, 9~11행의 내부 통행 가능 타일은 건설 불가
- 외곽형: 중심을 포함한 연결·무공동 차단 덩어리, 좌우 통로 최소 폭 3
- 3갈래형: 중앙 분리 대역에 3개 통로, 분리 대역 전체 이동 가능·건설 불가

맵은 결정적 seed로 재현한다. 경기 선택 단계에서 맵 유형, 허용 중립 광산 수, 시작 광산 방향 A/B(각 50%)를 최초 1회 선택한다. 정상 모드 초기 골드는 광산 수 표에서 파생하고, `GameConfig.MapTestModeEnabled=true`이면 실제 초기 골드는 `TestStartingGold=5000`이다. 테스트 모드는 초기 골드에만 영향을 준다. 선택값과 실제 테스트 모드 표식·초기 골드는 최대 100회 생성·검증과 폴백까지 유지하며, 재시도에서는 지형 세부 형태·중립 광산 위치·장식만 바꾼다. 실패한 후보 때문에 선택값을 다시 뽑아 최초 선택 확률을 왜곡하지 않는다. 모두 실패하면 같은 유형·광산 수·시작 광산 방향의 검증된 폴백을 사용하며, 시작 광산 A/B는 별도 전체 맵 복제 없이 기준 좌표의 좌우 대응으로 적용한다. 멀티플레이에서는 로비의 로딩 화면이 열린 동안 Host가 최종 맵 전체를 생성·검증해 Client에 전달하고, Client는 별도로 재추첨하거나 로컬 테스트 설정으로 덮어쓰지 않는다. 로딩 화면에는 맵 유형·광산 수·초기 골드·seed·전체 미리보기를 공개하지 않으며 플레이어는 전투 씬에서 실제 전장을 확인한다. 양측 맵 데이터 해시가 같을 때만 전투 씬으로 이동하며, 준비 실패 시에는 씬 전환 없이 기존 로비를 유지한다. 전투 씬에서는 이미 확정된 맵을 구성하고 양측 로드 완료 후 게임을 시작한다. seed·유형·광산 수·시작 광산 방향·테스트 모드 표식·실제 초기 골드·시도 횟수·폴백 여부·최종 해시를 기록한다. 종족/유닛의 맵 상성은 생성 공정성과 별도의 밸런스 범위다.

멀티 맵 전송은 reliable chunk를 사용한다. 준비 응답을 10초 기다리고 timeout/불완전 수신에만 같은 package 전체를 같은 nonce로 1회 재전송하며, 두 번째 10초 실패 시 중단한다. 미지원 맵 형식, 용량 초과, hash·deserialize·공정성 검증 실패, 연결 끊김은 즉시 실패하고 재전송하지 않는다. 최초 경기 실패 시 로비·연결을 유지하고 `맵 준비에 실패했습니다` 팝업에서 Retry/Leave Match를 제공한다. 어느 플레이어든 Retry할 수 있으며 새 seed로 새 맵을 준비한다. 내부 seed·유형·오류 코드는 UI에서 숨긴다.

### 재경기 맵 선택

승패 결과 화면에서 싱글·멀티플레이 모두 다음 두 선택을 제공한다.

- **같은 맵으로 재경기**: 방금 플레이한 맵을 그대로 사용
- **새 맵으로 재경기**: 새로운 무작위 맵을 생성·검증한 뒤 사용

멀티플레이는 요청 팝업에 조건을 표시하며 상대가 같은 조건을 보고 수락하거나 거절한다. 서로 다른 조건을 동시에 요청한 경우 먼저 서버에 도착한 요청 조건을 상대가 확인·수락해야 하며 자동 시작하지 않는다.

새 맵으로 재경기해도 팀·종족·그 밖의 매치 설정은 그대로 유지한다. 새 64-bit root seed에서 맵 유형, 허용 광산 수, 시작 광산 방향, 지형 세부 형태, 중립 광산 위치, 장식만 다시 정한다. Host는 새 맵 준비 시점의 테스트 모드 설정으로 실제 초기 골드를 확정하며 정상 모드는 새 광산 수 표, 테스트 모드는 5000을 사용한다. 새 후보의 canonical hash가 직전 맵과 같으면 새 맵으로 인정하지 않고 다른 새 seed로 다시 준비한다. 새 맵 생성이나 검증이 실패하면 결과 화면을 유지하고 기존 맵을 보존한다. 성공한 새 맵만 현재 맵으로 교체한 뒤 Game 씬을 재로드한다. 로비로 돌아가거나 연결이 종료되면 재경기 맵 정보는 폐기한다.

`NewMap` 실패 시 rematch pending 상태를 초기화하고 결과 화면의 자동 로비 복귀 countdown을 전체 길이로 복원하며 같은 맵/새 맵/로비 선택을 다시 제공한다. 싱글플레이 최초 실패는 Retry/로비, 새 맵 재경기 실패는 기존 결과 선택지를 복원한다.

### 생산 패널 운영 규칙

> 이 규칙은 생산 패널의 모든 동작 기준이며, 코드 수정 시 반드시 준수해야 한다. (최종 확정: 2026-03-23)

#### 전역 규칙 5가지

| # | 규칙 | 설명 |
|---|------|------|
| Rule 1 | 생산 취소 시 항상 전액 환불 | 슬롯 X 버튼으로 생산을 직접 취소할 때만 해당. 예외 없음 |
| Rule 2 | 슬롯 표시 항목은 자동 취소 후에도 생산 계속 | 슬롯에 이미 표시된(골드가 차감된) 자동 항목은 자동 순환 목록에서 제거되더라도 수동 큐로 이관되어 생산이 유지됨 |
| Rule 3 | 수동 추가 시 자동 모드 해제 | 수동 생산을 추가하면 자동 모드 인디케이터가 모두 꺼짐. 단 Rule 2에 따라 슬롯 표시 항목은 수동 큐로 이관 후 해제 |
| Rule 4 | 생산큐 최대 3개 | 현재 생산 중 + 수동 대기 항목 합산 기준. 자동 대기(골드 미차감) 항목은 이 상한에 포함되지 않음 |
| Rule 5 | 비용 차감은 슬롯에 표시되는 시점 | 자동 등록 시 슬롯에 표시 가능하면 즉시 차감, 큐가 꽉 차 있으면 슬롯 진입 시 차감 |

#### 용어 정의

| 용어 | 설명 |
|------|------|
| 슬롯 0 | 현재 생산 중인 유닛이 표시되는 위치 |
| 슬롯 1~2 | 다음 생산 대기 항목이 표시되는 위치 (화면에 보이는 큐) |
| 자동 순환 목록 | 자동생산에 등록된 유닛 타입 목록. 최대 3종. 순환 반복 생산 |
| 골드 차감 상태 | 슬롯에 표시된 자동 항목이 골드를 이미 차감한 상태 |
| 골드 미차감 상태 | 자동 등록됐지만 큐가 꽉 차 슬롯에 표시되지 않아 골드를 아직 차감하지 않은 상태 |
| 수동 큐 이관 | 슬롯에 표시 중인 자동 항목이 자동 모드 해제 시 수동 대기 큐로 넘어가 생산이 유지되는 동작 |

#### 공통 조건 (버튼 동작)

| 동작 | 조건 | 결과 |
|------|------|------|
| 유닛 버튼 탭 | 해당 유닛이 자동 순환 목록에 있음 | 자동 취소 (생산 취소 아님 — 환불 없음) |
| 유닛 버튼 탭 | 해당 유닛이 자동 순환 목록에 없음 | 수동 추가 |
| 유닛 버튼 롱프레스 | 항상 | 자동 등록/취소 토글 |
| 슬롯 X 버튼 클릭 | 항상 | 해당 슬롯 생산 취소 + 골드 환불 (Rule 1) |

### 자동 진군 (Auto-March / Siege)

생산된 유닛은 랠리포인트 도착 후 자동으로 적 Castle을 향해 진군합니다.

**흐름:**
```
유닛 생산 완료
  ↓
랠리포인트로 이동 (설정된 경우)
  ↓
적 Castle 방향으로 자동 진군 (BFS 경로)
  ↓
Castle 근처 도착 → 공성 상태 진입
  ↓
매 1초마다 Castle에 더 가까운 빈 타일이 있으면 전진
  ↓
Castle 바로 옆(인접 1칸)에 도달하면 공성 완료 → 정지
```

- 랠리포인트가 없으면 생산 직후 바로 적 Castle 방향으로 이동
- 공성 중 사망하면 공성 목록에서 자동 제거
- 유닛은 전투(사거리 내 적 공격)와 진군을 동시에 수행
