**🔴 2026-09-14 (4차) 갱신 — 재경기 맵 규칙(규칙 14)이 개정됐다. 그 결과 ① 아래 3단계 행의 ㉮ 에서 **없어진 작업 3건**을 표시했고 ② **「경기 종료 후 UI·프로세스」 행 1개를 새로 세웠다**(코드 변경 없음, 문서만).** 🔴 **개정 내용**: *"재경기는 「같은 맵 / 새 맵」을 따로 선택하지 않고, 무조건 무작위로 새 맵이 결정된다. 추가 UI나 작업도 필요 없다"*(사용자 확정). 그에 따라 `SameMap`/`NewMap` 조건, 상대 팝업의 조건 표시, 「서로 다른 mode 동시 요청 시 자동 시작 금지」, 「새 후보의 해시가 직전과 같으면 폐기」 조항이 규칙에서 제거됐다 — **제거 근거의 단일 소스는 `GameSystemRules/GameSystemRules_RandomMap.md` 규칙 14 의 개정 블록**이며 여기에 옮겨 적지 않는다.

- ✅ **이 개정으로 해소된 것 4가지** — 다음 사람이 남은 일로 오해하지 않도록 못 박아 둔다.
  - **UI 자산 작업이 불필요해졌다** — `GameEndUI` 세 번째 버튼도, `RematchRequestPopup` 의 조건 표시 텍스트 슬롯도 만들 필요가 없다.
  - **요청·수락 절차 수정이 불필요해졌다** — 고를 조건이 없으므로 현재 요청/수락/거절 흐름을 그대로 쓴다.
  - **싱글플레이 코드 변경 0건** — 싱글 재경기는 **이미 매 판 새 맵을 만든다**(다시하기 → 맵 로드 직접 호출 → 호출마다 새 root seed. 문서 작업 중 직접 실측). 규칙을 현실에 맞춘 것이지 새 사양이 아니다.
  - 🔴 **「현재 코드가 규칙 14 위반」이 해소됐다** — 종전 규칙의 「자동 시작 금지」 조항 때문에 *두 번째 요청을 받는 즉시 재경기를 시작하는* 현재 코드가 규칙 위반이었는데, **그 조항이 사라져 현재 동작이 그대로 규칙이 된다.**
- ⚠️ **맵 생성기가 폴백으로 넘어가는 경우를 로그로 확인한다는 요구는 추가 작업이 없다** — `MapPreparationUsedFallbackTemplate`(Warn) 키가 이미 존재한다.

**🔴 2026-09-14 (3차) 갱신 — 재경기 맵 조사 중 드러난 결과 화면 UI 문제 1건을 「나중에 작업할 사항」으로 아래 우선순위 표에 행 1개로 등록했다(코드 변경 없음, 문서만).** 🔴 **이 문제는 맵과 무관하다** — 결과 화면의 재경기 요청 UI 동작 계통이며, **같은 맵이든 새 맵이든, 맵을 아예 바꾸지 않아도 똑같이 발생한다.** **이번 재경기 맵 작업(규칙 14)이 만든 문제가 아니라 기존 동작**이고, **사용자가 이 점을 명시적으로 확인한 뒤 이번 작업 범위에서 뺐다.** 그래서 **아래 3단계 맵 행의 ㉮(재경기)에 묻지 않고 별도 행으로 세웠다** — 맵 행에 넣으면 맵 작업을 하는 사람만 보게 되어 다음 사람이 찾지 못한다. **행을 세우는 근거**는 사용자가 *"문서에 문제에 대한 내용만 기록하고 **나중에 작업할 사항**으로 남겨둬"* 라고 확정했고 **이 문서의 역할이 바로 「앞으로 해야 할 작업」**이기 때문이다. ⚠️ **심각도는 확정하지 못했다 — 미확인 2건이 남아 있다**(행 안에 적었다. CLAUDE.md 규칙 10).

**🔴 2026-09-14 (2차) 갱신 — 초기 골드와 맵 테스트 모드의 처분이 확정돼, 아래 우선순위 표에 행 2개를 새로 세웠다(코드 변경 없음, 문서만).** 종전에는 「초기 골드 미적용」을 **행으로 세우지 않고 사실만 적었는데**, 그 이유가 *"사용자가 범위로 고르지 않았고 「하지 말라」인지 「이번엔 아니다」인지 확정되지 않았다"* 였다. 🔴 **그 미확정이 이번에 해소됐다** — 사용자가 **① 광산 수 ↔ 초기 골드 연동은 「추후 밸런싱과 함께 조정하고 다시 작업한다」** ② **맵 테스트 모드는 「불필요하니 구현과 문서를 삭제한다」**로 **둘 다 「추후 작업」으로 명시**했다. **행을 세우는 근거는 이 문서의 역할(「앞으로 해야 할 작업」) 그 자체**이며, 「확정되지 않아 세우지 않는다」던 조건이 사라졌으므로 **더 미룰 이유가 없다.**

> - 🔴 **인게임 재접속의 완료 조건은 「끊긴 동안의 상태를 전부 복구해 실시간 플레이가 그대로 이어지는 것」이다.** 부분 복구는 완료가 아니다 — 화면만 돌아오고 자원·유닛·건물·점령 상태가 어긋나면 그 판은 이미 다른 경기다.

> - ⚠️ **결과 화면에서의 상대 이탈은 이 항목이 아니다** — 그쪽은 `GameSystemRules/GameSystemRules_RandomMap.md` **규칙 17**(30초 무반응 판정 · 정상 퇴장 즉시 통보 · 판정 시 연결 종료)이 단일 소스이며 **재접속이 아니라 「알리고 정리한다」가 결론**이다. **두 작업을 섞지 않는다.**
