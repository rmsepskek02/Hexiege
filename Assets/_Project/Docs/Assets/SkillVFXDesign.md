# 스킬 VFX 기획 (지원 스킬)

> **목적·답하는 질문:** 지원 스킬마다 어떤 VFX(V번호)를 어떻게 보이게 만들지, 크기를 무엇에 맞출지, 어느 스킬 자산 칸에 넣는지, 무엇이 아직 정해지지 않았는지, 어떤 순서로 만드는지를 찾는 상설 기획 문서다.
> **포함:** 스킬별 연출 기획 요지 · 크기 규격(범위 스킬은 「피해 영역 = VFX 크기」) · 넣을 칸과 프리팹 이름 · 열린 항목 · 만드는 순서와 그 근거가 된 사용자 결정.
> **제외·담당 문서:** 코드가 프리팹을 어떻게 재생하는지(재생 계약)와 프롬프트 작성 원칙은 [VFXSFXGuide](VFXSFXGuide.md) 「코드 계약」, 실제 제작·연결·수용 현황은 [VFXSFXList](VFXSFXList.md), 스킬 동작 규칙은 [스킬 규칙](../GameSystemRules/GameSystemRules_Skills.md), 수치는 밸런싱 단계(지금 값은 모두 시험용 임시값)가 담당한다. 이 문서에 연결 상태를 길게 복제하지 않는다 — 한 줄 상태와 링크만 둔다.
> **권위원본·주요 참조:** 지원 스킬 VFX 기획의 현행 원본이다. 2026-11-18까지의 기획 원문과 결정 기록은 [종족별 지원 스킬 기획 Plan](../_Tasks/2026-11-02/14_25_race-support-skills-design/Plan.md) 2-1 · 4절 23~26 · 5절 · 5-1 · 7절에 보존돼 있고, 이 문서는 그 내용을 스킬별로 옮겨 이어서 관리한다.
> **갱신 조건·방법:** VFX 기획 · 크기 규격 · 칸 · 만드는 순서에 관한 사용자 결정이 나오거나, 스킬 코드 구현으로 칸이 생기거나 바뀌면 해당 스킬 절을 제자리에서 고친다(옛 문구는 날짜 조각으로 남긴다). 제작 · 연결 · 수용 상태가 바뀌면 [VFXSFXList](VFXSFXList.md)를 고치고 이 문서의 한 줄 상태만 맞춘다.

## 이 문서는 무엇인가

지원 스킬(스킬 건물에서 쓰는 스킬 15개)에는 화면에 보일 이펙트가 스무 개 넘게 필요하다. 그동안 이 이펙트들을 어떻게 보이게 할지는 **작업(task) 문서** 안에 흩어져 있었다 — 주로 지원 스킬 기획 Task의 계획서와, 스킬 하나를 구현할 때마다 만든 task 문서들이다.

그런데 task 문서는 **그때그때 작업을 진행할 때 참고하는 자료**이지, 나중에 다시 찾아볼 문서가 아니다. 사용자도 그렇게 정했다 — 「task 문서 말고 별도 문서에 정리하는게 좋을거같은데 task 문서는 그때 그때 작업을 진행할떄 참고하기위한 자료이지 추후 참고하기위한 문서는 아니니까」(2026-11-18). 그래서 이 문서는 **이펙트 기획만 모아 두는 상설 문서**다. 이펙트를 만들 차례가 오면 여기서 그 스킬 절을 펴 보면 된다 — 무엇을 만들지, 크기를 무엇에 맞출지, 만든 것을 어느 칸에 넣을지, 아직 무엇을 정해야 하는지가 한 곳에 있다.

특히 중요한 원칙 하나: **범위로 피해를 주는 스킬의 이펙트는 피해 범위와 같은 크기로 보여야 한다.** 메테오 테스트에서 바닥 예고가 조준 원보다 조금 커 보였는데, 코드가 아니라 이펙트 모양 때문이었다. 사용자는 「vfx 제작할떄 크기에 맞춰서 진행해보자 피해영역에 맞게 크기를 조절하는게 중요하다고생각해」로 정했다(2절).

## 1. 만드는 순서

| 순서 · 원칙 | 내용 | 근거 |
|---|---|---|
| 스킬 하나의 단계 | **① VFX 기획 → ② VFX 제작 → ③ 코드 구현 → ④ 밸런싱** | 사용자 「스킬 vfx와 관련된 작업은 vfx를 기획 -> 제작 -> 코드 구현 -> 밸런싱으로 진행할 거야」(2026-11-02, 기획 Plan 5-1 결정 1) |
| 제작하는 사람 | ② 제작은 **사용자가 Unity AI로** 하나씩 한다. 제작 프롬프트도 하나씩 전달한다 | 기획 Plan 3-0 · 7-2 |
| VFX끼리의 순서 | 정해 둔 순서 없음 — **메인 세션 재량**. 시작은 메테오 → 서리 감옥 → EMP였다 | 사용자 「따로 정해둔 vfx 작업 순서는 없어, 편할 대로 하자」(결정 17) |
| 지금의 예외 | **VFX 제작 일시 중단 → 코드 구현 먼저.** Unity AI 크레딧 소진 때문이다. 그래서 대부분의 스킬이 ③ 코드 구현을 먼저 마치고 **빈 칸(프리팹을 넣을 자리)**만 가진 상태다 | 사용자 「유니티 AI 크레딧을 현재 모두 소진하여 vfx 제작은 멈추고 코드 구현 작업을 진행하면 될 것 같아」(결정 30) |
| 다시 시작할 때 | 칸이 준비된 스킬은 **프리팹만 만들어 넣으면 코드 수정 없이** 양쪽 화면에 나온다. 제작 전에 그 스킬 절의 「크기 규격」 · 「열린 항목」을 먼저 정한다 | 각 칸의 재생 계약 — [VFXSFXGuide](VFXSFXGuide.md) 「코드 계약」 10~17 |

- 칸이 생긴 스킬을 만들 때는 테스트에서 임시 프리팹으로 재생 경로만 확인했고, **모양 · 크기 · 보기 좋음은 어느 스킬도 검증되지 않았다**(임시 프리팹은 다른 용도의 이펙트였다).

### 2-2. 범위 스킬 VFX의 크기 규격 — 피해 영역 = VFX 크기

사용자 결정(2026-11-18): 「vfx 제작할떄 크기에 맞춰서 진행해보자 피해영역에 맞게 크기를 조절하는게 중요하다고생각해」. 원형 범위로 피해 · 상태를 주는 **모든 스킬 VFX**(바닥 예고 · 착탄 · 구역 · 범위 경고)에 적용한다. 원본 규격과 조사 수치는 [VFXSFXGuide](VFXSFXGuide.md) 「코드 계약」 17, 계기는 [메테오 Task Plan 14-4](../_Tasks/2026-11-18/03_34_support-skill-meteor/Plan.md#14-4-warning-size).

- 서버는 대상 **타일 중심**과 조준점의 거리 ≤ R0로 판정하고, 조준 원도 반경 R0에서 끝난다 — 그래서 VFX의 **보이는 경계 = R0**이어야 한다.
- 고정 링의 **가장 진한 선의 바깥 가장자리 = R0**(선 가운데가 아니다).
- 흐린 꼬리(번짐 · 글로우) **≤ R0 × 1.05**.
- 입자 크기 **= 2 × R0 ÷ q**(q = 텍스처 반폭에서 링 띠 바깥 가장자리의 비율 — 먼저 텍스처를 잰다).
- 안쪽 채움 빛 **≥ R0 × 0.9**.
- 줄어드는(수축) 링의 시작 크기 = 고정 링.
- Hierarchy · 회전 없음, 렌더러 **Max Particle Size 상한**이 큰 링을 잘라 작게 그리지 않는지 확인.
- 직선 범위(공습)는 같은 원칙을 길이 · 폭에 적용한다(보이는 가장 진한 경계 = 판정 경계, 번짐 5% 이내).
- **적용 범위(2026-11-23 결정):** **착탄 폭발 · 파편처럼 순간적인 연출은 결정 25(판정 반경을 10% 이내로 넘는 것 허용)**, **예고 링 · 구역 경계처럼 범위 경계를 보여 주는 표시는 이 규격(가장 진한 선 바깥 가장자리 = R0, 흐린 꼬리 ≤ R0 × 1.05)**을 적용한다. 수치는 잠정 — VFX를 만든 뒤 게임에서 보며 조정한다. 사용자 「착탄 폭발 크기 기준은 우선 추천대로 진행하고 vfx만들어서 조정해보자」 · 「추천대로 하라는건 너가 제안하는대로 하겠다는거니까 적절히 맞춰서 진행해줘」(메인 세션 제안 채택).

- **V4 `vfx_frostprison_frozen`:** 유닛 얼음 상태, 지속, 발밑 피벗. 가시 결정 5개(반경 0.5 · 높이 1.0), 유닛당 입자 16개 이하, 신규 텍스처(가시 결정). 기획안 크기 식 `max(키, 반경 × 1.1 / 0.5)` · 상한 `키 × 1.5`(큰 유닛에서 상한에 걸린다). 칸 = 같은 자산 「유닛 상태 VFX」 — 크기는 유닛 크기 표 × 스킬 크기 배율로 시작하고, **기준 크기로 먼저 만들고 큰 유닛 보정은 프리팹이 나온 뒤**(기획 Plan 결정 20 · 지속 상태 구역 Task Z-12).
- **열린 항목:** 발동 연출 `vfx_frostprison_cast`(0.9초 원샷 — 기획안 권장)를 따로 만들지(기획 Plan O-21, 사용자 미답). 만들면 기존 「발동 VFX」 칸에 넣는다(새 칸 불필요). V3의 「경계 링 5.56」이 2-2 규격(링 바깥 가장자리 = 2)을 만족하는지는 텍스처를 잰 뒤 계산한다(이 기획은 2-2 규격 전에 나왔다).
